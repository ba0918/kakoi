02 / SHAPE THE BOUNDARY

Make access explicit.

Write a policy ↗
01

Visible files

Use ro for read-only access and hide to conceal contents. In host mode, unspecified paths remain visible, read-only.

ro = ["~/reference"]
hide = ["~/.ssh"]
02

Writable paths

Writes to rw paths reach the host. Use rw-copy for a writable copy whose changes disappear when the command ends.

rw = ["${worktree}"]
rw-copy = ["~/.gitconfig"]
03

Environment

Shape what is inherited. Remove variables with unset, or start with clear and pass only the variables you need.

[env]
unset = ["*_TOKEN"]
04

Network access

The default host mode shares networking. Choose none to disconnect, or filtered to name destinations, protocols, and ports.

[network]
mode = "none"

Each snippet is a policy fragment, not a complete policy file.

OPT-IN / NOT THE DEFAULT

Need a smaller boundary?

mounts.mode = "listed"Shows the base plus listed paths. With host networking, requires Linux 6.12+ / Landlock ABI 6.Listed example ↗

network.mode = "filtered"Explicitly allow destinations. Requires pasta, nftables, /dev/net/tun, and environment checks.Filtered guide ↗

03 / FOR RUST APPLICATIONS

The same boundary.
Inside your application.

Prepare, spawn, stop, and collect results with kakoi-runtime. Use kakoi-policy on its own for policy validation.

API guide · Japanese ↗Sync Rust example ↗
EXPERIMENTAL PATH DEPENDENCY
Cargo.toml
[dependencies]
kakoi-runtime = { path = "../kakoi/crates/kakoi-runtime" }

Not distributed on crates.io. Call dispatch_helper() at the start of synchronous main, before application or async runtime initialization.

Embedding requires a readable self-executable and bwrap’s bind-fd / ro-bind-fd features.

04 / KNOW THE LIMITS

A boundary you
can reason about.

Security model & known gaps ↗
↳

Built for Linux x86_64 and WSL2.No native macOS, native Windows, or aarch64 support. Check user namespace permissions on Ubuntu 24.04 and later.

≠

Not a replacement for a container or VM.It trusts the host and shares its kernel. There are no resource limits, and no guarantee that malicious programs are safe to run.

!

Command guards are guardrails against mistakes.They are not a strong isolation boundary. Review allowed destinations and writable content that you will later use on the host.
