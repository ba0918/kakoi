# 目的・対応環境・対象外

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

## 1. 結果

`kakoi`は、指定したコマンドをポリシーに従う隔離環境で起動するRust製のCLIである。隔離にはbubblewrap（bwrap）のマウント名前空間を使う。

入力はポリシーファイル、ワークスペース、実行するコマンド。次の約束を守る。

- **引数を保つ**：ARGSを追加・変更しない。コマンド自身から見える名前（argv[0]）も、COMMANDに与えた文字列のままにする。実行ファイルを探して得たパスには置き換えない。
- **同じ条件から同じ計画を作る**：ポリシー、ワークスペース、cwd、環境、ファイルシステムの事実が同じなら、起動計画も同じになる。
- **実行結果を返す**：包んだコマンドの終了コードを返す。filteredの外部終了要求・安全上の故障については[終了契約](network/process.md)の例外が優先する。
- **許可の正本を固定する**：起動時に確定したポリシーを、アプリから変更・拡張できない。filteredのDNS由来IP許可と待受公開は、その範囲内で更新する。

**確認例**：COMMANDに`sh`を指定したら、argv[0]は`sh`になる。`/usr/bin/sh`へ変わるのは契約違反。同じ入力でマウント順が変わることや、kakoiが対象コマンドへ引数を足すことも契約違反である。

## 3. 対応環境

| 条件 | 対応範囲 |
|---|---|
| OSとCPU | Linux x86_64。WSL2を含む |
| bubblewrap | 0.9.0以上、setuidでないインストール |
| 利用者 | root以外 |
| その他のCPU | aarch64を含め未対応。x86_64以外へのビルドはコンパイル時に失敗する |

隔離の中で 32 ビットと x32 のバイナリは動かない（第 11 節）。

成功の観測条件: x86_64 の Linux で第 15 節のテストが通り、x86_64 以外のターゲットでビルドが
失敗する。反例: aarch64 でコンパイルが通ることを理由に対応環境に含める。

## 18. 0.3 で作らないもの

- cgroup による CPU やメモリの制限。bwrap で作れない。
- アプリのマルチキャスト・ブロードキャスト通信は初版対象外の方向。ただし後日対応の変更規模は[実証の完了条件](proof-gate.md)で確認する。
- DNS over HTTPSは初版対象外。後から輸送方式を追加できる責務分担を維持する。
- 段の合成における削除の演算子。
- `default.toml` を常に読む合成（書かれた段を 4 つにする形）。
- カレントディレクトリからのポリシーファイルの自動探索。
- bwrap の `--new-session`。
- 入れ子での二重の隔離と、環境変数以外の入れ子検出。
- aarch64、32 ビット、x32 のバイナリ。
- `.git/hooks` や `.git/config` の保護。
- ポリシーファイルの読み取り専用の重ね掛け。第 5.6 節の拒否で置き換えた。
- `git init --separate-git-dir` のメインワークツリーの相互リンク（第 5.2 節の 3 つ目の形）。既知の
  隙間として README に載せる。
- codex 以外のツール節の値（opencode、claude など）。実測していないものは同梱しない。利用者が雛形
  （第 16 節）を写してツール節を埋める。
- `init` の上書き（`--force`）。
- セットアップスキルのインストール手段。`gh skill install` など各 CLI の手段に任せる。
- シムの雛形による、位置引数の写しと、1 つのオプションに並べた複数の値のうち先頭より後ろの写し。写らない
  形はセットアップスキルが回避策を案内する（第 16 節）。

成功の観測条件: `--help` と README がこれらを提供すると書いておらず、これらを有効にするオプションや
ポリシーのキーが存在しない。反例: 文書に無いキーで `default.toml` を常に読む合成が有効になる。


filteredの追加依存と対応条件は[実証の完了条件](proof-gate.md)に従って確定する。host/noneに追加依存を必須としない。
