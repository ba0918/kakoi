# 通知の保持と出力

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

公開先の割当や通信の遮断・復帰は、アプリの出力と区別できる形で知らせる。通知を読めないことによって通信制御が止まる構造にはしない。

## 通知を受け取る場所

実行中のネットワーク通知は標準エラーへ1件1行で出し、kakoiの通知と分かる接頭辞を付ける。標準出力には通知を混ぜない。アプリの標準エラーと同じ出力先を使い、専用の受信設定を要求しない。

## 出力が詰まっても通信制御を続ける

標準エラーの読み手が止まっていたり、出力先が閉じていたりしても、通知待ちで通信制限・遮断・復帰・終了処理を止めない。通信制限を維持できる間はアプリを動かし続ける。

そのため、通知の欠落を許容する。保持するのは最大256件、かつ合計1MiBまで。出力が詰まったら古い通知から捨て、再び出力できるようになったら、欠落があったことと現在の状態を優先して知らせる。
