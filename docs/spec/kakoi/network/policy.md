# 通信許可と設定の合成

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

外部通信を必要な範囲に絞るには、`filtered`を選び、宛先・TCP/UDP・ポートを指定する。この文書ではポリシーの書き方と、指定がどこまで効くかを説明する。

## 通信制限を選ぶ

```toml
[network]
mode = "filtered"
```

`filtered`を明示すると、通信許可に従った制限が有効になる。許可・公開の指定が空でも起動でき、その場合は隔離環境内のループバックだけが使える。外部通信、ホストへの接続、待受公開は許可されない。

今回追加するネットワーク設定を書く場合は、空配列や補助設定だけでも`mode`を明示する。別の段で明示した値を引き継いでもよい。許可を書いたことを理由にモードを自動変更することはない。新設定を使わない既存ポリシーの扱いは変えない。

例えば`filtered`から`host`へモードだけを変更しても、残った許可一覧を消す必要はない。採用されたモードが明示的な`host`または`none`なら、使わない設定が残ることを警告し、そのモードで起動する。

ただし、使わない設定も入力形式と公開設定同士の競合は検査する。必須項目の欠落、不正なポート、競合は起動前エラーになる。使わない設定のためのDNS問い合わせやインターフェースの存在確認は行わない。`filtered`の準備失敗時の扱いは[起動の条件](recovery.md#通信制限を準備してから起動する)に従い、`host`へ自動移行しない。

## 宛先と通信方式を許可する

次の例は、`api.example.com`から得たIPのTCP・443番を許可する。

```toml
[network]
mode = "filtered"

[[network.allow]]
destination = { dns = "api.example.com" }
protocol = "tcp"
ports = ["443"]
```

`[[network.allow]]`には`destination`・`protocol`・`ports`の3項目を必ず書く。一般の宛先は`destination`内の`dns`・`ip`・`cidr`から一つを選び、`protocol`は`tcp`または`udp`にする。IPv6リンクローカルの`host-interface`も`destination`内に置く。ホストのlocalhostには[専用指定](host.md#ホストのlocalhostにつなぐ)を使う。

新規通信は、宛先・TCP/UDP・ポートがいずれかの有効な許可に一致するときに通す。後述するループバックと待受公開の例外を除き、どの有効な許可にも一致しない新規通信は拒否する。上の例はUDP・443番やTCP・22番を許可しない。

DNS名の許可は、得られたIPと指定ポートへの許可である。同じIP・ポートにIPを直打ちして接続したり、別名で接続したりしても区別しない。[DNS名だけでは許可しないアドレス](address.md#dns名だけでは許可しない宛先)と[許可の期限](dns-lifetime.md#名前解決で得た許可が切れるまで)も適用する。

例外として、隔離環境内のループバック通信はTCP/UDPの全ポートを既定で許可する。ホスト側のlocalhostは含まない。また、[待受公開](publish-target.md#許可範囲の待受を自動で公開する)を明示した範囲では、ホストのlocalhostから内側への接続を通す。

## ポート番号と範囲の書き方

`ports`は文字列配列で書く。省略できず、番号の範囲は1〜65535。

| 指定例 | 意味・結果 |
|---|---|
| `["443"]` | 一つのポート |
| `["443", "8000-8010"]` | 443番と、8000〜8010番の両端を含む範囲 |
| `["443-443"]` | `["443"]`と同じ |
| `["8000-8010", "8005-8020"]` | 重なる範囲をまとめ、8000〜8020番を許可 |
| `["443", "443"]` | 重複をまとめて443番を許可 |
| `["*"]` | 1〜65535番すべて |
| `[]`、`["*", "443"]` | 空配列と全ポート指定への混在はエラー |
| `["8010-8000"]` | 開始番号が終了番号より大きいためエラー |
| `["0443"]`、`[" 443 "]`、`["+443"]` | 先頭ゼロ、空白、符号はエラー |
| `["https"]`、`[443]` | サービス名と数値型はエラー |

この記法と検査は、待受公開の`ports`と`host-ports`にも共通で適用する。

## 起動後に許可が増える範囲

許可の正本は、起動時に確定したポリシーである。アプリは自身の申告によって許可を追加・拡張できない。

DNS応答は、すでに許可した名前の現在のIPを求める入力として扱う。IP許可の追加に使えるのは、kakoiが管理するDNS経路で送った問い合わせとの対応を確認できた上流応答だけ。アプリが別経路で取得した結果や申告したIPは、既存の有効なIP・ポート許可と照合するだけで、新しい許可の根拠にはしない。

## 複数の段に指定した場合

`network.allow` は段の間で追加して合成し、各許可のいずれかに一致する通信を許可する。重複はまとめ、空配列では元の許可を消さない。許可を減らす場合は元の設定を編集するか別プロファイルを使う。

UDP無通信期限の範囲と段の合成は[UDPの無通信期限](dns-lifetime.md#udpの無通信期限を変える)で定める。
