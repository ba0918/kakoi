# DNS上流の設定と信頼元

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

アプリの名前解決を受けて問い合わせる先を「上流DNS」と呼ぶ。指定がなければホストのDNS設定を使う。ここでは問い合わせ先を明示する場合と、信頼元・待ち時間の設定を説明する。

## ホストDNSを使うか問い合わせ先を書くか

DNS over TLSでは、接続するIPと証明書で照合する名前を分けて考える。次は役割を示す説明用の値であり、利用可能なサーバーや具体的な入力キーの定義ではない。

| 指定する情報 | 説明用の値 | 役割 |
|---|---|---|
| 接続先IP | `192.0.2.53` | 通信を届ける相手 |
| 証明書の照合名 | `resolver.example.com` | 相手の証明書を確認する名前 |


初版のポリシーによる上流DNSの明示指定は、全問い合わせに共通の設定とする。ポリシー内で名前別の上流指定は提供しない。ホストDNS設定を利用する場合の名前別振り分けの継承は維持する。

明示DNS上流は `network.dns-upstream` 配列で指定し、下位から上位へ連結する。接続IPとTLSの証明書照合名を分ける。上流指定がなければホストDNSを使う。同じ候補一覧に平文とTLSを混在させない。空配列では下位を消さず、総入替えには別プロファイルを使う。

共通の上流DNSは複数を明示指定でき、問い合わせ先が応答しない場合に指定済みの別候補を使えるようにする。列挙した全候補に同じ名前を問い合わせてよいという指定として扱い、指定外のDNSへは自動で切り替えない。

明示した複数上流は、上流問い合わせが必要になるたびに記載順で試す。先の候補が応答しない場合等の切替条件に達したら次へ進む。ホストDNS設定を使う場合の上流選択方式はこの規則の対象外とする。

## TLSの証明書を検証する

TLSは起動時にホストOSのCA証明書を読み込む。独自CAはOS側へ登録する。初版は専用CAファイル指定と証明書検証無効化を設けない。起動後のCA変更は再起動で反映する。

## 待ち時間の設定と合成

`network.dns-server-timeout-seconds` は既定2で1〜300秒、`network.dns-resolution-timeout-seconds` は既定10で1〜3600秒の整数とする。0・無制限・小数は認めない。

DNS待ち時間の各設定は上位の指定を優先し、省略時は下位を継承する。どの段にもなければ既定値を使う。合成後に1候補の待ち時間が全体上限を超えたら設定エラーとする。
