# 公開の寿命と復帰

後続の動的公開の仕様。[初版の範囲](initial-release.md)により、本文の動的公開は初版に含めない。固定公開にはinitial-releaseの契約を使う。

待受公開はサービスの寿命に追従する。ホスト側のポートを確保できなくても、隔離環境内の処理まで停止させない。

## 公開用の空きポートがない場合

ホスト側の事前許可範囲に空きがなく公開ポートを確保できない場合は、該当サービスの公開だけを失敗として通知する。隔離環境内の処理と他の公開は継続する。許可範囲外への拡張や既存ホストサービスの停止は行わない。

公開ポート不足で失敗した場合、サービスの待受が続く間は間隔を置いて自動再試行し、成功時に公開先を通知する。

公開ポート不足では失敗後1・2・4・8・16秒、以降30秒待って、待受が続く間だけ再試行する。通知は初回失敗・理由の変化・公開成功に絞り、同じ失敗は繰り返し通知しない。

## TCP待受の終了と再起動

TCPの待受終了を検出したら、その公開先からの新規接続の受付を停止する。待受終了だけを理由に確立済み接続を切断せず、最後の応答を送れるように維持する。

待受終了後は再起動用のホスト公開番号の予約を残さず解放する。待受が再び現れたら新規公開として番号を選ぶ。待受終了時に新規受付を停止し、確立済みTCP接続は維持する。

## UDP公開が続く期間

UDP公開の寿命と、外向きUDP通信の無通信期限は別である。

| 対象 | 維持する条件 |
|---|---|
| 外向きUDPの継続判定 | 同じIP・ポートの組で無通信期限内であること |
| ホスト向けのUDP公開 | 対象ソケットが開いていること |

したがって、公開したサービスが無通信でも、ソケットが開いていれば公開は続く。

初版からUDP公開を扱う。公開先はホストのlocalhostに限定し、TCPの公開許可だけでUDPを公開しない。

事前にUDP公開を許可した範囲内で、ローカルのアドレスとポートを割り当てられたソケットを検出したら、自動公開の対象とする。アプリ名や用途では区別せず、外向き通信の送信元ポートも範囲内なら対象とする。

対象UDPソケットが開いている間は無通信でも公開を維持し、ソケットが閉じられたことを検出したら公開を止める。外向きUDP通信の無通信期限を公開自体の停止条件にしない。

## 通信障害から復帰した場合

障害復帰時に同じ待受が継続している場合、以前のホスト公開番号が許可範囲内で使用可能なら優先して再利用する。使えなければ既存の選択規則で別の許可済みポートを選び、知らせる。
