# DNS照会と上流応答

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

名前からIPを得る照会のほか、メール配送先やサービス情報を読む照会も扱う。ただし、DNSで情報を取得できることが、その情報に書かれた宛先への通信許可にはならない。

## 読み取り照会の対応範囲

名前からIPを得るA・AAAAだけでなく、TXT・MX・SRV・HTTPSといった情報の読み取りも扱う。これらは例であり、対応種別をこの一覧に固定しない。未知の通常レコードもRFC 3597に従い、内容を解釈せずに中継する。不正な形式の検査は行う。

取得した情報は、通信許可とは分けて扱う。許可を追加する根拠になるのは、管理するDNS経路で検査したA・AAAAだけ。別のレコードが接続先IPや名前を紹介しても、それだけでは許可を増やさない。CNAME以外で紹介された名前を問い合わせるには、その名前の許可が別途必要になる。

DNS更新、ゾーン転送、全種類を一括照会するANYは初版の対象外。

## 上流との通信方式

初版の明示上流は通常のDNS（UDP/TCP）とDNS over TLSに対応し、DNS over HTTPSは含めない。TLS指定時は証明書を検査し、失敗時に平文へ自動で切り替えない。

DNSの通信方式をDNS応答の検査・IP許可判定から分離し、将来DNS over HTTPSを追加できる設計とする。方式の追加で既存の許可モデルを作り直す構造にしない。

## 失敗の種類と次の候補へ進む条件

失敗の名前が同じでも、「kakoiのポリシーが拒否した」のか「上流が拒否した」のかで扱いが異なる。上流の候補切替によって、kakoi自身の許可範囲が広がることはない。

| 名前 | 表す結果 |
|---|---|
| REFUSED | 問い合わせの拒否 |
| SERVFAIL | 解決処理の失敗 |
| NXDOMAIN | 問い合わせた名前が存在しない |
| NODATA | 名前に対して求めた種類のデータがない |

未許可の名前や解決先IPの全件禁止というポリシー拒否はREFUSEDを返す。上流で解決できない場合、時間・段数・回数の上限超過、CNAME循環、変更後のホストDNS設定取得失敗はSERVFAILを返す。採用可能な上流のNXDOMAIN/NODATAは既存方針どおり維持する。

明示上流から採用可能なNXDOMAINまたはNODATA応答を得たら、その問い合わせの結果として採用し、それだけを理由に次の候補へ問い合わせない。応答の正当性確認を省略しない。

明示上流からSERVFAILまたはREFUSEDを受けた場合は次の指定済み候補を試し、問い合わせ全体の時間・作業量の上限を引き継ぐ。先の上流が独自の方針で拒否しても次の上流が回答すれば採用する。kakoi自身の通信許可や上流に求める信頼条件は緩めない。
