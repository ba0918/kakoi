# filtered初版の範囲と拡張方針

会話および実装計画レビューで承認済み。既存の動的公開の契約から、初版として提供する範囲を切り出す。

## 初版で提供するもの

pastaとnftablesを使い、IP/CIDR/DNS名に基づく外向きTCP/UDPの制限、明示したホスト接続、明示的な固定ポート公開を提供する。IPv4/IPv6、DNS応答の検査と期限、障害時の遮断・復帰・終了は既存の責務別仕様を維持する。host/noneにpastaやnftablesを必須にしない。

pastaは外部実行ファイルとして起動する。初版は通常の起動時設定を使い、実験的な動的制御窓口やkakoi独自修正版を必須にしない。対応版・導入経路は[実証条件](../proof-gate.md)に従って確定する。

## 後続へ分けるもの

待受を検出して自動公開する機能、競合時に別のホスト番号を割り当てる機能、待受寿命に追従した公開の追加・削除・再割当は後続とする。

既存の[公開設定](publish-config.md)、[公開対象と割当](publish-target.md)、[公開の寿命](publish-lifetime.md)は後続の動的公開を定義する。それらの「初版」は今回の範囲変更により後続へ変更される。固定公開へそのまま適用しない。初版の固定公開は次節だけが定義元となる。

IPv6リンクローカル宛先と、`host-interface` による接続口の指定も後続とする。上流未修正のpastaは、アプリ側のリンクローカル宛て通信をホスト側の隣接ノードへ運ばないことを実測した。初版では `host-interface` を含む許可を起動前の診断で拒否し、別の宛先や接続口へ読み替えない。pastaの対応を確認してから[リンクローカルの仕様](link-local.md)を再実証する。

この分離は、DNSによる許可IPの更新や故障時の通信遮断を延期する意味ではない。動的なIP許可はnftables側で扱い、pastaの動的ポート公開とは別の責務にする。

## 固定公開

TCP/UDPの固定公開、環境終了までの対応維持、起動時競合での起動エラーと以下の記法は承認済み。実証でpastaの制約が判明したため、初版の転送は同じIP系統に限定する。

内側8000番をホスト18000番へ公開する例:

```toml
[network]
mode = "filtered"

[[network.publish]]
mode = "fixed"
protocol = "tcp"
port = 8000
host-port = 18000
# target-family = "ipv4"  # 内側の転送先。省略時ipv4
# host-family = "ipv4"    # ホストの公開先。省略時ipv4
```

`mode`、`protocol`、`port`、`host-port`は必須。`protocol`は`tcp`または`udp`、ポートは1〜65535の整数で指定する。`target-family`は`ipv4`または`ipv6`、`host-family`は`ipv4`または`ipv6`。両者の系統が異なる指定と`host-family = "both"`は初版では設定エラーにする。初版では範囲・自動割当・`mode = "dynamic"`・`mode`の省略を受け付けない。将来の動的公開は別の指定で追加し、この指定の意味を変えない。

ホスト側は127.0.0.1または::1だけで待ち受ける。内側の転送先も指定系統のループバックとし、そのアドレスで接続できる全アドレス待受も利用できる。指定していない待受は公開しない。IPv4からIPv4、IPv6からIPv6へ転送する。両系統に公開する場合はIPv4用とIPv6用の2項目を指定する。設定全体の準備が成功するまでアプリを起動せず、一部の公開だけを成功として起動しない。交差系統の転送は後続へ分離する。

### 公開する期間と失敗時の扱い

アプリ起動前にホスト側ポートの確保を確認し、指定した対応を隔離環境終了まで保持する。内側サービスがまだ起動していなくても公開用ポートを確保し、サービス停止中も別の用途へ番号を解放しない。

起動時の競合・確保失敗は起動エラーとし、アプリを実行しない。別の番号へ自動変更しない。設定一覧や外部コマンドの成功終了だけを実際の確保の証拠にはしない。準備失敗時はその環境用に確保した資源を回収する。

実行中の故障から復帰する場合は同じ対応だけを再確保する。確保できない間は遮断を維持し、[既存の復帰規則](recovery.md#遮断したまま復帰を試す)に従う。環境終了時には[既存の終了順序](recovery.md#主コマンド終了後に片付けるもの)に従って公開を止めて回収する。

公開したホストのアドレス・ポート・通信方式と内側の対応を通知する。アプリの標準出力は書き換えない。通知の出力先・詰まりの扱いは[通知仕様](notification.md)に従う。

### 重複・競合と設定の合成

`network.publish`はレイヤ間で連結し、空配列で下位の指定を消さない。正規化後の同じ項目はまとめる。同じ内側端点に異なる公開設定がある場合、同じホスト端点に異なる転送先がある場合は設定エラーとする。端点の一致は通信方式・IP系統・番号で判断する。

host/noneでも形式と設定同士の競合は検査するが、pasta探索やホスト側ポートの実際の確保はしない。

## 動的公開を追加できる責務分担

設定を検査して公開の意図を作る処理、ホスト側の公開先を決める処理、pastaへ設定して実際の状態を確認する処理、終了時の回収を分ける。初版では起動前に対応を確定し、将来は待受観測と番号割当の処理を追加できる形にする。

pasta固有の引数や制御プロトコルを設定の意味・DNS許可判断・CLIへ漏らさない。固定公開の設定を、将来の更新時に自動選択へ読み替えない。上流の正式対応は時期・採用とも未確定であり、拡張を提供するときに対応版と挙動を再検証する。
