# 通信の障害と復帰

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

通信の制御処理に障害が起きたときは、許可していない経路を開かずに処理を続けられるかで対応を分ける。起動前の準備失敗、実行中の遮断、終了時の片付けをここで定める。

## 通信制限を準備してから起動する

起動時に要求されたネットワーク制限を準備できない場合は、起動エラーにしてアプリを実行しない。通信なしの起動や無制限通信への自動移行はしない。

## 実行中に制限を維持できなくなった場合

![確実に遮断できれば処理を継続して復帰を試し、遮断できなければ猶予なしで終了する。](figures/recovery.svg)

図の遮断には、外向き通信・ホスト接続・待受公開を含む。再試行の時間条件は次節に従う。

起動後に通信制限を維持できなくなった場合は、外向き通信・ホスト側サービスへの接続・待受公開の経路を確実に遮断できる場合に限り、通知して隔離環境内の処理を継続する。遮断を保証できなければ隔離環境を終了する。

通信制限を維持できず遮断も保証できないため隔離環境を終了する場合は、kakoi自身の失敗として終了コード125と理由を返す。通常終了時は主コマンドの終了コードをそのまま返す。

通信制限も遮断も保証できず隔離環境を終了する場合は、通常終了の猶予を適用せず直ちに強制終了する。

## 遮断したまま復帰を試す

確実に遮断できた場合は、内側の処理を続けながら通信制限の再構築を試す。使うのは起動時に確定したポリシー。制限が正常に働くと確認するまで、経路を開かない。確認できたら利用者の操作を待たずに通信を自動復帰し、通知する。期限切れのDNS許可をそのまま復活させることもない。

復帰試行には次の時間条件を使う。

| 条件 | 扱い |
|---|---|
| 一回の試行 | 既定10秒で打ち切る。1〜300秒に設定変更できる |
| 失敗後の待ち時間 | 順に1・2・4・8・16秒、その後は毎回30秒 |
| 試行の重なり | 前の試行と重ねない |
| 再試行の回数 | 安全な遮断を維持でき、環境が動く間は上限なし |
| 復帰後に再び故障した場合 | 失敗回数をリセットし、最初の待ち時間から始める |

遮断開始、失敗理由の変化、復帰成功を通知する。同じ理由の失敗を繰り返す間は、同じ通知を出し続けない。通信経路が復帰しても、切れた接続自体を再試行するのはアプリの役割になる。

## 主コマンド終了後に片付けるもの

ネットワーク状態と補助処理は隔離環境ごとに独立して管理する。環境終了時に、その環境のIP許可・公開ポート・補助プロセスを片付ける。他の稼働中の隔離環境の通信や公開には影響させない。

主コマンドが終了したら隔離環境も終了する。残った子プロセスも終了し、公開ポートを片付ける。子プロセスが残っていることを理由に環境を維持しない。

主コマンド終了時は公開と外部通信を先に止め、残った子プロセスに終了を要求する。有限の猶予を与え、猶予後も残るプロセスは強制終了する。

終了猶予は既定5秒とし、設定で1〜300秒の整数に変更できる。残ったプロセス全体で共通の期限を使い、全員が終了したら期限を待たずに片付ける。
