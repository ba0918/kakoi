# DNS応答と許可の寿命

草案。実装前に[実証の完了条件](../proof-gate.md)を満たす必要がある。

DNSの回答にはTTLという有効期間がある。kakoiはこの期限に合わせて新規通信の許可を管理する。許可の期限と、すでに始まった通信の寿命は分けて扱う。

## 名前解決で得た許可が切れるまで

検査を通ったIPには、DNS応答のTTLの期間だけ新規通信を許可する。新しい応答を得たら再検査して更新するので、利用者が解決先IPを追いかけてポリシーを書き換える必要はない。

CNAMEで別名を辿った場合は、経路上のCNAMEと最終IP情報のうち、最も早い失効時点を許可の期限にする。別名の情報だけが先に切れる場合も、その時点で期限となる。

更新はアプリからの問い合わせを契機に行う。有効なキャッシュがあれば使い、期限切れ後の次の問い合わせで取得し直す。問い合わせのない名前を定期的に先読みしない。古い応答による許可は元の期限まで維持する。

許可が期限切れになり、他の有効な許可がなければ、そのIPへの新規通信は拒否する。アプリが古いIPを保持して名前を再問い合わせしない場合も同じ。他の有効な許可があれば、その許可によって接続できる。

## TTLゼロの応答にも接続のための猶予を設ける

TTLが0のDNS応答で検査を通ったIPには、応答の受信から既定1秒だけ新規通信の猶予を設ける。検査や許可登録が遅れても、そこから1秒を数え直さない。期限が切れた候補を後から有効にすることもない。

猶予は `network.dns-zero-ttl-grace-milliseconds` で変更できる。既定1000、範囲100〜10000の整数ミリ秒とする。上位の指定を優先し、省略時は下位の値を引き継ぐ。

新たに検査を通った応答を得た場合だけ許可を更新し、通常の通信では猶予を延長しない。TTLゼロのDNS応答を後の問い合わせへ再利用することもない。CNAME経路ではTTLゼロの情報にだけ猶予を適用し、各情報の失効時点の最小値を使う。正のTTLの期限を猶予で延ばさない。

猶予中には同じIP・許可ポートへの別の新規通信も通る。猶予中に始めたTCP・UDPには次節の継続規則を適用するため、通信全体を1秒で止めるものではない。具体値の合意と、[製品実装前の実証](../proof-gate.md)の完了は区別する。

## 期限が切れた後のTCPとUDP

TTLが切れたことだけを理由に、確立済みのTCP接続は切らない。例えば、期限内に開始したダウンロードは接続が続く間、古いIPとの通信を継続できる。

UDPは、送信元・宛先のIPとポートが同じ組である間、最後に許可した送受信からの無通信期限まで継続する。通信が続けば古いIPとも通信できる。IPまたはポートが変わった場合と、無通信期限が切れた後は、新規通信として許可を再判定する。

同じ組を無通信期限内に別の処理が再利用した場合も、同じ継続中のUDP通信として扱う。プロセスの入替えを、この継続判定の識別条件にはしない。

## UDPの無通信期限を変える

UDPの無通信期限は最後に許可した送受信から既定120秒とし、ポリシーファイルの `network` の `udp-idle-timeout-seconds` で変更できる。指定は正の整数秒とし、0と無制限の指定は認めない。省略時は120秒。そのポリシーのUDP許可すべてに共通で適用する。期限後の通信は新規通信として有効な許可を再判定する。

UDP無通信期限の設定可能範囲は1〜86400秒とし、既定120秒を維持する。これは最後の通信から待つ時間の上限であり、通信が続くフローの総時間を1日に制限するものではない。

UDP無通信期限は上の段で指定した値が上書きする。省略なら下の段の値を引き継ぎ、どこにも指定がなければ120秒とする。


## 失敗の保持と再問い合わせ

解決失敗は既定5秒保持し、その間は同じ解決条件の問い合わせに失敗を返して上流への再問い合わせを抑える。保持時間は1〜300秒で設定変更可能とする。

1回の解決中、同じ解決条件では同じ上流・通信方式へ同じ問い合わせを繰り返し送らず、応答しなければ次の指定候補へ進む。ホストDNS設定の変更後は別の解決条件として、問い合わせ先IP・通信方式が同じでもやり直しを認める。元の時間・問い合わせ回数の上限は引き継ぎ、設定変更を繰り返してもリセットしない。
