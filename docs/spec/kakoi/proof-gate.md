# 製品実装と提供前の実証条件

初版範囲の改訂と実装計画レビューで承認した条件。過去の実証全体を合格へ変更するものではない。

## 実装開始の条件

[初版](network/initial-release.md)で使うpastaの通常の起動時設定に対象を絞る。上流未修正版で次の成立を確認してから製品実装へ進む。

1. 公開なしでIPv4/IPv6の外向きTCP/UDPと明示したホスト接続を使える。
2. 固定公開を起動前に準備でき、公開先はホストlocalhostだけである。同一IP系統、競合の検出、UDPサービス再起動、環境終了後の番号再利用を確認する。
3. アプリ起動前から遮断を準備できる。外向き・ホスト接続・固定公開の各経路を、新規・既存通信と一方的なサーバー送信の両方向で遮断でき、内部通信は維持できる。
4. 確認した版を利用者が導入でき、必要な権限と対応環境を説明できる。

同じ起動方式のケースを一組にまとめ、初版に含まれない動的公開の試験を追加し続けない。未修正版で成立しない場合は、修正版へ黙って切り替えず方式・初版範囲を再判断する。過去の限定修正版でのPASSはこの条件の代用にならない。

## 提供前の条件

実装開始後、製品の実コードで以下を確認する。未完了の間はfiltered初版の提供完了とはしない。

- 全初版経路に許可判定があり、アプリが制限を解除・迂回できない。起動・復帰に全許可の瞬間がない。
- DNS応答の検査、ホストDNSの対応構成と変更追従、明示上流とTLS、TTLゼロを含む有限期限を守る。
- 制御役・監視役・更新役の故障、書込み失敗・応答喪失・競合時も範囲を広げない。遮断可能なら内部処理を維持して復帰し、不能なら合意の終了結果で回収する。
- 通信遮断から終了猶予・全子回収までを実pastaと統合し、端末・シグナル・終了コード・通知詰まりの規則を満たす。
- 固定公開の寿命・競合・終了回収と、複数環境の独立性を満たす。
- 対応を表明するOS・依存版の標準導入環境で、製品テストと既存の回帰検査を通す。

## 依存と対応環境

pastaとnftablesを初版の前提とする。pastaは外部実行ファイルとして扱い、独自の通信スタックは実装しない。標準パッケージから導入できるOS・版と依存版、TUN/TAPとuser namespaceの条件を記録する。host/noneへ追加依存を必須にしない。

初版はpestoによる実行中設定変更やkakoi独自修正版の配布を必要としない。将来、その機能を用いて動的公開を追加する際には、UDP公開の削除・再利用問題が上流で解決し、その版で再実証できることを必要とする。正式対応の時期は未確定である。

## 将来拡張と記録

動的公開と一斉送信は初版の実装開始条件へ含めない。将来のマルチキャスト・ブロードキャストには転送経路等の拡張や方式差替えが必要になる可能性があり、小規模な変更で済むとは保証しない。

詳細な試験条件と部分観測は[実証記録](../../decision/brainstorm/2026-09-16-kakoi-net-evidence.md)を参照する。第1〜26組の履歴・失敗・全体NOT_RUNの記録は維持する。今回の初版開始条件と提供前条件には、それぞれ対象版・ソース・結果を付けて新しく判定する。
