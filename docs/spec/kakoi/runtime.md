# 実行時の境界

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

起動時に読む情報、ホストへ書く範囲、bwrap へ渡す情報を定める。コマンドを包む起動と、設定を作る `init` では書き込みの扱いが異なる。

## 14. 実行時の境界

### ホストへの書き込み

コマンドを包む起動は、`--print-plan` を含め、永続状態を持たずファイルを書かない。`rw-copy` の複製もホストに保存しない。包んだコマンド自身の `rw` への書き込みは、[マウント指令](mounts.md)で許した範囲に従う。

ファイルを書く形は `init` だけである。書く範囲は、設定ディレクトリまでのパスの欠けた成分と、その下の `profile/`、`secrets/`、出力するプロファイルに限る。`/tmp/kakoi` は作らない。作成・上書き拒否の詳細は[CLI](cli.md)で定める。

### 読む情報

| 対象 | 読む情報 |
|---|---|
| ポリシーファイル・秘密ファイル | 設定と秘密の値 |
| Git の配置 | `.git` の `gitdir:`、`commondir`、`worktrees/*/gitdir`、サブモジュールの `config` |
| Git 共通ディレクトリ C の `HEAD` | 存在と種類。内容は読まない |
| マウントと走査 | マウント一覧、走査で辿るディレクトリ |
| 候補パス | 存在、種類、実体のパス |
| [配置保護](policy-placement.md)のパス解決 | 通過したディレクトリ、辿ったシンボリックリンクの先 |
| 適用する `rw-copy` の複製元 | ディレクトリのエントリ名・種類・モード、通常ファイルの内容・モード、リンクの先 |

起動計画は、引数、ポリシー、収集した環境とファイルシステムの事実から決まる。前回の起動結果を保存して次回の判断を変えない。filtered の実行中の通信状態は、これに加えて DNS 応答、待受、接続口の観測と経過時間にも従う。

### 外部コマンドとファイル記述子

host/none は `bwrap` 以外の外部コマンドを実行しない。`bwrap` はホストの `PATH` から探し、不在なら種類 `bwrap` の診断で終わる。filtered の追加依存は[実証の完了条件](proof-gate.md)で確定する。

次のデータはメモリ上のファイルを作り、ファイル記述子を通して bwrap に渡す。ホストのファイルシステムには現れない。

- `hide` 用の空ファイル。
- `rw-copy` で複製する通常ファイルごとの内容。
- seccomp フィルタ。

記述子を作る前に、開けるファイル数の soft 上限を hard 上限まで毎回引き上げる。包んだコマンドも変更後の上限を引き継ぐ。同じ入力に対する結果を保つため、必要な場合だけ上げる方法にはしない。入れ子は記述子を作らず、上限も変更しない。

たとえば soft 上限が 1024 で `hide` のファイルが 1100 個ある場合も、hard 上限が足りれば起動できる。それでも記述子を用意できなければ種類 `bwrap` の診断で終わる。`rw-copy` も通常ファイル1個につき記述子1個を使うため、[複製のエントリ数上限](mounts.md)がこの数にも効く。

### 読み込みで止まらないための制約

ポリシー、秘密、`.git` と G 配下のファイル、`rw-copy` の複製元ファイルは、**待たずに開き、開いた記述子で通常ファイルと確認してから読む**。FIFO を指定されても読み手待ちで停止しない。G は[Git のパス導出](policy.md)で得る管理ディレクトリを指す。

| 対象 | 読込量の上限 | 違反時の診断 |
|---|---|---|
| ポリシーファイル | 1ファイル 1 MiB | `policy` |
| `.git` と G 配下のファイル | 1ファイル 1 MiB | `path` |
| 秘密ファイル | 一般の 1 MiB より先に、末尾改行除去後の値 64 KiB が効く | `secret` |
| `rw-copy` の複製元 | 1ファイル 1 MiB の制限は適用しない。1項目あたり 4096 エントリ、通常ファイル内容の合計 64 MiB | `path` |

上限を超えるファイルは、通常ファイルでない場合と同じ種類の診断で拒否する。秘密の改行・値の検査は[認証情報](environment.md)、複製の範囲は[マウント](mounts.md)に従う。マウント一覧と走査するディレクトリは、この読込規則の対象外。

### リンクを辿る対象

| 対象 | 開く名前自身がシンボリックリンクの場合 |
|---|---|
| ポリシーファイル・秘密ファイル | 辿る。dotfiles へのリンク配置を許す。実体は配置保護の検査対象 |
| `.git` と G 配下のファイル | 辿らない |
| 実体化済みの `rw-copy` 複製元 | 辿らない。複製元ディレクトリの中のリンクも辿らず、リンクとして複製 |

[配置保護](policy-placement.md)のパス解決は、カーネルと同じくリンク40本まで辿る。超過後は存在しない成分と同じ扱いにする。

- 保護対象のパスは、そこまでに参照した場所を検査する。
- 書かれたマウント項目は、実体を持たない項目として飛ばす。
- `--workspace` は、[workspace の導出](policy.md)に従って `path` の診断になる。

### 信頼する情報と対象外

起動元の `HOME`、`XDG_CONFIG_HOME`、`PATH`、`KAKOI`、カレントディレクトリを信頼する。ホスト側でこれらを変えると、読むプロファイル、入れ子の判定、作業場所も変わる。この前提を README に記す。

cgroup による資源制限は対象外。filtered の DNS 由来 IP 許可は kakoi-net が担当し、bwrap 単体の機能には限定しない。

### bwrap の固定引数

host/none の引数は、次の固定部分から順に始まる。固定部分はポリシーで変更できない。

| 順序 | 引数 |
|---|---|
| 1 | `--ro-bind / /` |
| 2 | `--dev /dev` |
| 3 | `--proc /proc` |
| 4 | `--unshare-all` |
| 5 | `host` の場合だけ `--share-net` |
| 6 | `--die-with-parent` |
| 7 | `--chdir <カレントディレクトリ>` |
| 8 | `--seccomp <ファイル記述子>` |
| 9 | `--argv0 <COMMAND に与えた文字列>` |

続けて、[適用順](mounts.md)のマウント項目、区切りの `--` を1個、解決済みコマンドのパス、`ARGS` を置く。区切りは、`-x/tool` のようなコマンドパスを bwrap のオプションとして読ませないために必要。

`--print-plan` で `COMMAND` を省略した場合は、`--argv0` とその値、末尾の `--` とその後を計画の引数列から省く。記述子は計画では記号で表し、番号は起動直前に割り当てる。filtered の接続機構と起動順序は[実証の完了条件](proof-gate.md)で確認する。

### 確認例

- `--policy-file` に FIFO を指定しても待ち続けず診断になる。
- 1 MiB を1バイト超えるポリシーファイルは `policy` になる。
- `G/commondir` をリンクにすると `path` になる。
- soft 上限 1024 で1100個のファイルを隠す起動が成功し、隔離内の soft 上限は hard 上限と等しくなる。
- `init` は許された設定配置以外へ書かない。コマンドを包む起動自身や `rw-copy` の内部変更もホストへ永続化しない。

### filteredで観測する追加情報

ホストDNS構成とその変更、起動時のホストOSのCA証明書、指定インターフェースの存在と消失、初版の固定公開の確保状態を観測する。待受状態の自動検出は後続の動的公開で追加する。取得対象と機構は実証工程で列挙する。アプリの申告で許可を増やさない。永続状態を持たずファイルを書かない既存の境界は維持する。
