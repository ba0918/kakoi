# 入れ子・出力・終了

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

入れ子では外側の隔離を使い、通常の起動では検査を順に進める。この文書は、呼び出し元が観測する警告・診断・終了結果と計画出力を定める。

## 12. 入れ子と並列

### 12.1 入れ子

入れ子のとき、`init` の形を除き（第 4.1 節）、`--print-plan` を除き、`kakoi` はポリシーを読まず、bwrap を起動せず、環境を変えず、`kakoi: warning:` で始まる 1 行で内側のプロファイルが適用されないことを標準エラーに出してから、コマンドをそのまま exec する。

コマンドの解決（第 4.2 節）は入れ子でも行い、見つからなければ種類 `command not found` の診断で終了コード 127 で終わり、見つかったが exec に失敗すれば種類 `command not executable` の診断で終了コード 126 で終わる。exec の argv[0] は `COMMAND` に与えた文字列である。

解決には、`--print-plan` の有無にかかわらず、`kakoi` が受け取ったホストの`PATH` を使う。`--print-plan` の無い入れ子ではポリシーを読まないので第 8 節の `PATH` が無く、`--print-plan` のある入れ子でも実際に exec されるとすればホストの環境だからである。

`PATH` が無ければ探さない。カレントディレクトリとホームディレクトリの検査は行わない（第 13 節の順序）。

#### 入れ子で計画を見る場合

`--print-plan` は入れ子でもポリシーを読んで計画を表示し、計画の先頭に入れ子であることを示す。表示する計画の `PATH` は隔離の中のものだが、解決したコマンドの欄はホストの `PATH` で解決した結果である。

#### 環境変数による検出の限界

検出は環境変数だけに頼る。この設計には 2 方向の隙間がある。

- 隔離の中で環境を空にしてから `kakoi` を起動すると検出が外れ、隔離の中に二重の隔離を
  作ろうとする。二重の隔離は外側より広がらない。秘密ファイルが外側で空にされているため、秘密を持つ  ポリシーでは種類 `secret` の診断で起動できない。
- ホスト側で `KAKOI=1` を設定してから起動すると、隔離なしでコマンドが動く。その起動では
  必ず入れ子の警告が出るので、意図しない場合は標準エラーで気づける。

どちらも 0.3 では塞がず、README に書く。

### 12.2 並列

コマンドを包む起動は永続状態を持たない（第 14 節）。同時に起動した複数の `kakoi` は、コマンドを包む起動どうしで内部状態を共有せず、一方の終了時に他方を停止しない。filteredのホスト公開ポートは競合し得るため、番号の変更・不足には[公開の割当](network/publish-config.md)と[公開の復帰](network/publish-lifetime.md)を適用する（同じ `NAME` の `init` を同時に起動した結果は保証しない。書く内容が同じなので、どちらが書いても残るファイルは同じである）。

成功の観測条件: 隔離の中から `kakoi` を起動すると警告 1 行が出てコマンドが外側の境界で動き、入れ子でない `kakoi` を 2 つ同時に起動しても両方が第 1 節の結果を満たす。反例: 入れ子でbwrap が二重に起動する。

## 13. 出力と終了コードの契約

診断は標準エラーに 1 行、`kakoi: <種類>: <説明>` の形で出す。種類は契約であり、説明は自由文である。警告は `kakoi: warning: <説明>`。警告は下の表のどの行にも先行して出うる。

### 表示する値のエスケープ

`kakoi` 自身が書く文字列（診断、警告、計画の表示、使い方、版）に埋め込む値（パス、キー名、変数名、コマンドライン引数）は、改行（LF、CR）とその他の制御文字（0x00〜0x1F、0x7F）を含んでいれば、見える表記に逃がして出す。診断と警告はこの規則で末尾の改行 1 つを除いて改行を含まず、1 行になる。

計画の表示と使い方は複数行でよく、行の構造は第 20 節の整形の委譲に含まれる。Unicode の行区切り（U+2028、U+2029、U+0085）は制御文字に数えない。包んだコマンドの出力は対象外。見える表記の形と、UTF-8 として不正なバイト列の表し方は第 20 節で委譲する。


### 診断の種類

#### `usage`

コマンドラインの誤り。未知のオプション、`COMMAND` の欠落、文法の誤り、`--profile` の名前が第 4.1 節の制約に反する、`--help` または `--version` と他の引数の併用、`init` と `NAME` 以外の引数の併用、`init` の `NAME` が第 4.1 節の制約に反する、`--rw` と `--hide` 以外のオプションの繰り返し、コマンドラインの中での同じパスへの違う指令

#### `policy`

ポリシーファイルの読み込みと合成の失敗。プロファイルまたは `--policy-file` の不在、TOML の解析失敗、未知の固定キー、必須キーの欠落または空、相対パス、`~ユーザー名`、未知の変数、同じ段での同じパスへの違う指令、`inherit` での `pass`、`env.set` と `secrets` の同じキー、ポリシーファイルが通常ファイルでないか第 14 節の上限を超える

#### `path`

次のいずれかに当たるとき。パス解決に使う「根の項目」「露出する組」は[配置保護](policy-placement.md)で定義する。

| 検査するもの | 拒否する条件 |
|---|---|
| 基本の位置 | workspace が不在または非ディレクトリ。cwd を取得できない。設定ディレクトリが存在するのに実体を得られない |
| マウントの種類 | `rw` にディレクトリ以外、`rw-file` にディレクトリ、`rw-copy` にディレクトリでも通常ファイルでもないもの |
| 広すぎる範囲 | worktree・workspace・`rw`・`rw-file` が `/`、HOME、HOME の祖先 |
| Git の導出 | `${git_common_dir}` の相互リンクが成立しない。`.git` と G 配下の読込対象が非通常ファイルまたは上限超過の場合も含む |
| 保護対象 | ポリシー、設定ディレクトリ、秘密、`path-prepend` が書ける項目内にある。または、それらのパス解決が書ける項目内を参照する |
| 根の外への移動 | 書かれた `rw`・`rw-file`・`hide`、明示 workspace、走査 `root`、`hide-mounts` の `under` の解決が書ける項目内を参照し、実体が根の項目の外にある |
| hide と生成のリンク | 書かれた `hide`、走査 `root`、`under` の解決が書ける項目内のリンクを辿る |
| 生成の起点 | `root` または `under` の解決が書ける項目内を参照し、実体が書ける項目のマウント点でない |
| 露出する組 | 書ける項目内を参照して解決される項目が `hide`・`ro`・`rw-copy` と露出する組になる。下の段と同一の場所か、生成段を含め段を問わず祖先へ効く場合を含む |
| 固定部分への着地 | どの指令でも、実体が `/`、`/dev`、`/proc` と同一、または `/dev`・`/proc` の中 |
| 明示 workspace のリンク | リンクを辿った実体が、workspace 由来でない根の項目の外 |
| cwd | 適用後の cwd が `hide` の中 |
| マウント一覧 | 値を持つ `under` があるのに一覧を読めない |
| 走査したリンク | 一致したリンクの先が差し替えられうる `ro` 項目の中 |
| コピー元 | `rw-copy` の複製元を読めない、エントリ数または内容の合計が上限超過 |
| init | 出力名が既存。設定ディレクトリと祖先・`profile/`・`secrets/` を作れない、書けない、または出力名より上の成分の実体が非ディレクトリ |

#### `secret`

秘密ファイルが空、読めない、NUL バイトを含む、通常ファイルでない、第 9 節の値の上限を超える

#### `env`

`HOME` が第 2 節「ホームディレクトリ」の条件に反する、`GIT_CONFIG_COUNT` が数値でない（空を含む）か項目を足すと上限を超える

#### `bwrap`

`bwrap` がホストの `PATH` に無い、`bwrap` に渡すファイル記述子を用意できない（第 14 節）、`bwrap` の exec 自体に失敗した

#### `command not found`

コマンドが見つからない。説明はコマンド名

#### `command not executable`

入れ子で、見つかったコマンドの exec に失敗した。説明はそのパスとエラー

### 終了結果

| 状況 | 標準出力 | 標準エラー | 終了コード |
|---|---|---|---|
| `command not found`・`command not executable` 以外の診断 | 無し | 診断 1 行 | 125 |
| `command not found` | 無し | 診断 1 行 | 127 |
| `command not executable`（入れ子のみ） | 無し | 診断 1 行 | 126 |
| bwrap 自身の失敗（マウントの失敗、コマンドの exec の失敗） | 無し | bwrap の出力 | bwrap の終了コードをそのまま |
| コマンドが終了コード n で終了 | コマンドのもの | 警告があれば + コマンドのもの | n |
| コマンドがシグナル s で終了 | コマンドのもの | 警告があれば + コマンドのもの | 128 + s |
| `--print-plan`、診断なし（入れ子を含む） | 計画 | 警告があれば | 0 |
| `--print-plan`、診断あり | 無し | 診断 1 行 | 上の診断の行と同じ |
| `--version`、`--help` | 版または使い方 | 無し | 0 |
| `init`、診断なし（入れ子を含む） | 書いたファイルのパス 1 行 | 無し | 0 |
| 入れ子（`--print-plan` なし） | コマンドのもの | 警告 1 行 + コマンドのもの | コマンドのもの。コマンドが見つからなければ 127、見つかったが exec できなければ 126 |

### 起動前に行う検査

`--print-plan` は bwrap の起動の直前までのすべての処理（ポリシーの読み込み、事実の収集、秘密の読み込み、`bwrap` の所在確認、コマンドの解決）を行い、診断が出る状況では計画を表示せずその診断で終わる。

検査は次の順で行い、最初に当たった診断で終わる。複数の診断が同時に成り立つ入力でも、出る診断はこの順で決まる。段階は検査を行う時点を定めるもので、診断の種類は段階と独立である。

1. `--help` と `--version` の形（終了コード 0。カレントディレクトリを必要としない）
2. 文法（第 4.1 節の規則。`usage`。パスの同一性は含まない）。この後、`init` 以外の形では、入れ子
   （第 12.1 節）で `--print-plan` が無ければ、段階 3〜8 を飛ばし、入れ子の警告を出して段階 9 へ進む。`init` の形は
   入れ子を見ず、段階 4 のホームディレクトリの検査だけを通り、書き込み（`path`）を行って終わる
   （第 4.1 節）
3. カレントディレクトリの取得（`path`）
4. ホームディレクトリ（第 2 節。`env`）
5. ポリシーファイルの読み込みと合成（`policy`）
6. ワークスペースと変数の導出（第 5.2 節。`path`）
7. マウントの解決。内部の順序は次の表に従う。
8. `bwrap` の所在（`bwrap`）
9. コマンドの解決（`command not found`。入れ子でも効き、見つからなければ終了コード 127）
10. 起動。host/noneは記述子の用意（失敗は `bwrap`、125）と bwrap の exec（失敗は `bwrap`、125）。filteredは通信の準備を完了してから監督下で起動する（[起動・復帰](network/recovery.md)）。入れ子は
    コマンドの exec（失敗は `command not executable`、126）

#### 段階7の内訳

| 順序 | 検査 | 診断 |
|---|---|---|
| 1 | 展開・実体化後のパス同一性（第5.4節） | 同じポリシー段なら `policy`、CLI 内なら `usage` |
| 2 | 生成前に、走査 `root`、次に `under` の根とリンクの規則 | `path` |
| 3 | 第6.3節の生成。走査リンクの先の差し替えられる `ro`、マウント一覧の読込失敗もここで検査 | `path` |
| 4 | 第6.1・6.2節の種類検査 | `path` |
| 5 | 第5.6節の保護対象、根、露出する組、固定部分への着地、広さ | `path` |
| 6 | 第6.5節の位置と cwd | `path` |
| 7 | 第9節の秘密読込 | `secret` |
| 8 | 環境合成中の `GIT_CONFIG_COUNT` | `env` |
| 9 | `rw-copy` の読込。対象種類、読めない複製元、量の上限 | `path` |

コピー読込を最後に置くのは、安く分かる誤りを先に示し、検査を通って実際に適用される項目だけを読むため。

#### 同じ段階で複数の誤りがある場合

1 つの検査の中で複数の項目が診断になるときは、マウント項目は第 6.4 節の順序、環境変数と秘密は名前のバイト順で最初のものを出す。第 5.6 節の保護対象のパスの検査では、プロファイル、`--policy-file`、設定ディレクトリ、秘密ファイル（名前のバイト順）、`path-prepend`（合成後の並び順）の順で最初のものを出す。

走査の `root` と`hide-mounts` の `under` の根の項目の検査は段階 7 の中で生成の前に行うので、その診断は書かれた項目の検査より先に出る。書かれた項目の根の項目の検査と露出する組の検査では書かれた項目を第 6.4 節の順序で、次に `--workspace` を見る（項目をまたいで 2 つの検査をどう交互に行うかは第 20 節で委譲する。
最初に出る診断だけが変わる）。

### exec と失敗の伝わり方

host/noneでは `kakoi` は bwrap を子プロセスとして待つのではなく exec する。bwrap の失敗がそのまま呼び出し元に見えるのはこのためである。bwrap 自身の exec に失敗したとき（見つけた後に消された、実行できない）は、まだ `kakoi` が動いているので種類 `bwrap` の診断になる。包んだコマンドのexec 失敗は、通常の起動では bwrap の失敗としてそのまま返り、入れ子では `command not executable` になる。この非対称は許容する（第 4.2 節）。

### 人が読む計画：要約と全量

要約と全量は、表示する内容をこの節で定める。レイアウトや文言は 0.3 の契約に含めない。人が読む形は2つある。要約（`--print-plan` の省略時の形）は、使ったポリシーファイルの実体のパス（`profile/default.toml` の代わりに組み込みの既定を使ったときは、その欄に文字列 `kakoi init` を含む。
この文字列だけが契約で、前後の文言は第 20 節で委譲）、4 変数の値、ネットワークのモード、各マウント項目の適用か飛ばしかとその理由（ホームディレクトリは`~` に縮め、グローバルスコープ以外から来た項目にだけ出所を添える）、最終の環境のホストとの差分（消した変数の名前、設定した変数とその値、秘密の名前。
秘密の値は伏せる。ホストと同じ変数は数だけ）、解決したコマンドのパスを含む。`rw-copy` の項目があるときは、その指令が何をするか（ホストの内容で始まり、書き込みはホストに出ず、終了時に消える）が読んで分かる説明を添える。指令の名前だけでは `rw` との違いが読み取れないためである。

文言は第 20 節で委譲する。全量（`--print-plan=full`）は、要約の代わりに合成後のポリシー、各マウント項目の実体のパスと出所、最終の環境の全体（秘密の値は伏せる）、解決したコマンドのパス、bwrap の引数列を含む。どちらの形でも、飛ばした項目とその理由、`rw-copy` が複製できなかったエントリとその理由（第 6.1 節）、`rw-copy` の説明、入れ子の印は同じに出る。


### ツールが読む計画：JSON

JSON（`--print-plan=json`）は、LLM エージェントとツールのための形で、人が読むことは想定しない。全量と同じ内容に要約の環境の差分を加えて、改行 1 つで終わる 1 行の JSON として出す。文字の形と違い、この形の内容は契約である。トップレベルのキーと値は次のとおり。

| キー | 内容 |
|---|---|
| `format_version` | 整数。1から開始。キーを消すか意味を変えるときに上げ、追加だけでは上げない |
| `nested` | 入れ子かどうか |
| `policy_sources` | 使ったポリシーの情報 |
| `variables` | 4変数。値がない変数は `null` |
| `home` | HOME |
| `policy` | 合成後のポリシー |
| `mounts` | 適用項目の実体パス、種類、書かれた値、出所 |
| `skipped_mounts` | 飛ばしたマウント項目 |
| `left_visible` | 走査後も見えるままにした対象 |
| `skipped_paths` | 飛ばしたパス |
| `not_copied` | 複製できなかった項目の実体パス、エントリのパス、理由 |
| `environment` | 最終環境。秘密の値は `null` |
| `environment_changes` | 要約と同じ、ホスト環境との差分 |
| `command` | 解決したコマンド。COMMAND 省略時は `null` |
| `bwrap` | bwrap の情報 |
| `bwrap_arguments` | 次の形式の引数列 |

`bwrap_arguments` の各要素は `kind` で区別する。

| `kind` | 追加の値 |
|---|---|
| `literal` | `value` に引数の文字列 |
| `seccomp-filter` | フィルタの記述子を表す |
| `empty-file` | 空ファイルの記述子を表す |
| `copied-file` | コピーする通常ファイルの長さだけを `bytes` に持つ。内容は出さない |

出所は、`kind` が `profile`、`built-in-default`、`policy-file`、`command-line`、`scan`、`hide-mounts`、`secret`、`config-secrets` のいずれかである。ファイルのあるものは `path`、`secret` は `name` を持つ。

同じ `format_version` の間は、既存キーをなくさず意味を変えない。キーの追加は許す。`not_copied` と `copied-file` は追加なので版は1のまま。

秘密の値はどのキーにも出さない。不正な UTF-8 は置換文字で表し、制御文字は JSON のエスケープで表す。生の制御文字は出さない。

### 確認例

成功の観測条件: 「診断の種類」と「終了結果」のすべての条件が第 15 節のテストで観測され、隣り合う段階の診断が同時に成り立つ入力では先の段階の種類が出て、改行や ESC を含むプロファイル名やキー名を与えても標準エラーが1 行のままである。反例: ポリシーの誤りが終了コード 1 で終わり、コマンドの失敗と区別がつかない。キー名に含めた ESC がそのまま端末に届く。


### filteredの監督・終了の追加契約

filteredは[プロセス寿命](network/process.md)に従い監督を残し、主コマンドの終了後に残存子を回収する。このモードのSIGTERM・Ctrl-Cと安全上の125優先は同文書を定義元とし、上の一般的な終了結果より優先する。動的な公開と通信状態の通知は[通知](network/notification.md)と[公開対象](network/publish-target.md)に従う。
