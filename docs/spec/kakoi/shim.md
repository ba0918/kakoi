# シムの契約

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

[公開ドキュメント（第16節）](documentation.md)の一部。シムはコマンドの手前に置き、kakoiを経由して起動するための小さなスクリプトである。codexは同梱例であり、この契約は包む対象全般に適用する。

## 雛形とツールごとの設定

`examples/shim/codex` に、シムの雛形を置き、README から指す。セットアップスキルは同じ内容の写しを自身のディレクトリに持つ（この節のスキルの記述）。スキルだけを入れた利用者の手元にはソースツリーが無く、入手先を聞く手順が働かないためである。2 つの写しが一致していることは検証で確かめる。本仕様のシムの規則は包む対象に依らず、codex はここでは例にすぎない。雛形は包む対象に依らない汎用の本体と、包む対象ごとに書き換える先頭のツール節から成り、同梱するのは例として codex の値を入れたものである。ツール節の中身は 5 つ: 実体のコマンド名、差し込むフラグ（対象が自前のサンドボックスを切るために受け付けるもの。無ければ空）、引数の写し（対象のオプションを `kakoi` の `--workspace` と `--rw` に写す対応）、素通しの許可リスト、フラグを付けない一覧。本体はツール節のフラグが空でも同じ動きをし、何も差し込まない。

## 隔離に通す条件と例外

既定は、すべての起動を `kakoi` に通すことである。`--help` や `--version` も例外にしない。隔離の要否をサブコマンドから決めることはしない（対象の版が上がって知らないサブコマンドが増えても、それは隔離に入る）。

例外は 2 つ。環境変数 `KAKOI_SHIM_OFF=1` は、`kakoi` もフラグも付けずに実体を exec する（ホストは第 14 節で信頼する側で、既知の隙間 8 のとおり既に外せるので、安全の増減は無い）。ツール節の許可リストに書いたサブコマンドも同じく素通しする。許可リストには、利用者が承認したサブコマンドだけを書く（ホワイトリスト方式）。素通しの結果は利用者の責任で、承認の前に、そのサブコマンドでモデルが動かない（第 2 節）ことを利用者が確かめる（対象の文書を読み、起動して観測する。codex なら起動時に表示されるヘッダーと `exec` の表示で分かる）。

## 実体の探索と引数の受け渡し

本体は、`PATH` から自分自身を除いて実体を探し、`PATH` で見つけた候補のパスをそのまま `COMMAND` として`kakoi` に渡す（名前で渡すと隔離の中で `PATH` のシムに戻って呼び合う。第 4.2 節により隔離の中の対象の argv[0] はそのパスになる）。候補のシンボリックリンクは最後まで解決しない（版管理ツールのシムは自分の名前でどのツールかを決めるので、最後まで解決すると別のコマンドを指す）。自分自身との比較にだけ実体のパスを使う。

`kakoi` に通す経路でだけ、`/tmp/kakoi` が無ければ作る。その名前がシンボリックリンクなら作らずに止まる（同じホストの別の利用者が先にリンクを置く形。`/tmp` は `hide` で書き込める項目でないので第 5.6 節の検査は届かない）。素通しの経路では作らない。

差し込むフラグは引数列の先頭（グローバルオプションの位置）に常に置き、サブコマンドで位置を変えない。

フラグの有無の例外はツール節のフラグを付けない一覧だけで、そこに書いたサブコマンドは `kakoi` に通すがフラグを付けない。フラグが無くても境界は `kakoi` のもので緩まない（対象の自前のサンドボックスが隔離の中で動くか、対象がそのサブコマンドで動くかは保証しない。動かなければ、そのサブコマンドは隔離の中では使えない）。

引数の写しはツール節の対応に従う。値の書き方は対象の文法に従って読む（次の語、`=` で付けた形、短いオプションに続けた形）。`--` より後ろは走査しない。写しの取りこぼしは隔離が緩む向きに働かない（写し先が足りず対象が書けない側に倒れる）。存在しない写し先は第 6.2 節どおり飛ばされ、雛形は検査しない。

## 一覧の照合と、壊れたときの直し先

許可リストとフラグを付けない一覧の照合は、引数列の先頭の語だけと行う。先頭がオプションなら一致せず、既定どおり隔離に入る（値を取るオプションの一覧を雛形に持たず、誤読の向きを隔離側に固定するため）。

どちらの一覧も出荷時は空で、利用者の手元の写しの中で、壊れたときにだけ増える。雛形は実行時にヒントを出さず、壊れ方と足す先の対応を次の表の形でヘッダーのコメントに持つ。

| 壊れ方 | 足す先 |
|---|---|
| 対象がフラグを拒む、または受け取るが効かない | フラグを付けない一覧 |
| 隔離の中でホストに届かず、かつモデルが動かない | 許可リスト（利用者が確かめて承認） |
| モデルが動くのに隔離の中で壊れる | どちらにも入れない。プロファイルで直す |

許可リストに最初に入りそうな例として認証のサブコマンド（codex なら `login`）もヘッダーで持つ（実測していない読み方の例であり、ツール節の値ではない）。入れ子でも `kakoi` を呼び、入れ子の検出と警告は第 12.1 節の規則で `kakoi` が行う（雛形は入れ子を見ない）。

## 保守側と利用者が確認すること

雛形の検証は人が行い、第 15 節のテストの対象にしない。観測は、`PATH` の先頭にディレクトリを 2 つ置き、前に雛形の写しを包む対象の名前で、後に受け取った引数を表示するだけの包む対象の代わりと `kakoi` の代わりを置いて起動することで行う（素通しの経路でも本物の対象は起動しない）。

保守側は同梱雛形について、次を確かめる。

- 先頭がサブコマンド、オプション、`--help`のどの場合も、kakoiの代役が起動する。
- 対応するオプションを付けると、workspaceとrwへ写した値がkakoiの代役の引数に出る。
- 一覧へ一時的に名前を入れた写しでは、先頭の語がその名前のときだけ素通しまたはフラグなしになる。先頭がオプションなら既定の経路になる。
- フラグを空にしたツール節でも起動する。
- `KAKOI_SHIM_OFF=1`ではkakoiの代役が起動しない。
- 同梱値のフラグを先頭へ置いたとき、実対象へ効果がある。codexの例では起動ヘッダーが`sandbox: read-only`以外になる。

利用者が自分の写しについて守る条件: 許可リストの各項目について、モデルが動かないことを確かめてある。

`docs/shim.md`には、雛形を写してツール節を埋める手順、同梱の値が codex の例であること、上の表、最初に入りそうな例、保守側と利用者の確かめる条件を載せる。

README のシムの節には、雛形を写す最短の手順と`KAKOI_SHIM_OFF=1` の存在、`docs/shim.md` への導線を載せる。
