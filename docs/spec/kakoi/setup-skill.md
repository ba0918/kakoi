# セットアップスキルの契約

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

[公開ドキュメント（第16節）](documentation.md)の一部。利用者のプロファイルとシムを整える補助スキルの手順と操作範囲を定める。

## 配置と実行環境

スキルは`skills/kakoi-setup/SKILL.md`に置く。Agent Skillsの共通仕様に従い、`name`はディレクトリ名と同じ`kakoi-setup`にし、`description`を持つ。

実行するのは隔離の外。シム導入前、`KAKOI_SHIM_OFF=1`、kakoiを通さないCLIという経路を案内する。その間はエージェントが隔離されないため、スキルの差分承認に加え、CLI自体も承認を求めるモードで使うよう説明する。

## 1. 書き先と正本を確認する

プロファイルとシムについて、別のファイルから生成・同期されるものか、他所へのリンクかを利用者に聞く。それらの元になるファイルを「正本」と呼ぶ。ファイルの印や内容からは推測しない。

| 対象 | 質問する時点 |
|---|---|
| プロファイル | 手順の最初。最初の変更提案より前 |
| シム | 利用者が置き場を承認した時点。最初の変更提案より前 |

プロファイルがまだない場合は、先に`kakoi init`で組み込みの既定を書き出すか尋ねる。承認された場合だけ実行する。書き出すのは組み込みの既定そのもので、full計画の合成後ポリシーと同じ内容である。

initを実行しない場合は、プロファイルへの変更提案をせず、その旨を伝える。

## 2. 対象に合わせた変更を提案する

導入済みの対象コマンドを調べ、次を提案する。エージェントCLI以外も対象に含む。

- 状態を書き込む置き場には`rw`。
- 設定や指示を読むファイルには`ro`。
- シムは雛形を写し、先頭のツール節を対象に合わせて埋める。
- 環境固有の代替コマンドは`path-prepend`へ追加する。これは隔離内のPATHであり、ホスト側でシムを見つけるPATHとは別である。

ツール節の値は対象の`--help`出力だけを根拠に提案し、未実測と明記する。実際に対象へ効くことは利用者が確認する。

雛形はスキル自身のディレクトリにある写しから読む。記憶から作り直さない。ツール節より下の本体は、同梱のものも利用者の写しも編集しない。

## 3. 雛形で写せない引数を説明する

`--help`に次の形がある場合、どのオプションがなぜ写らないかを明示する。黙って取りこぼさない。対象コマンド自身には元の引数をそのまま渡すため、取りこぼしは書けない側に働く。

| 対象が受け付ける形 | 雛形での結果 | 案内する回避策 |
|---|---|---|
| 作業ディレクトリを位置引数で渡す | 写らず、workspaceはcwdのまま | そのディレクトリで起動する |
| 一つのオプションに空白区切りで複数値を渡す | 先頭の値だけが写る | rwへの対応なら、対象が許す限りオプションを繰り返す。workspaceへの対応は最後の一つしか残らないため、そのディレクトリで起動する |
| 区切り文字で複数値を一語にする | 全体が一つの不在パスとして写る | rwなら飛ばされ、workspaceならpath診断で止まることを説明する |

## 4. 差分を承認してもらい、書く

プロファイルとシムの変更は、**書く前に**書き先と位置を差分で示し、利用者の承認を得る。

利用者が変更内容を先に指定した場合も、CLI側の書き込み承認がある場合も、差分の提示と承認を省かない。書いてから差分を見せる順序は認めない。

| 状況 | スキルが行うこと |
|---|---|
| 別の正本がなく、現在のファイルを読める | 承認後に変更する |
| 別の正本がある | その場所には書かない。プロファイルなら正本へ足す行、シムなら置く内容を提案する。反映と実行可能ビットの設定は利用者が行う |
| 設定ディレクトリを読めない | full計画の合成後ポリシーと出所を読み、コメントは見えていないと伝える。差分を作れないため、書込可能でもプロファイルへ書かず行の提案にとどめる |

設定を読めない場合、組み込みの既定や記憶で現在のファイル内容を補ってはいけない。

書き先は、設定ディレクトリの`secrets/`以外と、利用者が承認したシムの置き場に限る。この仕様と公開ドキュメントは編集しない。

## 5. シムが実際に選ばれることを確認する

写しは実行可能にし、そのビットを確認する。差分はファイルのモードを運ばないため、差分を示すときに「実行可能にもする」と伝える。ビットがなければPATH探索で飛ばされ、対象が直接起動してしまう。

確認は**設置後**に行う。利用者に起動経路を挙げてもらい、少なくとも次の二つを確認する。

| 経路 | 誰が確認するか |
|---|---|
| 利用者の対話シェル | 利用者 |
| スキルを実行中のエージェントCLIのコマンド実行 | スキル |
| その他の経路 | スキルから実行できなければ利用者 |

対象コマンドそのものは起動しない。各経路で`command -v NAME`の結果を実体パスへ解決し、承認した写しの実体と一致することを確かめる。対話シェルでは、その名前を関数やaliasが取っていないことも確認する。

旧仕様には「command -vは関数とaliasを見ない」という説明がある。この説明の正確性は[問題の記録](../../ir/FLAGS.md)で追跡し、今回の整理では確認手順自体を変更しない。

CLI側だけ一致しない場合は、利用者が変更したPATHがCLIプロセスへ反映されていない可能性を伝え、CLI再起動後に再確認する。版管理ツールのshimsが前にあれば写しは素通りされる。対話シェルでは後ろでも、非対話のPATHでは前になる場合があることを案内する。

## 6. 計画に反映されたことを確認する

変更前後の`--print-plan`を並べて確認する。別の正本がある場合は、利用者が反映したと伝えてから変更後の計画を取る。前後とも`--print-plan=full`を使い、提案した項目が合成後ポリシーに現れなければ、その旨を伝える。

隔離内で壊れたコマンドの相談では、[シムの直し先の表](shim.md)に従い、一覧へ足すかプロファイルで直すかを差分で提案する。判断は利用者に求める。

## 秘密にアクセスしない

`secrets/`の中を一覧・読取・書込しない。置き場とモードの案内にとどめる。守る対象は秘密の値と、どんな名前のファイルがあるか。既にプロファイルや計画に現れる秘密の環境変数名とパスは、この非開示対象には含めない。

secretsの項目がある場合、配置状況は起動時の結果から判断する。

| 起動の結果 | 分かること |
|---|---|
| 秘密の不在の警告 | 置かれていない |
| secret診断 | 置かれているが値を使えない |
| 警告も診断もない | 置かれている |
| そもそもsecrets項目がない | 判断できない。利用者に尋ねる |

## 人が確認すること

スキルは第15節のテスト対象にせず、人が確認する。SKILL.mdに上の操作境界が指示として書かれていることに加え、実際の試行で次を観測する。

- 通常の変更と、利用者が内容を先に指定した変更の双方で、書く前に差分と承認要求が出る。
- 各書き先への最初の提案より前に、別の正本があるか質問する。
- プロファイルがなければinit実行を尋ねる。未作成のまま項目を提案しない。
- 別の正本がある場所には書かず、行または内容を提案する。
- 写せない引数の形を持つhelpを与えると、該当箇所・理由・回避策を説明する。
- シム設置後に、各経路での探索結果を確認する。
- 設定を読めない場合、コメントは見えていないと伝える。

Agent Skills形式への適合は、skills-refパッケージの`agentskills validate`で検証する。独自のインストール手段は作らず、READMEに`gh skill install`の形を書く。
