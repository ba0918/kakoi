# 端末の保護

Status: Approved（2026-09-16。IR抽出・対応付けを承認。文章の追加校正は別件）

対話操作を保ったまま、制御端末への TIOCSTI による入力注入を拒否する。ここでは拒否する呼び出しと、保護の対象外を区別する。

## 11. 端末の保護

隔離の中のプロセスが制御端末にキー入力を注入する `ioctl`、`TIOCSTI` を seccomp フィルタで塞ぐ。フィルタは bwrap の `--seccomp` で渡す。

### 拒否する呼び出し

フィルタの規則は次の 3 つだけである。

- 呼び出しのアーキテクチャが x86_64 でないシステムコールは、そのプロセス全体（全スレッド）を
  終了させる。
- システムコール番号に x32 のビット（`0x40000000`）が立っているシステムコールも、そのプロセス全体を
  終了させる。これら 2 つによって 32 ビットと x32 のバイナリは隔離の中で動かない。
- `ioctl` のうち、第 2 引数の下位 32 ビットが `TIOCSTI` に等しいものは `EPERM` で失敗させる。比較を
  下位 32 ビットで行うのは、カーネルが第 2 引数を 32 ビットとして受け取るためで、上位ビットを立てた呼び出しを素通しにしないためである。

### 対象外と対話操作

これ以外のシステムコールは通す。塞ぐのは `TIOCSTI` だけである。仮想コンソール向けの別の注入経路（`TIOCLINUX`）、端末への書き込みと端末の応答を使った注入、ディスプレイサーバのソケットを通した入力の合成は対象外で、README に既知の隙間として書く。最後の 1 つは同梱プロファイルの `hide` と`unset` で経路を消す。

bwrap の `--new-session` は使わない。制御端末との関係を切ると対話的なプログラムの挙動が変わりうるためである。

成功の観測条件: 隔離の中で `TIOCSTI` を呼ぶと `EPERM` で失敗し、上位ビットを立てた要求番号でも`EPERM` で失敗し、x32 のビットを立てた番号でシステムコールを呼ぶとプロセスが終了し、フィルタの先頭がアーキテクチャの検査であることがフィルタのバイト列の検査で確かめられ、隔離の中の対話的なプログラムが制御端末を持ち続ける。反例: フィルタが `TIOCSTI` 以外の `ioctl` を拒否して端末のサイズ取得が失敗する。
