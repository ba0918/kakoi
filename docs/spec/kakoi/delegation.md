## 20. 未決と委譲

### 別作業で判断する事項

ここに挙げる事項は、今回の文章整理では決定しない。

- 同梱プロファイルの `ro ~/.codex/skills` は、codex の公式文書（2026-09-07 時点）がスキルの探索先として
  挙げていないパスである（挙げているのは `.agents/skills`、`~/.agents/skills`、`/etc/codex/skills`）。
  本改訂の範囲外で、別の作業で保守側が決める。それまで同梱プロファイルは写しのままとする。

- セットアップスキルの、エージェント CLI でない包む対象に固有の手順。事例が出たときに別の作業で
  決める。それまでスキルは「包む対象のコマンド」の一般の手順だけを持つ。

### 実装側で決めてよい事項

以下は本仕様の振る舞いを保つ範囲で選べる。

- 内部のモジュール構成と、TOML の読み込みに使うライブラリ。
- seccomp フィルタを bwrap に渡すファイル記述子の作り方（パイプかメモリ上のファイルか）と番号の割り当て。
- 計画の表示の整形。第 13 節の内容を含むことだけが条件。
- 警告と診断の説明部分の文言。接頭辞と種類、および第 5.6 節と第 6.3 節が検査ごとに要求する要素
  （多くは 3 つ、固定部分への着地の拒否は 2 つ）だけが契約。
- 走査の探索順と並列化。結果を第 6.4 節で並べ直し、走査の中で出る診断が名指すリンクはパスの
  バイト順で決まる（第 6.3 節）ため、順序は結果に影響しない。
- `rw-copy` の複製元を読む順と並列化。引数に並ぶ順（ディレクトリが先、同じディレクトリの中は
  エントリ名のバイト順）は第 6.1 節の契約なので、どう読んでも結果は同じである。
- 制御文字の見える表記の形と、UTF-8 として不正なバイト列の表し方（第 13 節）。どの形でも「1 行、
  制御文字なし」は保たれる。
- 第 5.6 節と第 6.3 節の診断の要素に出すパスの形（書いたまま、展開後、実体のどれでもよい）。検査ごとに
  要求する要素が含まれることだけが契約。
- 第 5.6 節で、根の項目の検査と露出する組の検査を項目をまたいでどう交互に行うか（項目ごとに 2 つを
  行ってから次の項目へ進むか、検査ごとに全項目を見るか）。最初に出る診断だけが変わる。
- 第 5.6 節で、診断に名指すリンクや書き込める項目が複数あるときの選び方、保護対象の 3 つの規則の
  どれを出すか、通ったディレクトリがディレクトリでない成分だったときの名詞、理由の文言。
- `--print-plan` で組み込みの既定を使ったことを示す文言。文字列 `kakoi init` を含むことだけが
  契約（第 13 節）。
- `--print-plan=json` の 1 行の中の空白とオブジェクトのキーの順序。第 13 節のキーと値の意味、1 行である
  ことだけが契約。
- `init` が `profile/` と `secrets/` を作る順と、書き込みの途中で失敗したときに作ったディレクトリを
  残すか消すか。どちらでも次の `init` の結果は同じ。

実装者はここに無い新しい観測可能な振る舞いを黙って選ばない。必要になったらこの仕様に戻す。

### ネットワーク改訂の実装裁量

合意した挙動を変えない内部構造、関数名、内部型、処理手順と検証方法は担当側で決める。許可範囲・安全性・対応環境・設定の意味・公開APIの責務が変わる判断は利用者へ戻す。未実証の条件を満たせなければ[実証の完了条件](proof-gate.md)に従い製品実装へ進まない。
