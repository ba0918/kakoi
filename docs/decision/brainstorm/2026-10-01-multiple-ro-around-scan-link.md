# 走査のリンクの先を複数の ro が囲むとき

## Context

走査が見つけたリンクの先が書かれた "ro" の項目の中にあるとき、その "ro" が隔離の中から差し替えられるなら止め、差し替えられないなら隠さずに理由付きで残す（REQ-170、REQ-403）。
IR はこの "ro" を「その ro」と一つの前提で書いており、リンクの先を複数の "ro" が囲むとき（外側の `ro /home/u` と内側の `ro ~/.claude/settings.json`）にどれで判定し、どれを名指すかを定めていない。
2 周目の品質診断で、実装が書かれた順で最初の一つだけを見て、差し替えられる内側の "ro" があっても止まらないことが分かり、「どれか一つでも差し替えられるなら止める」に直した（main aeae137、コミット 20da6fd）。
ここでは、その判定と名指しを IR に書く。

事実（2026-10-01、main aeae137）: 実装は、囲む "ro" のうち差し替えられるものがあれば、書かれた項目の並び（実体のパスのバイト順、外側が先）で最初の差し替えられるものを診断に名指して止まる。差し替えられるものが無ければ、同じ並びで最初（最も外側）の "ro" を理由に名指して残す。
事実: 診断に名指すリンクは、リンクのパスのバイト順で最初のものである（REQ-170、REQ-295）。

Position: A1〜A3 を IR（REQ-170、REQ-403、EX-962、EX-963）に写し、照合を 3 回行って指摘 0 件。承認待ち。

## Agreements

  - why: 次の起動で向きを変えられるのは差し替えられる "ro" の方で、外側の "ro" が差し替えられなくても、リンクを残してよい根拠にはならない。

  - why: リンクもバイト順で最初のものを名指す（REQ-295）ので、並びの決まりが一つにそろう。
