# 初版で作らない草案を後回しとして宣言する

## Context

kotowari に要求の後回し（`- deferred:`）を宣言する仕組みが入った。
kakoi の IR には、pasta の制約で初版では作らないと決めた草案（動的公開、IPv6 リンクローカル）が残っていて、テストが無いという誤りとして `kotowari check` を埋めていた。
check を commit と push で強制したので、作らないと決めた要求と、作ったのに確かめていない要求を区別する必要がある。
どの文書・要求を後回しにし、後回しにしたことで食い違う例やガイドをどう直すかを決める。

Position: 利用者の指示「deferred 対応だけ先にやる」と、人の判断に回る事項も根拠があれば LLM が判断してよいという委任を受けて決めた。

## Agreements

- A1 動的公開の草案 10 文書（`docs/ir/network/publish-config/`、`publish-lifetime/`、`publish-target/` の下）と、使わない公開設定の検査の草案（`docs/ir/network/policy/network-inactive-validation.md`）は、文書単位で後回しにする。後回しの出典は 2026-09-15-kakoi-net の A158 と A159。
  - why: どの文書も冒頭で「後続の動的公開」と書いていて、初版は固定公開だけを提供する（A158）。使わない公開設定の検査の草案は、文書自身が後続の動的公開の入力検査と書いている。
  - decided_by: 利用者（後回しの対応の指示）と LLM（対象の特定）
- A2 IPv6 リンクローカルの接続口の草案（`docs/ir/network/link-local/network-link-local.md`）は文書単位で後回しにする。出典は 2026-09-15-kakoi-net の A167。そこに印を持っていたテストからは、後回しにした要求と例の ID だけを外す（どのテストもほかの ID を持つので、印の無いテストにはならない）。
  - why: 初版はリンクローカル宛ての許可を提供せず、`host-interface` を含む宛先を合成の段階で拒否する（REQ-428）。接続口の入力の形を確かめるテストはあるが、初版の利用者には届かない振る舞いで、後回しと印が食い違うと kotowari が知らせる。
  - decided_by: LLM（利用者の委任）
- A3 広い IPv6 CIDR とリンクローカルの文書（`docs/ir/network/link-local/network-link-local-wide-cidr.md`）は後回しにしない。その例のうち、接続口付きの別ルールでリンクローカルを許可する例 EX-315 の `@about` を、REQ-141 から後回しにした REQ-052 に移す。
  - why: REQ-141 の前半（接続口の無い広い CIDR はリンクローカルを許可しない）は初版で守られている安全の振る舞いで、テストもある。後半を示す EX-315 は接続口付きの許可に当たり、初版では作らない。例だけを後回しにする書き方は無いので、振る舞いの本体である REQ-052 に結び付け直す。
  - decided_by: LLM（利用者の委任）
- A4 ガイド `docs/guide/reference/network/01-modes.md` の host と none の検査の節が引いていた REQ-086、EX-177、EX-178 を、初版の固定公開の検査 REQ-395 と EX-730 に替え、例の書き方も固定公開の形に直す。動的公開と IPv6 リンクローカルの節は、もともと初版では提供しないと書いているので、読み直したうえで指紋だけを写す。
  - why: 使わない公開設定の競合の検査は、初版では REQ-395（host と none では形と設定内の競合だけを検査する）が担っていて、後回しにした要求を今の振る舞いの根拠として示すのは誤り。
  - decided_by: LLM（利用者の委任）
