# コマンドポリシー

## Context

kakoi は今、隔離の中で見える・書けるファイル、通信、環境変数、秘密を制限するが、隔離の中でどのプログラムを実行できるかは制限しない。
隔離の中の LLM エージェントは、読めて実行ビットのあるものなら何でも実行でき、自分で書いたりダウンロードしたりしたものも実行できる。
利用者は、ファイルと通信に続いて、実行できるコマンドも制限したい。
一方で、コマンド文字列を事前に見て危険を判定する方式は、展開・サブプロセス・リンクを理解できず迂回されるため信頼できない（DeepSeek Harness からの収穫の A11）。
何を防ぎたいのか、どの粒度で、何で強制するのかを決める。

事実: この開発環境のカーネル（6.18、WSL2）では Landlock が有効で、ABI 7 を返した（2026-09-25 に実測）。
実測（2026-09-25、別コンテキストの実験、この環境）: Landlock の EXECUTE の禁止は execve を止めるが、動的リンカ経由（`ld.so <ELF>`）、memfd にコピーしての実行、dlopen、LD_PRELOAD、匿名メモリの実行は止めない。マウントの noexec は execve と動的リンカ経由と dlopen を止めるが、memfd は止めない。seccomp で memfd_create を拒否すると memfd 経由は止まる。インタプリタに読ませる形（`sh x`、`python3 x.py`）はどれでも止まらない。bwrap 0.9.0 には noexec を付けるオプションが無く、kakoi が外側のマウント名前空間で noexec のマウントを用意して `--bind` で渡せば中で noexec が保たれる。seccomp はパスの中身を見られない。指定したプログラムを読めなくする（`hide`）と、動的リンカ経由も含めて起動できない。

Position: 照合を 3 回終え、承認待ち。

## Agreements

- A1 コマンドポリシーは 2 層に分ける。カーネルが強制する「境界」の層は、隔離の中で書ける場所に置いた・作ったプログラムの実行と、指定したプログラムの実行を止める。確実ではない「ガードレール」の層は、プログラムの使い方（サブコマンドや引数、たとえば git の commit は許して push は禁じる）を止める。ガードレールは悪意があれば迂回できる事故防止の柵であることを、名前と文書で境界と分けて示し、禁止に当たったときは理由と取るべき手段を返す。
  - why: 使い方の禁止は、隔離の中で起動されるたびに引数を見る手段がラッパーしかなく、本物の実行ファイルの直接呼び出しや別名で迂回できるため、境界にはならない。一方で LLM が禁じた操作をするのは多くが善意からで、理由を返す柵で止まる。トークンの権限を絞る手間を省きたいという利用者の要望に応える。本当に止めるには権限の狭いトークンや filtered の通信の許可を使うと案内する。
  - rejected: 使い方の禁止を作らない（利用者の要望に応えない）。使い方の禁止を境界として扱う（守れないものを守れると見せる）。
  - decided_by: 利用者
- A2 ガードレールの層の判定の主な手段は、正規表現かそれに類する規則とする。LLM によるコマンドの安全性の評価は、1 回ごとに費用がかかり確実でもないので、主な手段にはしない（任意で提供するかは別に決める）。
  - why: 規則は費用がかからず、同じ入力に同じ結果を返す。
  - decided_by: 利用者

- A3 ガードレールの層は、ポリシーに書いたプログラムと同じ名前の見張り役を隔離のための一時的な場所に作り、その場所を隔離の中の PATH の先頭に足す形で、隔離の中での起動のたびに引数を見る。見張り役は kakoi 自身の実行ファイルで、呼ばれた名前で振る舞いを切り替え、規則に当たれば理由を標準エラーに出して 0 以外で終わり、当たらなければ本物のプログラムを実行する。本物を絶対パスで呼べば見張り役を通らないことは、ガードレールの限界として受け入れる。
  - why: 隔離の中で `bash -c` などから起動されても PATH をたどる限り見張り役を通る。利用者の言う「codex jail のような仕組みを汎用にしたもの」に当たる。
  - decided_by: 利用者（推奨を採用）

- A4 ガードレールの規則は、見張り役が受け取った引数を語の並びとして先頭から照合する（Codex の execpolicy の prefix_rule に倣う）。位置ごとに代替の語を並べられ、語には正規表現も書ける。規則ごとに値を取るグローバルオプションを宣言でき、照合の前にそれらを値ごと読み飛ばす。位置を問わず禁じるフラグも書ける。規則には当たるべき例と当たってはならない例を書け、ポリシーを読み込むときに確かめる。決定は禁止だけで、どの規則にも当たらなければそのまま実行する。プログラムごとの知識（git のグローバルオプションなど）は kakoi 本体に持たず、規則の側に書き、git の分は同梱プロファイルに例として入れる。別名を作る操作（`-c alias.*`、`GIT_CONFIG_*` の環境変数）を禁じる規則も同梱プロファイルに入れる。
  - why: 前例（Codex の execpolicy、Claude Code の権限規則、sudoers）では、1 本の文字列への正規表現は語をまたいで当たって壊れやすく、先頭一致はグローバルオプションと別名で見逃す。git での実測でも、すり抜けの主な経路はこの 2 つだった。見張り役はシェルが展開した後の実際の引数を受け取るので、シェルの文字列を分解する必要は無い。隔離の中には承認する人がいないので、確認を求める決定は作らない。ツールごとの対応を本体に持たない方針による。
  - rejected: 引数をつないだ 1 本の文字列に正規表現を当てる。引数のどこかに語があれば禁じる（`git commit -m "push fix"` を誤って止める）。
  - decided_by: 利用者（推奨を採用）
- A5 書ける場所に置いた・作ったプログラムの実行を止める仕組みは作らない。
  - why: 実測では、ネイティブのプログラムの起動を止めるには Landlock、マウントの noexec、seccomp による memfd_create の拒否を重ねる必要があり、それでもインタプリタに読ませる形（`python3 x.py`、`sh x`）と匿名メモリの実行は止まらない。隔離の中の python でできることは、落としたプログラムでできることとほぼ同じで、ファイルと通信の範囲は既存の境界で絞られているので、守りはほとんど増えない。作業場所でビルドして動かす普通の開発が壊れ、bwrap の外でマウント名前空間を扱う大きな改修も要る。
  - decided_by: 利用者（推奨を採用）
- A6 指定したプログラムを使わせない境界は、既存の `hide` でそのファイルを隠すことで担い、新しい仕組みは作らない。文書と同梱プロファイルの例で案内し、守るべきものがプログラムではなく資源（たとえば docker のソケット）である場合はそちらを隠すよう強調する。
  - why: 実測では、ファイルを読めなくすると動的リンカ経由でも起動できない。Landlock の実行の禁止だけでは動的リンカ経由で起動できた。プログラムを隠しても、資源を直接使われれば守れない。
  - decided_by: 利用者（推奨を採用）
- A7 ガードレールは、隔離の中のプログラムが実行ファイルを PATH で探して起動する限り、スクリプトの中から起動されたもの（python の `subprocess.run(["git", "push"])` など）も見張る。絶対パスでの起動と、プログラムを起動せずに同じ操作をするライブラリ（python の git 実装など）は見張れないことを、ガードレールの限界として文書に示す。
  - why: 利用者の懸念（python から `git push --no-verify` をされると検知できない）に対し、PATH で探す起動は見張り役を通るので検知でき、見張れないのは絶対パスとライブラリの実装である。
  - decided_by: LLM（事実の整理。利用者の懸念への回答）

- A8 ガードレールは絶対パスでの起動も見張る。隔離の中で、規則に書いたプログラムの本物の場所（PATH で見つけた実体）に見張り役を重ね、本物は kakoi が決めた別の場所に置き直す。置き直した場所を見つけて直接起動されることは、ガードレールの限界として受け入れる。
  - why: 絶対パスで書かれたスクリプトやうっかりした絶対パスの起動は、現実によくある経路である。
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A26](#A26)
- A9 ガードレールの規則はポリシーの段をまたいで足し合わせ、上の段で下の段の規則を消すことはできない。
  - why: "network.allow" と同じ扱いで、kakoi 全体の「削除の演算子は無い」方針に合わせる。
  - decided_by: 利用者（推奨を採用）
- A10 禁止に当たった見張り役は、標準エラーに `kakoi: guard: <プログラム名> <当たった語の並び>: <reason>` を 1 行出し、終了コード 126 で終わる。隔離の外の利用者にも kakoi の通知として出す。
  - why: 126 はシェルでコマンドを実行できなかったときの番号で、呼んだ側が失敗と分かる。
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A12](#A12)
- A11 LLM による判定（利用者の ba-toys の guardrail）は最初の版に含めない。規則だけの版を作って使ってから、別の壁打ちで決める。
  - why: 隔離の中から判定を呼ぶと API キーを隔離の中に置くことになり、LLM が読める。安全にするには判定を隔離の外で行う仕組みが要り、設計が一段大きくなる。
  - decided_by: 利用者（推奨を採用）

- A12 禁止に当たったことは、見張り役の標準エラーの 1 行（A10 の形）と終了コード 126 だけで伝え、隔離の外への通知は作らない。
  - why: host と none では kakoi が bwrap に置き換わり、隔離の外に通知を受け取る kakoi がいない。利用者の端末へ書ける通り道を隔離の中に渡すと、LLM がそこへ任意の文字列を書ける新しい穴になる。隔離の外へ伝える仕組みは、判定を隔離の外で行う仕組み（A11）と合わせて考える。
  - rejected: 隔離の外の利用者にも kakoi の通知として出す（A10 の一部）。
  - decided_by: 利用者（推奨を採用）
- A13 規則に書いたプログラムが起動のときに PATH に見つからなければ、理由を付けて飛ばし、見張り役を置かない。規則の形と例の検証は行う。
  - why: 存在しないパスのマウント項目を理由付きで飛ばすのと同じ扱いで、プログラムが無い環境では守るものが無い。
  - decided_by: 利用者（推奨を採用）
- A14 同梱プロファイルには有効な規則を入れず、git の例（push の禁止、グローバルオプションの宣言、別名を作る操作の禁止）をコメントにした見本として入れる。
  - why: 有効な規則を同梱すると、上の段から消せない（A9）ため利用者が外せない。push を禁じたいかは利用者による。
  - decided_by: 利用者（推奨を採用）
- A15 `--print-plan` は、合成した後の規則とそれぞれの出所、見張り役を置いたプログラムとその場所（PATH 側と本物の置き場所）、飛ばしたプログラムと理由を示す。JSON にはキーを足すだけで、`format_version` は 1 のままとする。
  - why: 計画表示で合成の結果と適用の結果を確かめられるようにする。キーの追加は版を上げない約束である。
  - decided_by: 利用者（推奨を採用）

- A16 規則は `[[commands.guard]]` に書き、`program`（PATH で探す名前、`/` を含まない）、`options-with-value`、`deny`（先頭一致の語の並びの一覧、位置ごとに代替を並べられる）、`deny-flags`（位置を問わないフラグ）、`deny-env`（この名前の環境変数があれば禁止、ワイルドカード可）、`reason`（必須）、`examples.deny` と `examples.allow` を持つ。`deny`、`deny-flags`、`deny-env` のどれかに当たれば禁止で、3 つとも無い規則は形の誤りとする。
  - why: 別名の迂回（`GIT_CONFIG_*`）を環境変数でも塞げるようにする。理由に代わりの手段を書かせるのは Codex の慣習に倣う。
  - decided_by: 利用者（推奨を採用）
- A17 語の照合は語全体との一致とする。普通の文字列は完全一致、`/.../` で囲んだ文字列は語全体に当てる正規表現とする。
  - why: 大半は完全一致で足り、語の一部に当たる事故（sudoers の失敗例）を防ぐ。
  - decided_by: 利用者（推奨を採用）
- A18 `deny-flags` は `--` より前の語だけを見る。`--force=yes` のように `=` の付いた形も `--force` として当て、1 文字のオプションはまとめ書き（`-fq`）の中の文字にも当てる。
  - why: `--` の後はファイル名などで、`git log -- --force` を誤って止めない。まとめ書きの扱いは Codex の強制削除の検出に倣う。
  - decided_by: 利用者（推奨を採用）
- A19 `hide` で隠したプログラムに規則があれば、隠す方が勝ち、A13 と同じく見つからなかったとして飛ばし、見張り役を置かない。
  - why: 境界はガードレールより強い。
  - decided_by: 利用者（推奨を採用）
- A20 kakoi に直接渡したコマンドも、隔離の中で起動される以上、見張り役を通る（A8 の重ね方による）。例外を作らない。
  - why: 例外が無い方が分かりやすい。
  - decided_by: 利用者（推奨を採用）

- A21 `deny` の先頭一致の前に、プログラム名の直後から `-` で始まる語を読み飛ばす。`options-with-value` に宣言したものは次の語も値として読み飛ばし、`=` の付いた形はその 1 語で済ませ、宣言していないものは値を取らないものとして読み飛ばす。`--` が来たらそこで読み飛ばしをやめる。
  - why: `git --no-pager -C . push` を `push` から照合できる。
  - decided_by: 利用者（推奨を採用）
- A22 `examples` の例は、シェルと同じ引用の規則で語に分ける文字列で書く。先頭の語がその規則の `program` と異なれば形の誤りとする。
  - why: 例を普段のコマンドの形で書ける。
  - decided_by: 利用者（推奨を採用）
- A23 例の検証に失敗した規則、壊れた正規表現、形の誤りは、ポリシーの読み込みの誤りとして種類 `policy`、終了コード 125 で起動を止め、`--print-plan` でも同じ診断で止まる。説明にはどの規則のどの例が期待と違ったかを含める。
  - why: 規則が思ったとおりに当たらないまま動くのが最も悪い。
  - decided_by: 利用者（推奨を採用）

- A24 規則に `deny-option-values` を足し、オプションの名前ごとに、禁じる値を語の照合（A17 の完全一致か正規表現）で書けるようにする。読み飛ばすオプションの値にも当てる。
  - why: 別名を作る `git -c alias.p=push p` の `-c` は読み飛ばしで値ごと飛ばされ、`deny-flags` で `-c` を禁じると無害な `-c` まで止まる。値に当てれば `alias.` で始まる値だけを止められる。
  - decided_by: 利用者（推奨を採用）
- A25 設定ファイルに書かれた別名（隔離の中から書ける `.git/config` の `[alias]` など）は仕組みで塞がず、ガードレールの限界として公開文書に書く。
  - why: 塞ぐには見張り役が git の設定を読んで別名を展開する必要があり、git に固有の知識を本体に持たない方針に反する。本当に止めるには権限の狭いトークンや filtered の通信の許可を使う（A1）。`.git/config` を守らないことは既存の既知の隙間である。
  - decided_by: 利用者（推奨を採用）

- A26 本物の場所に見張り役を重ねて本物を置き直すのは、規則ごとの任意（`guard-absolute-path = true`、既定は無効）とする。既定では PATH の先頭の見張り役の場所にだけ置く。見張り役は本物を exec で置き換えて起動し、受け取った argv[0] をそのまま渡す。
  - why: 置き直すとプログラムから見た自分の場所が変わり、自分の場所から資源を探すプログラム（python の標準ライブラリなど）が壊れうる。git のように自分の場所に依存しないものだけ、利用者が絶対パスの起動も見張れるようにする。
  - decided_by: 利用者（推奨を採用）
- A27 kakoi は、起動された実行ファイルの場所（`/proc/self/exe`）が、自分で作った見張り役の場所とプログラムの対応表に載っていれば見張り役として動く。この判定は入れ子の判定と引数の解析より前に行い、見張り役は入れ子の警告を出さない。同じ本物を複数の名前が指すときは、それらすべての規則を当てる。
  - why: 見張り役は kakoi 自身で、隔離の中には KAKOI=1 があるので、見分けないと入れ子の kakoi として動き、`git --version` が kakoi の版を返す事故が起きる。
  - decided_by: 利用者（推奨を採用）
- A28 本物は、隔離へ渡す PATH（path-prepend を足した後、見張り役の場所を除く）で探す。見張り役の場所は PATH の最も先頭、path-prepend より前に置く。隔離へ渡す環境に PATH が無ければ PATH を作らず、見張り役を置けなかったことを計画表示に示す。
  - why: `kakoi -- git` が path-prepend の中の git に解決される場合と同じものを見張る。
  - decided_by: 利用者（推奨を採用）
- A29 見張り役、置き直した本物、規則は kakoi 専用の tmpfs の中に置き、利用者のマウントより後、最後に重ねる。本物が rw や rw-copy の中にあっても見張り役が勝つ。host、none、filtered のすべてで同じにする。
  - why: ホストに残骸を残さず、利用者のマウントで見張り役が消えないようにする。
  - decided_by: 利用者（推奨を採用）
- A30 例の先頭に `NAME=value` の語があれば、それを環境として読み、例の検証の環境はその語だけとする（ホストの環境は使わない）。
  - why: deny-env を使う規則も例で確かめられ、実行する環境で結果が変わらない。
  - decided_by: 利用者（推奨を採用）
- A31 同梱の見本は `GIT_CONFIG_*` の環境変数を禁じず、`-c` と `--config-env` の値で別名を作ることだけを禁じる。環境変数で作った別名は見張れないものとして案内する。
  - why: `git.instead-of` を使うと kakoi 自身が `GIT_CONFIG_*` を環境に入れるので、禁じると git のすべての起動が止まる。kakoi が入れた変数だけを見逃す仕組みは複雑で、同じ名前で上書きされれば意味が無い。
  - decided_by: 利用者（推奨を採用）
- A32 例の検証はポリシーの読み込みと合成の段階で行う。本物を探すことと hide で隠されるかの判定はマウントの解決の後に行い、見張り役を置けないとき（本物が通常ファイルでない、など）は止めずに理由を付けて飛ばす。
  - why: 例の検証はポリシーだけで決まり、本物と隠し方はマウントの解決が要る。置けないことは A13 と同じく飛ばす。
  - decided_by: 利用者（推奨を採用）

- A33 規則に任意の `for`（deny の 1 項目と同じ書き方）を書け、書いた規則の deny-flags、deny-option-values、deny-env は、先頭の語の並びが `for` に当たる起動にだけ当てる。

- A35 IR の敵対的レビューの判断の要らない指摘を次のとおり決める。固定キーの一覧と合成の表に `commands.guard` を足し、段をまたいで連結する。正規表現を使えるのは deny と for の語と deny-option-values の値だけで、方言は Rust の regex クレートの構文とする。`=` を含む語は最初の `=` で分ける。deny-env の名前の型は REQ-155 のワイルドカードに従う。空の一覧、空の項目、空の program、program が "kakoi" の規則は形の誤りとする。禁止の出力に出す当たった語は引数の側の語で、REQ-289 のとおり制御文字を逃がし、照合は deny-env、deny、deny-flags、deny-option-values の順で最初に当たったものを出す。UTF-8 でない語はどの語の照合にも当たらない。探した本物が kakoi 自身の実行ファイルなら見張り役を置かずに理由を付けて飛ばす。診断の定義を、見張り役の禁止の 1 行を含むように広げる。JSON は `guards`（置いたプログラムごとの program、見張り役の場所、置き直した本物の場所、当てる規則の出所）と `skipped_guards`（program と理由）を足す。見張れないものの案内に、重ねた場所以外の別名やハードリンクからの起動、長いオプションの省略形を足す。
  - why: どれも仕様の曖昧さや既存の要求との食い違いを埋めるもので、選び方で守りの強さが変わらないか、既存の方針に従う。UTF-8 でない語を当てないのは、ガードレールとして見逃す方向で、誤って止めるより害が小さい。
  - decided_by: LLM（利用者の委任）

- A36 規則の型、読み込み、段の合成、語の照合、例の検証、見張り役を置く計画と計画表示は kakoi-core に置き、見張り役として起動されたときの処理（場所の対応を読む、引数と環境を受け取る、禁止の 1 行を出す、本物を exec する）は kakoi の実行ファイルに置く。新しいクレートは作らない。
  - why: kakoi-core は引数の解釈、環境変数の読み取り、標準エラーへの書き込み、コマンドの実行をしない（REQ-150）。判断を kakoi-core に置き実行時の操作を外に置くのは kakoi-net の先例（REQ-391）に合う。例の検証と見張り役が同じ照合を使うので、例と実際の結果がずれない。見張り役の実行時の処理は小さく、見張り役は kakoi 自身の実行ファイル（A3）なので実行ファイルに入る。照合を kakoi の外（Claude Code のフックや ba-toys）でも使いたくなったら、入出力の無い照合だけを別のクレートに切り出す。
  - rejected: 見張り役の機能を新しいクレート（kakoi-command）として作る。
  - decided_by: 利用者（推奨を採用）

- A37 照合で根拠の足りなかった細部を次のとおり決める。規則の知らないキーは形の誤りとし、"reason" は空でない文字列とする。"--" の語は読み飛ばしを終えるときにそれ自体も読み飛ばす。"deny-option-values" も "deny-flags" と同じく最初の "--" より前の語にだけ当てる。見張り役は禁止のとき標準出力に何も出さない。禁止の 1 行に出す当たった語は、先頭一致なら当たった語の並び、フラグならそのフラグ、オプションの値ならオプションと値、環境変数ならその名前とする。hide で隠されるとは、自動で生成された hide を含め、本物を含む項目のうちマウント順で最後に効くものが hide であることとする。計画表示は、見張り役を置いたプログラムと飛ばしたプログラムを要約と全量の両方に、合成した規則と出所を全量だけに示す。見張れないものにシェルの組み込みのコマンドを含める。公開文書の案内には、"guard-absolute-path" を有効にすると自分の場所から資源を探すプログラムが壊れうること（A26）と、"git.instead-of" と "GIT_CONFIG_*" の禁止を一緒に使えないこと（A31）も含める。同梱の見本は理由と当たるべき例と当たってはならない例を持つ。
  - why: 仕様の照合で、決定から導けない細部として見つかった。知らないキーを誤りとするのは既存の固定キーの扱い（REQ-151）に合わせる。"--" を読み飛ばすのは、"--" の後を語として照合するため。標準出力に出さないのは既存の診断（REQ-290）に合わせる。hide の判定はマウントの最後に効くものの考え方（REQ-173）に合わせる。見本に理由と例を入れるのは、規則の必須の形（A16）と例の検証（A4）を見本でも示すため。
  - decided_by: LLM（利用者の委任）

- A38 見張り役を置く本物は、隔離の中でシェルがその名前で起動するものとする。隔離へ渡す PATH（path-prepend を足した後で、見張り役の場所を除く）の項目の順に同じ名前を見て、その名前の場所がマウントの hide で隠されず、リンクを解決した先が実行できる通常ファイルである最初のものを本物とする。ディレクトリ、行き先の無いリンク、実行できない通常ファイル、隠された場所の名前は飛ばして先を探す。A32 の例のうち「本物が通常ファイルでない」ときに飛ばすことは取り下げる（そういう名前は飛ばして先を探す）。kakoi に直接渡したコマンドが見張り役を通るかも、同じ探し方で決める。
  - why: 通常ファイルでない名前や実行できない名前で探すのを止めると、シェルと execvp はそれを飛ばして後ろの本物を起動するので、その本物が見張られない。実行できない同名ファイルの後ろの本物で、禁止でない起動まで 126 になる失敗も、実際のレビューで見つかった。隠された場所の名前は隔離の中では見えないので、シェルと同じく飛ばす。
  - rejected: 最初に見つかった名前で止め、通常ファイルでなければ見張り役を置かずに飛ばす（A32 の例）。見張られない本物が残る。
  - decided_by: 利用者（推奨を採用）
- A39 禁止の 1 行の `<プログラム名>` は、当たった規則の `program` とする。
  - why: 同じ本物を複数の名前が指すとき（REQ-453）、どの規則が当たったかと reason の出所がそのまま分かる。起動した名前は起動した側が知っている。
  - decided_by: 利用者（推奨を採用）
- A40 見張り役が禁止にしなかった起動で本物の exec に失敗したときは、入れ子と同じく種類 command not executable の診断を出して 126 で終わる。
  - why: 見張り役は bwrap がコマンドを起動した後で動くので、bwrap はその失敗を報告できない。入れ子と同じく kakoi が直接 exec するので、同じ種類と終了コードに揃える。

- A41 見張り役、規則、置き直した本物が隔離の中から書き換えられないという保証は、見張り役の場所を通した書き込みについてのものとする。kakoi 自身の実行ファイルが書ける項目の下にあるときは、その項目を通して見張り役の中身が変わることを、見張れないものとして案内する。

- A42 "guard-absolute-path" の置き直しは、計画の時点で解決した実体のパスを bwrap が起動時に解決し直すので、その間に同じ場所へ書ける別の隔離がファイルを差し替えると、隠したファイルが置き直し先に見えうる。これを既知の隙間 15 と同じ種類の見張れないものとして案内し、記述子で渡す作りにはしない。

  - rejected: 実体が隠されたらプログラムごと飛ばし、後ろの本物が見張られないことを見張れないものとして案内する。
