# 修正の多いファイルの品質診断で見つかった仕様の穴

## Context

修正コミットの多い `kakoi-core` のファイルを品質の観点でレビューし、仕様を決めないと直せない指摘が 2 件残った。
1 つは、設定ディレクトリの中に書き込める項目を置けることである。隔離の中から次の起動が読むプロファイルを植えられる。
もう 1 つは、host・none・filtered で kakoi に直接渡したコマンドを探すときに、`hide` で隠された PATH の候補を選び、隔離の中に無いパスを起動しようとして bwrap が失敗することである。
利用者は 2 件とも、レビューの推奨どおりに直すと決めた（2026-09-30）。ここではその細部を決める。

事実（2026-09-30、この環境、kakoi 0.5.0 の main 4c4de3e、一時的な HOME）: 空の `~/.config/kakoi/profile` を作り `kakoi --rw ~/.config/kakoi/profile --print-plan -- true` を実行すると、終了コード 0 で `rw ~/.config/kakoi/profile (command line)` が計画に載った。`--rw ~/.config/kakoi` は種類 path の診断で止まった。
事実（同上）: `PATH=<一時ディレクトリ>/a/bin:/usr/bin` で `<一時ディレクトリ>/a/bin/true` を置き（既定で `/tmp` は隠される）、`kakoi -- true` を実行すると、`bwrap: execvp ...: No such file or directory` で終了コード 1 になった。`kakoi -- sh -c true` は 0 で、隔離の中のシェルは `/usr/bin/true` を起動した。
事実: 共有ファイルの置き場には、中に書き込める項目があれば止まる規則がすでにある（[REQ-462](../../ir/core/core-nested-isolation.md#REQ-462)）。見張り役の本物は、場所か実体が隠される名前を飛ばして探す（[REQ-446](../../ir/core/core-command-guard-runtime.md#REQ-446)）。listed のコマンドの探索も、見えていない候補を飛ばす（[REQ-484](../../ir/core/core-listed-mounts.md#REQ-484)）。
事実: 見本のプロファイルとガイドに、設定ディレクトリの下を "rw" にする例は無い。
事実: [REQ-264](../../ir/core/core-command-resolution.md#REQ-264) は、`hide` の下で見つかったコマンドが後に bwrap の exec で失敗することを許容すると定めていた。A2 はこれを改める。

Position: 照合を 2 回行い、2 回目で指摘 0 件になった。敵対的レビューは行わない（変えた要求は REQ-260 と REQ-264 の組と独立した REQ-486 で、既存の REQ-446・REQ-484 と同じ判定を指すだけのため）。承認待ち。

## Agreements

- A1 合成後の "rw" または "rw-file" の項目が設定ディレクトリの中にあれば、種類 "path" の診断で終わる。
  - why: 隔離の中から次の起動が読むプロファイルや秘密ファイルを植え付け、書き換えられる。REQ-158 は「隔離の中から設定ディレクトリを作ってプロファイルを植えられないため」と目的を述べるのに、祖先の側しか縛っていなかった。
  - decided_by: 利用者（推奨を採用）
- A2 host、none、filtered でも、kakoi に直接渡したコマンドを PATH で探すときは、場所か実体が `hide` で隠される候補を飛ばす。
  - why: 隠された候補を選ぶと、隔離の中に無いパスを起動しようとして bwrap が失敗する。隔離の中のシェルと見張り役の本物選びはその候補を飛ばしており、同じ名前で起動されるものが食い違う。
  - decided_by: 利用者（推奨を採用）
- A3 A1 の「設定ディレクトリの中」は、"rw" または "rw-file" の項目の実体が設定ディレクトリの実体と同じか、その子孫であることを指す。リンクを経由して設定ディレクトリの中に着く項目も含み、`profile` や `secrets` のような中のディレクトリも含む。"rw-copy" と "ro" の項目は対象にしない。
  - why: 書いたパスで判定すると、リンクを通して中に着く "rw" を見逃す。"rw-copy" の中への書き込みはホストに届かないので、REQ-158 も保護の対象から外している。共有ファイルの置き場の規則（REQ-462）と同じ形になる。
  - decided_by: 利用者（推奨を採用）
- A4 A1 の診断は種類 "path"、終了コードは 125 とし、計画表示でも行う。説明には、その項目の指令とパス、設定ディレクトリのパス、隔離の中から次の起動が読むプロファイルを書き換えられるという理由を含める。保護対象の診断の順（REQ-295）では、設定ディレクトリの今の検査（その前置きと解決が参照するもの）のすぐ後に置く。
  - why: ほかの配置保護の診断と同じ種類と終了コードにそろえる。今の検査の後に置けば、設定ディレクトリ自身が書き込める項目の中にあるときは今までどおりの診断が先に出る。
  - decided_by: 利用者（推奨を採用）
- A5 A2 の「`hide` で隠される」は、見張り役の本物選び（REQ-446）と同じく、その名前の場所か、リンクを解決した実体について、それを含む項目のうちマウント順で最後に効くもの（自動で生成された "hide" を含む）が "hide" であることを指す。マウントのモードが "listed" のときは、これに加えて今までどおり見えていない候補も飛ばす（REQ-484）。すべての候補を飛ばして何も残らなければ、名前を説明とする command not found で 127 とする。
  - why: 同じ名前で起動されるものの決め方を、kakoi に直接渡したコマンド、隔離の中のシェル、見張り役の本物選びでそろえる。
  - decided_by: 利用者（推奨を採用）
- A6 COMMAND に "/" があるときも、そのパスの場所か実体が A5 の意味で隠されるとき、またはマウントのモードが "listed" でそれが隔離の中に見えていないときは、見つからないものとして、名前を説明とする command not found で 127 とする。すべてのモードで同じにする。
  - why: 隔離の中に無いパスを bwrap に渡すと、bwrap の exec の失敗として分かりにくく終わる。PATH で探したときと同じ結果にそろう。
  - decided_by: 利用者（推奨を採用）
- A7 REQ-486 は、行数と要求数の注意（too_many_lines、too_many_requirements）が出ても core-policy-placement.md に置き、文書を分けない。
  - why: 文書の要求はどれも「隔離の中からの書き換えで、起動時のパスの解決や次の起動が読むものを変えられないこと」という一つの責務に属し、範囲の行で説明できないものは混じっていない。件数や行数だけで分けないという既存の決定（[2026-09-16 の A5](./2026-09-16-kakoi-spec-readability.md#A5)）にそろえる。
  - decided_by: LLM（kotowari check の注意を読み直した結果）

## Revisions

- [REQ-264](../../ir/core/core-command-resolution.md#REQ-264) が許容していた「`hide` の下で見つかったコマンドが後に bwrap の exec で失敗すること」を、A2、A5、A6 で改めた。PATH の要素が "rw" の項目の中にあるかを検査しないことは変えない。
