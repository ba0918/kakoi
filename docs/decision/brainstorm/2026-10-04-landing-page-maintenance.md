# LPの保守性と言語選択

## Context

LPの日英文言がHTMLとJavaScriptに分散し、CSSの調整が末尾に重なっている。
ビルドはPages workflow内だけにあり、ローカルで同じ確認を再現しにくい。
TOPと各LPが同一originで公開されるため、利用者の明示的な言語選択を引き継げる。
製品説明・見た目・導線を維持する範囲で、利用者が保守性整理と言語選択の共通化を承認した。

## Agreements

- A1 有効な共通キー "ba0918-language" の "en" または "ja" を最優先し、共通値が無効または存在しなければ当該LPの旧キー "kakoi-lp-language" の有効値を読み、それもなければ英語を表示する。保存するのは明示切替時だけとし、旧値の自動昇格や旧キー同士の新旧推測をしない。保存拒否時もページ内切替を動作させ、選択の引継ぎは次の遷移または再読込で行う。
  - why: 同じoriginのTOPとLPで明示選択を引き継ぎながら、旧kakoiが初期表示で保存した英語を利用者の明示選択と誤認しないため。
  - decided_by: 利用者が承認した共通言語契約。
- A2 kakoiの文言を日英の辞書へ集約し、Jinja2テンプレート・CSS・言語処理を分離する。Cargo.toml由来の版表示と対象commitの識別を維持し、ローカルとPagesで同じbuild/checkを使用する。CSS末尾の上書きは既存ルールへ統合し、本文・導線・表示を維持する。
  - why: 翻訳の変更箇所とCSSの最終値を追いやすくし、公開前に同じビルドと必要な検証を実行できるようにするため。
  - decided_by: 利用者の承認範囲内で実装者がコードを確認して選択した構成。

## Prohibitions

- P1 今回の変更では製品本体と無関係なCIの修理を行わず、push・PR・公開は別の指示まで行わない。
  - why: 同時開発中の変更と分離し、利用者が最終差分を公開前に確認するため。
  - decided_by: 利用者。
