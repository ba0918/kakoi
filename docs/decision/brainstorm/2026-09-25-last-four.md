# テストで確かめられない最後の 4 件の扱い

## Context

kotowari check を commit と push で強制し、push は誤り 0 件を求める。
後回しの宣言と仕様どおりのテストの追加で、誤りは 4 件まで減った。EX-533（rw-copy の複製の性質の表示）、EX-271（通信層の再送を数えない）、FLAG-007 の 2 つのテスト（星の多いパターンの照合時間、UTF-8 でないマウント名）である。
どれも、仕様が観測できる形で書かれていないか、テストが仕様に無い細部を確かめているため、テストの印だけでは片付かない。
利用者は、現実に起こり得るか、どんな実害が出るかで判断し、根拠があれば LLM が決めてよいと委任している。

Position: 第 1 ラウンドで 4 件とも決めた。IR に反映する。

## Agreements

- A1 REQ-297 から「rw-copy がホストの内容で始まり、書き込みがホストに出ず、終了時に消える」という説明の句を切り出し、要約と全量の両方にこの 3 点の説明を載せることをレビューで確かめる要求にする。EX-533 は、全量計画が複製できなかった項目のパスを示すことだけを確かめる例に直す（理由の表示は REQ-297 の本文に残るが、文面が契約でないので例では確かめない）。
  - why: 説明が抜けると、利用者が rw-copy での書き込みがホストに残らないことを知らずにデータを失う実害が現実にあり得る。一方で説明の文面は契約ではなく、機械で確かめると言い回しを固定する。
  - decided_by: 利用者（推奨を採用）
- A2 REQ-122 の「通信層のパケット再送は数えない」という句は本文に残し、それを確かめる例 EX-271 は消す。
  - why: DNS を UDP で送るときの再送は kakoi-net 自身のもので、数える側に入る。TCP と TLS の再送はカーネルが行い kakoi-net からは見えないので、数えてしまう状況は作りとして起こり得ず、例を確かめるテストは条件を作る者がいない。
  - decided_by: 利用者（推奨を採用）
- A3 星の多いパターンの照合時間を要求にしない。`tests/mounts.rs` の a_name_the_isolation_planted_cannot_stall_a_pattern_with_many_stars から時間の上限を外し、照合の意味（`*a*a*a*a*a*b` は a だけの 255 バイトの名前に一致しない）だけを確かめて REQ-155 の印を付ける。
  - why: 隔離の中のプログラムが操れるのは名前だけで、パターンは利用者がポリシーに書く。照合が遅くなるのは星の多いパターンのときだけで、普通のパターンでは現実に起きない。時間に依存するテストは安定しないので、よほどの理由がない限り採らない。
  - decided_by: 利用者（推奨を採用。時間に依存するテストを避ける方針は利用者の指示）
- A4 マウント一覧のパスはバイト列として扱い、UTF-8 でない名前の項目も落とさないことを要求にし、`tests/mounts.rs` の a_mount_point_with_a_byte_that_is_not_utf8_does_not_empty_the_mount_list にその印を付ける。
  - why: UTF-8 でない名前のマウントはまれだが現実にあり得る（FUSE や利用者が作ったマウント）。黙って落とすと "mounts.hide-mounts" で隠すはずのマウントが隠れないまま起動し、守りが抜ける。振る舞いもテストも既にある。
  - decided_by: 利用者（推奨を採用）
- A5 FLAG-007 は A3 と A4 で解消したので消す。
  - why: 2 つのテストはどちらも、仕様の範囲だけを確かめる形か、仕様に足した要求を確かめる形になった。
  - decided_by: 利用者（推奨を採用）
