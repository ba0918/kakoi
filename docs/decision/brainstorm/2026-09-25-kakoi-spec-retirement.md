# 人間向け仕様の廃止とガイドへの移行

## Context

`docs/spec/` の人間向け仕様は、規則が密に詰まり、節番号での相互参照が多く、利用者が「何を指定すると何が起き、何がエラーになるか」を引けなかった。
2026-09-16 の整理（[A1](./2026-09-16-kakoi-spec-readability.md#A1)）で IR を抽出したが、正本は仕様のままにしていたため、同じ契約を二つの文書で保守していた。
IR を根拠にした日本語のリファレンスガイドを `docs/guide/` に書き、仕様を削除する。
ガイドを書く過程で、仕様にだけあって IR に無い規則が見つかった。
それらの扱いもここで決める。

## Agreements

- A1 契約の正本を `docs/ir/` の IR とし、`docs/spec/` の人間向け仕様を削除する。人間向けの読み物は `docs/guide/` のガイドが担い、各節に IR 項目の指紋つきのガイド印を置く。
  - why: 仕様と IR の二重保守をやめ、IR の変更がガイドの見直しとして kotowari に検出されるようにするため
  - rejected: 仕様を読みやすく書き直して正本に残す案。二重保守が続き、仕様と IR の食い違いを機械で検出できない
  - decided_by: the user
- A2 仕様にだけあって IR に無い規則は、今回は IR の要求にせず、仕様の文面ごと `docs/ir/FLAGS.md` に gap として記録する。ガイドは未決事項の付録でそれらを示す。
  - why: 仕様の削除で実装済みの振る舞いの記述を失わないため。要求への昇格は件ごとの承認とテストの対応付けが要るので別の作業にする
  - rejected: 今回すべて要求へ昇格する案。範囲が件ごとの承認とテストの印付けまで広がる
  - decided_by: the user (took the recommendation)
- A3 コード、テスト、IR、決定記録に残る旧仕様の節番号での参照は書き換えず、ガイドの付録に旧節番号とガイドの章の対応表を置いて参照先とする。
  - why: 参照は数百件あり、書き換えは文書整理の範囲を超えて製品コードとテストに及ぶため
  - decided_by: Claude（利用者が任せた削除の後始末の範囲で選んだ）

## Prohibitions

- P1 今回は製品コードとテストの動作を変更しない。
  - why: 文書の移行に製品の変更を紛れ込ませないため。2026-09-16 の P1 と同じ線を引き継ぐ
  - decided_by: Claude（2026-09-16 の P1 を引き継いだ）
