# 0.4.0 のリリース準備

## Context

filtered ネットワークモードを含む変更がそろい、利用者が 0.4.0 として出すと決めた。
IR、ガイド、公開文書、用語集には「0.3 では」と版の番号で範囲を述べる箇所が散らばっていて、版を上げるたびに書き換える必要があり、機械で一致を確かめる仕組みも無い。
filtered の初版を提供する前の条件（ガイド "maintainer/library.md" の 6 つ）を実コードで確かめたことが、実証の記録にまとまっていない。
リリースの前に、この 2 点の扱いを決める。

Position: 利用者が推奨を採用した。反映して承認に出す。

## Agreements

- A1 IR、ガイド、公開文書、用語集で、製品の範囲を版の番号（「0.3 では」「Not in 0.3」など）で述べる箇所は、版の番号を持たない書き方（「今の版では」「Not supported yet」など）に改める。版の番号は "Cargo.toml"、"CHANGELOG.md"、タグ、`--version` の出力と、例として示す箇所にだけ置く。旧仕様の節名や過去の判断を述べる箇所の「0.3」は、そのときの事実として残す。
  - why: 版の番号の写しが複数あると、版を上げるときに書き換え漏れで食い違う。一致を機械で確かめる仕組みも無い。番号を持たなければ次の版から書き換えが要らない。
  - decided_by: 利用者（推奨を採用）
- A2 filtered の初版を提供する前の 6 つの条件について、どのテストと CI のジョブで確かめているかの対応を、実証の記録（"2026-09-16-kakoi-net-evidence.md"）に 1 節として残す。確かめきれない条件があれば、リリースの前に利用者に報告する。
  - why: REQ-392 は提供前に実コードで統合を確かめたことを実証の記録で確かめる要求である。確認は工程 10 の節（2026-09-24）に記録済みだったが、6 つの条件ごとに試験と CI のジョブを対応付けたものは無く、本物の pasta で確かめていない範囲も書かれていなかった。
  - decided_by: 利用者（推奨を採用）
