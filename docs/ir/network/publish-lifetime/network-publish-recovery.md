# 障害復帰時の待受公開

同じ待受が継続している場合の公開番号の選択を定義する草案。同じ待受の継続を確認する具体的な機構は未決。

後続の動的公開の要求。A158/A159により初版の対象から分離した。本文の初版は動的公開の初回提供を指す。初版の固定公開はnetwork/network-initial-release.mdで定義する。

## 要求

### REQ-070: 復帰時の以前の公開ポートの優先

- 種類: event_driven
- 出典: docs/decision/brainstorm/2026-09-15-kakoi-net.md#A75
- 検証: unit

障害復帰時に同じ待受が継続している場合、以前のホスト公開番号が許可範囲内で使用可能なら優先して再利用する。使えなければ既存の選択規則で別の許可済みポートを選び、知らせる。

## 具体例

```gherkin
@id=EX-134 @about=REQ-070 @source=docs/decision/brainstorm/2026-09-15-kakoi-net.md#A75
Scenario: 内側と同じ番号より以前の公開番号を優先する
  Given 隔離環境内の40000番の待受が障害中も継続している
  And 以前はホストの45000番で公開していた
  And ホストの40000番と45000番はともに許可範囲内で使用可能である
  When 障害から復帰して公開を再開する
  Then ホストの45000番を再利用する

@id=EX-135 @about=REQ-070 @source=docs/decision/brainstorm/2026-09-15-kakoi-net.md#A75
Scenario: 以前の番号を使えなければ別の許可済み番号を知らせる
  Given 同じ待受が継続しているが以前のホスト公開番号は別の処理が使用している
  And ホストの許可範囲内に別の空きポートがある
  When 障害から復帰して公開を再開する
  Then 既存の選択規則で別の許可済みポートを選ぶ
  And 実際の公開先を通知する
```
