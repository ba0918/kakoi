## Requirements

### REQ-167: 五つの指令と複製の生成
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

指令と対象と隔離内の見え方：表 TBL-153 に従う。"rw" にディレクトリ以外を指定したら、種類 "path" の診断で終わり、"rw-file" を案内する。"rw-file" にディレクトリを指定した場合も種類 "path" の診断で終わる。"rw-copy" にディレクトリでも通常ファイルでもないもの（ソケット、FIFO、デバイスファイル）を指定した場合も種類 "path" の診断で終わり、"rw-file" を案内する。

複製する内容を持たないためである。この 3 つのうち "rw-copy" の判定だけは、下の複製の読み込みで開いた記述子の上で行うので、第 13 節の段階 7 の最後に出る（名前で見てから開くまでの間に実体を差し替えられるため。第 14 節と同じ規律）。隔離の中のファイルシステム全体は、ポリシーに書かれていない範囲を読み取り専用で見せる。

"/dev" と"/proc" は隔離用のものを用意する。読み取り専用で見えている範囲にあるホストの UNIX ソケットには接続できる。それを止めるには "hide" を使う。"rw-copy" は、"ro"（ホストの内容で始まり、書けない）と "hide"（空で始まり、ホストは不変）のどちらでも表せない要求のためにある。

隔離の中の道具に自分の設定ファイルを書き換えさせたいが、その結果をホストに残したくない、という形である。3 つの違いは次のとおり。表 TBL-154 に従う。"rw-copy" の複製。 "rw-copy" の項目は、隔離の中にだけ存在する複製を用意して実体の上に重ねる。ホストの実体は読むだけで、書き換えない。

実体がディレクトリのとき: その実体に tmpfs を重ね、起動時にホストの実体の下にある木を流し込む。  流し込むのは、通常ファイル（内容とモード）、ディレクトリ（モード）、シンボリックリンク（辿らず、  同じ先の文字列でリンクとして作り直す）の 3 種類で、ディレクトリはその下のエントリより先に作る。  空のディレクトリも作る。同じディレクトリの中はエントリ名のバイト順に見る。同じ木からは同じ並びの  引数が得られる（第 1 節の決定性）。

実体が通常ファイルのとき: その内容の複製を作り、実体の上に読み書きできる形で重ねる。複製の中身は隔離のマウント名前空間の中にしか無く、名前空間と一緒に消える。ホストのファイルシステムに複製の実体は残らない（第 14 節）。第 6.4 節の順序では、tmpfs とそれを埋める引数はその項目の位置にまとめて置かれるので、"rw-copy" の中に着地する狭い項目は複製が出来上がった後に乗る。

モードは複製元のものを引き継ぐ（実行ビットを含む。set-user-ID、set-group-ID、sticky も写すが、tmpfs は "nosuid" なので効かない）。所有者、時刻、ハードリンクの共有は引き継がない。

### REQ-168: 複製の改名・上限・読み取り失敗
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

改名と削除ができるかは 2 つの形で異なる。ディレクトリの複製の中のエントリは tmpfs の中の普通のファイルなので、改名も削除も一時ファイルからの置き換え（rename）もできる。通常ファイルの複製は実体の上に重ねた 1 つのマウント点なので、"rw-file" と同じく、その場での書き込みはできるが、rename での置き換えと削除は失敗する（2026-09-10 に bwrap 0.9.0 で実測）。

置き換えを行う道具に設定ファイルを書かせるなら、そのファイルではなく親ディレクトリを "rw-copy" にする。シンボリックリンクを辿らないのは、辿ると複製が木の外へ広がり、循環もありうるためである。隔離の中ではリンクは他のパスと同じに解決され、複製の外を指すリンクは、ポリシーがその先に与えたもの（既定では読み取り専用）に届く。

これは隔離の中のどこからでもできることで、"rw-copy" が新しく与える経路ではない。複製の上限と失敗。 1 つの項目が持てるのは、エントリ 4096 個までと、通常ファイルの内容の合計64 MiB までである。どちらかを超えたら種類 "path" の診断で終わる。内容は記述子と隔離の tmpfs に二重に載るので、大きすぎる複製元を指した指定は読み込まずに止める。

診断の説明は、その項目のパス、超えた上限、"ro" を使う案内を含む。複製元が読めない（ディレクトリのエントリを列挙できない、通常ファイルを開けないか読めない、シンボリックリンクの先を読めない）ときは、種類 "path" の診断で終わる。この指令はホストの内容で始まることを約束するので、それより少ない内容で黙って始めない。

診断の説明は、その項目のパス、読めなかったエントリのパス、理由を含む。複製元のエントリが、通常ファイルでもディレクトリでもシンボリックリンクでもない（ソケット、FIFO、デバイスファイル）ときは、そのエントリを複製に作らず、計画に理由付きで表示して起動を続ける（第 13 節）。これらは読めない失敗ではなく、複製に意味の無い種別である（ソケットはホストのそれ自身であって、複製はそれではない）。

作らないことで隔離の中から見えなくなるだけなので、新しく露出するものは無い。黙って飛ばさないことだけを求める。複製元の実体が存在しない項目は、第 6.2 節どおり飛ばす（空で始めない）。

### REQ-169: 存在しないマウント項目の飛ばし
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

すべての指令は、シンボリックリンクを解決した実体のパスにマウントする。実体が存在しない項目は飛ばす。飛ばした項目は計画に「飛ばした」と理由付きで表示する。起動のたびの警告は出さない。この規則は"rw-copy" にも例外なく効く。複製元が無いときに空の複製で始めることはしない。存在しないパスに何かを用意すれば、下の理由でホストに実体が残る。

存在しないパスにマウントしない理由: bwrap はマウント先を作ろうとし、書ける領域では 0 バイトの実ファイルがホストに残る（2026-09-03 に実測）。帰結として、起動後に現れたファイルは隠れない。これは README に既知の隙間として書く。

### REQ-170: 走査・マウント・秘密からの hide 生成
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

ポリシーに書かれた項目に加えて、次の項目が生成の段に置かれる。

走査（"mounts.scan"）: "root" 以下を探索し、"names" のいずれかに一致する名前のエントリのうち、  ディレクトリと、解決先がディレクトリのシンボリックリンクを除いたものを "hide" にする。"exclude" に  一致する名前は対象外。読み込んだポリシーファイルは対象外。

"prune" に一致する名前のディレクトリは  中に入らない。シンボリックリンクのディレクトリには入らない。一致したエントリがシンボリックリンク  なら、第 6.2 節のとおり解決先を隠す。ただし、その解決先が、書かれた段に第 5.4 節の置き換えを適用した  後に残っている "ro" の項目の実体と同一かその中（子孫）なら、隠さない。

その "ro" の解決が書き込める  項目の中を参照しない（隔離の中から差し替えられない）なら、隠さずに計画に理由付きで表示して起動を  続ける。参照する（差し替えられうる）なら、種類 "path" の診断で終わる。この判定の書き込める項目は、  走査の "root" の検査と同じく、書かれた段だけに第 5.4 節の置き換えを適用した集合で見る。

該当する  リンクが複数あれば、リンクのパスのバイト順で最初のものを名指す（走査の探索順に依らない）。説明はそのリンクのパス、  "ro" の項目のパス、理由を含む。隔離の中で ".env" の名前のリンクを張って、読み取り専用にした自分の  設定や指示を次の起動で空にする経路（2026-09-06 に実測）と、"ro" のリンクを向け直して走査が隠すべき  ファイルの隠しを外す経路の両方を、診断で見える形で塞ぐためである。

解決先がディレクトリのリンクは  元から対象外。"names"、"exclude"、"prune" はシェルのワイルドカード  （"*"、"?"。意味は第 5.3 節）を使える。走査で隠したファイルが git に追跡されていると、隔離の中の  git には空になった変更として見える。

マウント種別による隠蔽（"mounts.hide-mounts"）: "under" 以下にあるマウントのうち、ファイル  システム種別が "fstype" のいずれかであるものを、そのマウント先ごとに "hide" にする。マウント先が  ワークスペース、ワークツリー、"${git_common_dir}" の実体と同一なら生成しない。

利用者が選んだ  作業場所そのものを隠さないためである。マウント一覧（第 14 節）は "under" が値を持つ "hide-mounts" が  1 つでもあるときだけ読み（"under" が値を持たない項目は第 5.2 節どおり飛ばし、隠すものが無いので  一覧も要らない）、読めなければ種類 "path" の診断で終わる。

隠すべきマウントを隠さずに起動しない  ためである（別のサンドボックスの中等 "/proc" が制限された環境からの起動で起きうる）。

秘密ファイル: "secrets" に書かれたファイルのうち存在するものを "hide" にする（第 9 節）。

設定ディレクトリの "secrets/": 存在すれば "hide" にする。参照されていない秘密ファイルを隔離の中から  読めなくするため。走査が一致したエントリを隠す先が "rw-copy" の項目の中であっても、上の "ro" のような別扱いはしない。隠すのは複製の中身であってホストのファイルではなく、隠さなければ複製に載った ".env" の中身が隔離の中で読めてしまうためである。第 6.4 節の順序で "hide" は複製が出来上がった後に乗る。

### REQ-171: 生成の優先順位と検査対象の確定
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

生成された項目には第 5.4 節の同一性判定を同じように適用し、生成された項目は書かれた項目を置き換える。生成された項目同士が同じパスを指したときは、同じ指令なら 1 つにまとめる。生成される指令は "hide"だけなので、違う指令の衝突は起きない。第 5.6 節、第 6.1 節、第 6.5 節の検査は、生成の段を適用した後の項目の集合に対して行う。

例外は走査の "root" と "hide-mounts" の "under" の根の項目の検査（第 5.6 節。生成の前に行う）と、走査で一致したリンクの先の "ro" が差し替えられうるかの判定（上。走査の最中に行う）で、どちらも書かれた段だけに第 5.4 節の置き換えを適用した集合で見る。生成の4 つは、走査、"hide-mounts"、秘密ファイル、"secrets/" の順に行う。

### REQ-172: 祖先から子孫へ適用するマウント順
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

同一性判定を終えた項目を、実体のパスで、祖先が先、子孫が後の順にマウントする。互いに祖先でも子孫でもないパス同士は、実体のパスのバイト順に並べる。この規則により、狭いパスの指令が広いパスの指令に勝ち、同じ入力からは同じ順序が得られる。"rw-copy" の項目は、tmpfs とそれを埋める引数（第 6.1 節）をその項目の位置にまとめて置く。複製の中に着地する狭い項目は複製の後に乗り、狭い項目が勝つ規則は変わらない。表 TBL-155 に従う。

### REQ-173: 作業場所の警告・拒否と次回起動の隙間
- kind: ubiquitous
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1
- verification: unit

合成と飛ばしを終えた項目のうち、ワークスペースかワークツリーかそれらの祖先を指す "rw" が 1 つも無いとき、"kakoi: warning:" で始まる 1 行を標準エラーに出す。起動は止めない。"rw-copy" はこの "rw" に数えない。作業場所を "rw-copy" にした起動では、隔離の中で書いた成果が終了時に消える。

この警告が要るのはまさにその場面である。ワークツリーまたはワークスペースの実体が、"/"、ホームディレクトリ、ホームディレクトリの祖先のいずれかであるとき、種類 "path" の診断で終わる。git 管理外のホームディレクトリで "--workspace" を省略して起動すると、この規則に当たる。カレントディレクトリの実体について、第 6.4 節の順序でそれを含む項目のうち最後に適用されるものが"hide" であるとき、種類 "path" の診断で終わる。

bwrap がそこへ移れないためである。"hide" の中に"rw" で再露出したディレクトリは、この規則に当たらない。"rw-copy" の複製の中のディレクトリも、複製がそのディレクトリを作るので、この規則に当たらない。カレントディレクトリそのものが取得できない（消されている、辿れない）ときも、種類 "path" の診断で終わる。

第 14 節の "--chdir" に渡す値が無いためである。ワークツリーの ".git" を隔離の中から消すと、次回の起動でワークツリーの導出が祖先のリポジトリに変わりうる。ホームとその祖先は上の規則で止まるが、それより下の祖先は止まらない。これは README に既知の隙間として書く。成功の観測条件: 第 6.4 節の表の 6 場面が、計画の表示と隔離の中からの読み書きの両方で表のとおりになり、ホームディレクトリをワークツリーとする起動と、"hide" の中を作業ディレクトリとする起動と、消されたディレクトリからの起動が終了コード 125 で終わる。

反例: 設定ディレクトリの "secrets/" の "hide" より後に祖先のマウントが来て、本物の秘密ファイルが隔離の中から読める。

## Decision tables

### TBL-153: 指令の対象と効果
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1

| 指令 | 対象 | 隔離の中での見え方 |
|---|---|---|
| "rw" | ディレクトリ | 読み書きできる |
| "rw-file" | ディレクトリ以外（通常ファイル、ソケット、FIFO） | その場での書き込みができる。一時ファイルを作ってからの置き換え（rename）は失敗する |
| "rw-copy" | ディレクトリまたは通常ファイル | ホストの内容の複製で始まり、読み書きできる。書いたものはホストに届かず、終了時に消える |
| "ro" | ディレクトリまたはファイル | 読み取り専用 |
| "hide" | ディレクトリまたはファイル | ディレクトリは空のディレクトリで、書けるが内容は終了時に消える。ファイルは空の読み取り専用ファイル |

### TBL-154: ホストへ書き戻さない指令の比較
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1

| 指令 | 初期状態 | 書き込み | 終了後 |
|---|---|---|---|
| "ro" | ホストの内容 | 不可 | ホストは不変 |
| "hide" | 空 | ディレクトリは可、ファイルは不可 | ホストは不変 |
| "rw-copy" | ホストの内容 | 可 | ホストは不変。内側の変更は消える |

### TBL-155: 狭い項目を後に適用する例
- source: docs/decision/brainstorm/2026-09-16-kakoi-spec-readability.md#A1

| 場面 | 結果 |
|---|---|
| "/mnt/c" を "hide"、その中のワークツリーを "rw" | ワークツリーは読み書きできる |
| "~/.codex" を "rw"、"~/.codex/AGENTS.md" を "ro" | "AGENTS.md" は読み取り専用 |
| ワークツリーを "rw"、走査で見つけた ".env" を "hide" | ".env" は空 |
| "/tmp" を "hide"、"/tmp/kakoi" を "rw" | "/tmp" は空で、"/tmp/kakoi" だけがホストと共有される |
| "~/.cache" を "rw"、"~/.cache/x/.env" を走査で "hide" | ".env" は空 |
| "~/.config" を "rw"、"~/.config/gh" を "rw-copy" | "gh" の中は書けるがホストに出ず、"~/.config" の他はホストと共有される |
