# 検証の契約

この章は、kakoi の振る舞いをどの層のテストで、何を条件として確かめるかを定める。
テストを足す保守者、計画の算出や起動の処理を変える保守者が読む。

検証は 2 つの層で行う。
1 つは、合成した事実を計画の算出に与えて判断を調べる純粋な関数のテストである。
もう 1 つは、ビルド済みの kakoi と実際の bwrap を起動し、隔離の中と外で読み書きして確かめるテストである。
両方を通すのは、「計画は正しいが、実行すると違う」という見落としを防ぐためである。
どちらの層のテストも、外部ネットワークへの接続に依存せずに通ること。

## 計画の算出を純粋な関数にする
<!-- @kotowari[REQ-354:6447ca91, EX-648:47f60ee3, EX-649:b2b8636c] -->

計画の算出は、次の入力だけから結果が決まる純粋な関数として実装する。

| 入力 | 含めるもの |
|---|---|
| ポリシー | 合成前の各段と、その出所（ファイルの実体パスか、組み込みの既定か） |
| 起動条件 | コマンドライン引数、ホストの環境、カレントディレクトリ |
| パスの事実 | 候補パスの存在、種類、実体。パス解決で参照したもの（通るディレクトリ、リンクの置き場と先） |
| 収集結果 | マウント一覧とその取得失敗、走査結果、ワークツリーと Git の相互リンク、秘密の内容、`rw-copy` の複製元の木 |

次の 3 つは、この関数の外に置く。

- 事実の収集。
- ファイル記述子の割り当て。
- bwrap の起動。

テストでは合成した事実を与え、次の 4 つを期待値と比べる。
外部の入出力なしで比べられる。

- 記号付きの bwrap 引数列。
- 環境。
- 各項目の適用結果。
- 解決したコマンド。

計画の算出がホストのファイルを直接読むことは、この契約に反する。

## 純粋な関数で確かめること
<!-- @kotowari[REQ-355:e3de01f6, EX-650:61347dde, EX-651:5ae9dd1e] -->

純粋な関数のテストは、この節に挙げる項目をすべて含める。
どの項目も、成り立つ条件だけでなく、対になる成り立たない境界も確かめる。
たとえば根の項目の検査が拒否することだけを確かめ、検査の対象外である `ro` が通ることを確かめないのは、この契約に反する。

### 設定、変数、合成
<!-- @kotowari[TBL-156:3473d98a] -->

- `${git_common_dir}` の相互リンクが成り立つ場合と成り立たない場合。共通ディレクトリ C に通常ファイルの `HEAD` が無い場合も含める。
- 3 種類の合成規則、`path-prepend` の向き、ワイルドカードの意味。
- パスの同一性。存在しないパスを展開後の文字列で判定する場合も含める。
- 変数の展開と、相対パスの拒否。
- `init` の文法。NAME の制約と、他の引数との併用を含める。

組み込みの既定への置き換えは、ファイルを読み込むときに決まる。
そのため純粋な関数の外の検証として、[ビルド済みバイナリで確かめること](#ビルド済みバイナリで確かめること)で観測する。

### ポリシーを保護する配置
<!-- @kotowari[TBL-156:3473d98a, TBL-157:f2fe03b4] -->

[ポリシーを保護する配置](../reference/06-policy-placement.md)について、拒否だけでなく、許可すべき境界も確かめる。

| 対象 | 確かめる条件 |
|---|---|
| 保護対象のパス | 3 つの検査すべて。秘密ファイルも対象に含める |
| 根の項目の検査の対象 | `rw`、`rw-file`、`hide`、明示した workspace、走査の `root`、`hide-mounts` の `under` |
| 生成前の起点の検査 | `root` と `under` は生成前の集合で判定し、その診断が後続の検査より先に出る |
| パス解決で参照したもの | 入れ子の項目、`..` で書き込める領域を通り抜けるリンク先、workspace の変数からの参照の引き継ぎ。走査の `root` への引き継ぎも含める |
| workspace | カレントディレクトリと同じ実体を指す指定は除外する。リンクを辿る明示の指定の規則も確かめる |
| `hide` のリンク | 書き込める領域の中のリンクを辿る `hide` は、着地先が `rw` の外でも根の項目の中でも拒否する。`rw` の中を実体のパスで指定した `hide` は許可する |
| 走査の起点 | `rw` の下位の `root` は拒否し、`rw` のマウント点そのものの `root` は許可する。`rw` の中のリンクを経由してマウント点を指す `root` と `under` は拒否する |
| 根の項目の検査の対象外 | `ro` と `rw-copy` のリンクは、どの項目でもない場所へ向けても通る |
| 固定部分と広さ | `/`、`/dev`、`/proc` への着地と、広すぎる書き込み範囲を拒否する |

露出する組の検査では、次を確かめる。

| 区分 | 形 |
|---|---|
| 拒否する形 | 下の段と同じ実体、段を問わない祖先、生成された `hide` の中への着地、`hide` の中への `rw-copy`、`rw-copy` の中への `rw` と `rw-file` |
| 許可する形 | `hide` の再指定、間の段の `rw` が遮る形、別の根の項目への着地、`ro` の中への `rw-copy` |

### マウントと複製
<!-- @kotowari[TBL-156:3473d98a] -->

- `rw-copy` を、ホストへ書き込める項目に数えない。中に置いたポリシーファイル、設定ディレクトリ、秘密ファイルが保護対象の検査を通ること、根の項目の検査の対象外であること、作業場所への警告で `rw` として数えないことを確かめる。
- `rw-copy` の複製元が無ければ飛ばす。生成する引数は、ディレクトリの tmpfs とエントリの順、通常ファイルの `--bind-data`、モードの引き継ぎを確かめる。
- 生成の段と走査は、シンボリックリンクとポリシーファイルの除外を含める。差し替えられない `ro` の中を指すリンクは隠さず、差し替えられうる `ro` の中を指すリンクは `path` の診断になることを確かめる。
- `hide-mounts` は、作業場所の除外と、マウント一覧を読めないという事実からの `path` の診断を確かめる。設定ディレクトリの `secrets/` の隠しも確かめる。
- マウントの 6 場面の重なりと、兄弟の順序を確かめる。
- 作業場所への警告と、2 種類の拒否（広すぎる位置、隠されたカレントディレクトリ）を確かめる。再び見えるようにしたカレントディレクトリは許可する。

### 環境、起動、表示
<!-- @kotowari[TBL-156:3473d98a] -->

- 環境の構成の 7 段階、`unset` のワイルドカード、`path-prepend` の実体化と飛ばし。
- 秘密の注入の 2 段階、LF と CR LF の扱い、秘密ファイルが無いときの警告、値の上限。
- Git の設定の番号付け。空の `GIT_CONFIG_COUNT` も含める。
- 出力に埋め込む制御文字のエスケープ。
- コマンドの解決と、bwrap 引数列の `--argv0` および末尾の `--`。

## ビルド済みバイナリで確かめること
<!-- @kotowari[REQ-356:67c78770, EX-652:4cefc5f6, EX-653:1389ca4a] -->

Linux x86_64 でビルド済みの kakoi を起動し、実際の bwrap を使って、この節に挙げる観測条件をすべて確かめる。
テストは外部ネットワークへの接続に依存しない。
純粋な関数のテストが通ったことだけで、実バイナリを検証済みとすることはこの契約に反する。

### 診断、終了、実行の境界
<!-- @kotowari[TBL-158:d67a978f] -->

- [入れ子、並列、出力、診断と終了コード](../reference/10-process.md)が説明する診断と終了結果の全条件。隣り合う検査段階の診断が同時に成り立つときは、先の段階の診断が出ること。
- ファイルの読み方。FIFO でも停止せず診断になることと、読み込み量の上限の超過（[実行時の境界](runtime.md)）。
- 記述子の上限。soft 上限が 1024 の環境で、1100 件の走査を行うこと。
- マウントの 6 場面を、隔離の中から読み書きして確かめること。
- `network.mode` の `none`、秘密が隔離の中からどう見えるか。
- seccomp による `TIOCSTI` の EPERM。上位ビットを立てた呼び出しと、x32 のビットを立てた呼び出しによる終了も含める。
- 入れ子の警告と `command not executable`。argv[0] は、隔離の中と入れ子の両方で確かめる。

### rw-copy
<!-- @kotowari[TBL-158:d67a978f, TBL-159:f026d784] -->

| 場面 | 隔離の中とホスト側で確かめること |
|---|---|
| 通常ファイル | ホストの内容を読める。書き込みが成功して読み戻せる。ホストの元のファイルは変わらず、終了後に残骸が無い |
| ディレクトリ | 既存の内容を読め、新規作成と上書きができる。実行ビットが引き継がれ、中で作った実行可能ファイルも実行できる。ホストのディレクトリは変わらず、残骸も無い |
| 複製元の不在と種類 | 不在なら飛ばす。根がソケットか FIFO なら `path` になる |
| 上限と複製できない内容 | エントリ数の超過は `path` になる。複製できないエントリは計画に出る |
| リンクと重なり | リンクはリンクのまま複製する。中にある狭い `rw` への書き込みはホストに届く |
| 計画 | `--print-plan` の表示と JSON の両方に、項目と指令が出る |
| 中に置いたポリシーファイル | 起動を許可する。隔離の中で書き換えても、ホストには出ない |

### init と既定のプロファイル
<!-- @kotowari[TBL-158:d67a978f] -->

- 設定ディレクトリが無い状態から書き出せる。`~/.config` も無い場合は、そこから作る。
- 書き出した内容が `examples/profile/default.toml` とバイト単位で一致する。
- `secrets/` のモードが 0700 になり、既存のものも 0700 に狭まる。
- 書き出し先が既存またはリンク切れなら `path` になる。`profile/` の位置が通常ファイルの場合も `path` になる。
- 標準出力はパス 1 行。設定ディレクトリがリンクならリンク先へ書き、表示するのは組み立てたままのパスである。
- `KAKOI=1` でも、`init` は標準エラーに何も出さず、終了コード 0 で書く。
- 設定ディレクトリが通常ファイルなら `policy` になる。既定のファイルか設定ディレクトリがリンク切れの場合も `policy` になる。
- 設定ディレクトリが無いとき、組み込みの既定による `--print-plan` は 0 で終わり、計画に `kakoi init` が出る。同じ状態で、追加のポリシーの `ro` に `config_dir` を使うと、その項目が飛ばしとして出る。
- 設定ディレクトリが無く、存在する最も深い祖先が書き込める領域にある場合は、ポリシーを保護する配置の `path` の診断になる。

### JSON の契約
<!-- @kotowari[TBL-158:d67a978f] -->

`--print-plan` の JSON が解析でき、[計画の表示](../reference/04-plan.md)が定めるトップレベルのキーを持ち、秘密の値が `null` になっていることを確かめる。

## 移行時に一度だけ行う確認
<!-- @kotowari[REQ-357:77d04910, EX-654:6b209399, EX-655:88a5249d] -->

現行の codex 用 jail（bash スクリプト）から移行するとき、利用者の実機で一度だけ確認する。
旧スクリプトが bwrap へ渡す引数列と `--print-plan` の出力を並べ、マウントの集合が同じであることを人が確かめる。

旧スクリプトは製品の一部ではないので、この比較は継続するテストとして残さない。
旧スクリプトを製品の恒久的なテストの依存にすることは、この契約に反する。

## ネットワークの検証

filtered の検証でも、計画の算出（kakoi-core）の純粋さを保ち、DNS 応答の採否と許可の期限の判断を OS の操作から分けて検証する。
この分担は[ライブラリの責務と実証条件](library.md)が定める。
実ネットワークと故障時の保証は、同じ章の実証条件を先に満たしてから確かめる。
