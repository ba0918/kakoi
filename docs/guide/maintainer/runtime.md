# 実行時の境界

この章は、kakoi が起動のたびに何を読み、ホストへ何を書かず、どの外部コマンドに依存するかを定める。
読み込みやファイル記述子の扱いを変える保守者、bwrap に渡す引数を変える保守者が読む。
コマンドを包む起動と、設定ディレクトリを作る `init` とでは、書き込みの扱いが異なる。

## ホストへ書くもの
<!-- @kotowari[REQ-305:001f6676, EX-538:b19c7edb] -->

コマンドを包む起動は、`--print-plan` による計画の表示も含めて、永続する状態を持たず、kakoi 自身はホストのファイルを書かない。
`rw-copy` の複製もホストに保存しない。
包んだコマンド自身による `rw` への書き込みは、[マウントの解決](../reference/07-mounts.md)で許した範囲に従う。

前回の起動結果を保存して次回の判断を変えることはしない。
起動計画は、引数、ポリシー、収集した環境とファイルシステムの事実だけから決まる。
同じ入力と事実で計画の表示を 2 回行えば、同じ計画が得られる。

ファイルを書くのは `init` だけである。
書く範囲は次の 4 つに限る。

- 設定ディレクトリまでのパスで欠けている成分。
- 設定ディレクトリの下の `profile/`。
- 設定ディレクトリの下の `secrets/`。
- 出力するプロファイル。

kakoi は `/tmp/kakoi` を作らない。
作成と上書き拒否の詳細は[コマンドライン](../reference/03-cli.md)が定める。

## 読む事実
<!-- @kotowari[REQ-306:8be7f29c, EX-539:84e216b9] -->

起動時に読む対象と、そこから読む情報は次のとおりである。

| 対象 | 読む情報 |
|---|---|
| ポリシーファイル、秘密ファイル | ポリシーの内容と秘密の値 |
| Git の配置 | `.git` の `gitdir:`、`commondir`、`worktrees/*/gitdir`、サブモジュールの `config` |
| Git 共通ディレクトリ C の `HEAD` | 存在と種類だけ。内容は読まない |
| マウントと走査 | マウント一覧、走査で辿るディレクトリ |
| 候補パス | 存在、種類、実体のパス |
| [ポリシーを保護する配置](../reference/06-policy-placement.md)のパス解決 | 通過したディレクトリ、辿ったシンボリックリンクの先 |
| 適用する `rw-copy` の複製元 | ディレクトリのエントリ名、種類、モード。通常ファイルの内容とモード。リンクの先 |

たとえば linked worktree の共通ディレクトリを調べるときは、`HEAD` が存在して通常ファイルであることを確かめ、中身は読まない。

filtered で加わる観測は、ネットワークの章の規則に従う（[filtered で加わる観測](#filtered-で加わる観測)）。

## 外部コマンド
<!-- @kotowari[REQ-307:8030697b, EX-540:0805751b] -->

host と none は、`bwrap` 以外の外部コマンドを実行しない。
`bwrap` はホストの `PATH` から探す。

| 状況 | 結果 |
|---|---|
| ホストの `PATH` に `bwrap` がある | その `bwrap` を使う |
| ホストの `PATH` に `bwrap` がない | 種類 `bwrap` の診断、終了コード 125 |

`bwrap` が無いときの診断は、コマンドの解決より先に出る。

filtered が追加で依存するもの（pasta と nftables）は、[ライブラリの責務と実証条件](library.md)の完了条件で確定する。

## メモリ上のファイル記述子
<!-- @kotowari[REQ-308:79523cd2, EX-541:4945ee3f] -->

次の 3 つのデータは、メモリ上のファイルとして作り、ファイル記述子を通して bwrap に渡す。
ホストのファイルシステムには現れない。

- `hide` 用の空ファイル。
- `rw-copy` で複製する通常ファイルごとの内容。
- seccomp フィルタ。

記述子を用意できない場合は、種類 `bwrap` の診断で終わる（終了コード 125）。

記述子の番号は起動の直前に割り当てる。
計画の表示では、番号の代わりに記号を示す。
起動前に全量の計画を表示しても、記述子番号は現れない。

## 開けるファイル数の上限
<!-- @kotowari[REQ-309:9dd961c9, EX-542:5d410ab1] -->

記述子を作る前に、開けるファイル数の soft 上限を hard 上限まで引き上げる。
必要なときだけ上げるのではなく、毎回上げる。
包んだコマンドも、引き上げた後の上限を引き継ぐ。
必要なときだけ上げる方式にすると、同じ入力でも包んだコマンドの上限が変わり、結果が入力だけで決まらなくなるためである。

入れ子の起動は記述子を作らず、上限も変えない。

`rw-copy` は、複製する通常ファイル 1 個につき記述子を 1 個使う。
そのため[マウントの解決](../reference/07-mounts.md)が定める複製のエントリ数の上限は、記述子の数にも効く。

例として、soft 上限が 1024 の環境で `hide` のファイルを 1100 個使う起動を考える。
hard 上限が足りていれば起動でき、包んだコマンドには引き上げた後の値（hard 上限と同じ値）が渡る。
hard 上限まで上げても記述子を用意できなければ、種類 `bwrap` の診断で終わる。

## 待たずに開き、通常ファイルだけを読む
<!-- @kotowari[REQ-310:955b03fa, EX-543:94637565] -->

次のファイルは、待たずに開き、開いた記述子で通常ファイルであることを確かめてから読む。

| 対象 | 通常ファイルでないときの診断 |
|---|---|
| ポリシーファイル | `policy` |
| 秘密ファイル | `secret` |
| `.git` と G 配下の読み取るファイル | `path` |
| `rw-copy` の複製元のファイル | `path` |

G は、[ポリシーファイルの形式と合成](../reference/05-policy.md)が定める Git のパスの導出で得る管理ディレクトリを指す。
どの診断も終了コードは 125 である。

FIFO を指定されても、読み手を待って停止することはない。
たとえば `--policy-file` に FIFO を指定すると、待たずに種類 `policy` の診断になり、125 で終わる。

## 読み込み量の上限
<!-- @kotowari[REQ-311:3a0eaa11, EX-544:e4a8ab48] -->

読み込むファイルには、対象ごとに次の上限がある。
上限を超えるファイルは、通常ファイルでない場合と同じ種類の診断で拒否する。

| 対象 | 読み込み量の上限 | 超過時の診断 |
|---|---|---|
| ポリシーファイル | 1 ファイル 1 MiB | `policy` |
| `.git` と G 配下のファイル | 1 ファイル 1 MiB | `path` |
| 秘密ファイル | 1 MiB より先に、末尾の改行を除いた値の 64 KiB が効く | `secret` |
| `rw-copy` の複製元 | 1 ファイル 1 MiB は適用しない。1 項目あたり 4096 エントリ、通常ファイルの内容の合計 64 MiB | `path` |

たとえば 1 MiB を 1 バイト超えるポリシーファイルは、種類 `policy` の診断で 125 になる。

秘密の改行と値の検査は[環境変数と認証情報](../reference/08-environment.md)に、複製の範囲は[マウントの解決](../reference/07-mounts.md)に従う。
マウント一覧と走査するディレクトリは、この読み込みの規則の対象外である。

## 開く名前がシンボリックリンクのとき
<!-- @kotowari[REQ-312:70d39bf2, EX-545:026ce065] -->

開く名前自身がシンボリックリンクのとき、辿るかどうかは対象で決まる。

| 対象 | 開く名前がリンクの場合 |
|---|---|
| ポリシーファイル、秘密ファイル | 辿る。dotfiles へのリンクで置く配置を許すためである。リンク先の実体は[ポリシーを保護する配置](../reference/06-policy-placement.md)の検査対象になる |
| `.git` と G 配下のファイル | 辿らない |
| 実体化済みの `rw-copy` の複製元 | 辿らない。複製元ディレクトリの中のリンクも辿らず、リンクのまま複製する |

秘密ファイルが通常ファイルへのリンクであれば、リンク先の値を読む。
一方、`G/commondir` をリンクにすると、辿らずに通常ファイルでないものとして扱われ、種類 `path` の診断になる。

## 配置検査で辿るリンクの数
<!-- @kotowari[REQ-313:d8dd8cca, EX-546:f8b4c0f3] -->

[ポリシーを保護する配置](../reference/06-policy-placement.md)のパス解決は、カーネルと同じくシンボリックリンクを 40 本まで辿る。
それを超えた後は、存在しない成分と同じ扱いにする。
超えたときの結果は、パスの役割で次のように分かれる。

| パスの役割 | 上限を超えたときの結果 |
|---|---|
| 保護対象のパス | そこまでに参照した場所を検査する |
| 書かれたマウント項目 | 実体を持たない項目として飛ばす |
| `--workspace` | [ポリシーファイルの形式と合成](../reference/05-policy.md)が定める workspace の導出に従い、種類 `path` の診断 |

## 信頼する起動環境と対象外
<!-- @kotowari[REQ-314:c2427c51, EX-547:b860a6bf] -->

kakoi は、起動元の次の 5 つを信頼する。

- `HOME`
- `XDG_CONFIG_HOME`
- `PATH`
- `KAKOI`
- カレントディレクトリ

ホスト側でこれらを変えると、読むプロファイル、入れ子の判定、作業場所も変わる。
たとえばホストで `KAKOI=1` を与えて起動すると、入れ子として扱う。
この前提は README に記す（[公開文書に載せる事項](public-docs.md)）。

cgroup による資源の制限は対象外である。

## bwrap の固定引数
<!-- @kotowari[REQ-315:b6d7b7e4, EX-548:d62fe4db] -->

host と none で bwrap に渡す引数は、次の固定部分から順に始まる。
固定部分はポリシーで変えられない。

| 順序 | 引数 |
|---|---|
| 1 | `--ro-bind / /` |
| 2 | `--dev /dev` |
| 3 | `--proc /proc` |
| 4 | `--unshare-all` |
| 5 | `--share-net`（`host` の場合だけ） |
| 6 | `--die-with-parent` |
| 7 | `--chdir <カレントディレクトリ>` |
| 8 | `--seccomp <ファイル記述子>` |
| 9 | `--argv0 <COMMAND に与えた文字列>` |

固定部分に続けて、次の順に置く。

1. [マウントの解決](../reference/07-mounts.md)が定める適用順のマウント項目。
2. 区切りの `--` を 1 個。
3. 解決済みのコマンドのパス。
4. `ARGS`。

区切りの `--` は、`-x/tool` のようにハイフンで始まるコマンドパスを bwrap のオプションとして読ませないために置く。
COMMAND が `-` で始まる相対パスでも、`--` の後のコマンドとして渡る。

## COMMAND を省いた計画の引数列
<!-- @kotowari[REQ-316:b44ebe78, EX-549:4038f2a9] -->

`--print-plan` で `COMMAND` を省略した場合は、計画の引数列から次を省く。

- `--argv0` とその値。
- 末尾の `--` と、その後ろ。

計画の表示そのものは[計画の表示](../reference/04-plan.md)が定める。

filtered の接続機構と起動の順序は、[ライブラリの責務と実証条件](library.md)の実証工程で確認する。

## filtered で加わる観測
<!-- @kotowari[REQ-306:8be7f29c] -->

filtered の実行中の通信状態は、上に挙げた事実に加えて、DNS 応答、待受、接続口の観測と経過時間にも従う。
観測する対象と規則は、ネットワークの各章が定める。

| 観測するもの | 規則を定める章 |
|---|---|
| ホストの DNS の構成とその変更、起動時のホスト OS の CA 証明書 | [上流 DNS](../reference/network/05-dns-upstream.md) |
| 指定したインターフェースの存在と消失 | [IP の入力と分類](../reference/network/03-addresses.md) |
| 初版の固定公開の確保状態 | [公開](../reference/network/06-publish.md) |

待受状態の自動検出は初版に含まず、後続の動的公開で加える（[公開](../reference/network/06-publish.md)）。
アプリの申告を根拠に許可を増やすことはない（[通信許可](../reference/network/02-allow.md)）。

filtered でも、永続する状態を持たずホストのファイルを書かないという[ホストへ書くもの](#ホストへ書くもの)の境界は変わらない。
