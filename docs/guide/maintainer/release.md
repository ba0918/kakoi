# 版とリリース

この章は、kakoi の版をどこで管理し、リリースで利用者に何を届けるかを定める。
版を上げる保守者と、配布物の形を変える保守者が読む。

## 版の典拠
<!-- @kotowari[REQ-386:a3459981, EX-712:3a0a2afb, EX-713:569446a1] -->

版は `Cargo.toml` だけで管理する。
ソースの別の場所で版を独立に管理することは、この契約に反する。

リリースのたびに、次の 2 つを行う。

- `CHANGELOG.md` に項目を追加する。
- 版の先頭に `v` を付けたタグを付ける（版が `0.3.0` ならタグは `v0.3.0`）。

リリースした版では、次の 3 つの版が一致する。

| 表示する場所 | 例（版が `0.3.0` の場合） |
|---|---|
| `kakoi --version` の出力 | `0.3.0` を示す |
| `Cargo.toml` の `version` | `0.3.0` |
| タグ | `v0.3.0` |

## 利用者に届けるもの
<!-- @kotowari[REQ-387:e77fdde9, EX-714:b4a46cf5, EX-715:733e6c14] -->

リリースには次の配布物を添える。

| 配布物 | 契約 |
|---|---|
| 実行ファイル | Linux x86_64 向け、静的リンク |
| 書庫 | `kakoi-v<版>-x86_64-unknown-linux-musl.tar.gz` |
| 書庫の中身 | 実行ファイル 1 つを、ディレクトリを挟まず平置きで含む |
| チェックサム | 書庫名に `.sha256` を付けたファイルに、書庫の SHA-256 を記す |

書庫名は、インストーラが機種に合う配布物を選ぶための契約である。

実行ファイルを静的リンクにするのは、ビルドした機械の libc の版を利用者側の動作条件に持ち込まないためである。
書庫だけを取得した利用者が、ビルドの道具なしで起動できること。
動的リンクした libc の版を配布先の追加条件にすることは、この契約に反する。

CI と配布物の作成手順は、この契約の対象外である。
