# 用語

この章は、ガイドと kakoi の診断で使う言葉の意味を決める。
他の章は用語の初出で一言説明するだけなので、意味を正確に確かめたいときはここを引く。
関連する語を小見出しでまとめ、各語に「使わない」言い方を添えた。

## 用語の典拠
<!-- @kotowari[REQ-174:a26b3aba] -->

この章の定義が、用語の意味の典拠である。
各語の読みと、その意味で使わない言葉は、リポジトリ直下の `CONTEXT.md` に記録する。
「使わない」は、続けて書いた意味では使わないという限定付きの禁止である。
仕様が固定した診断の種類（例：`policy`、`path`）は契約の文字列であり、用語としては扱わない。

## 隔離
<!-- @kotowari[REQ-175:a80f0859] -->

**隔離**：プロセスを実行するとき、利用者が安全を確保できるかどうかの境界。
0.3 では次の 4 つの次元を持つ。

| 次元 | 扱う範囲 |
|---|---|
| ファイルシステム | 見える範囲と書ける範囲 |
| ネットワーク | ホストと共有するか、切るか、filtered で許可範囲を制限するか |
| 環境変数 | ホストから何を引き継ぎ、何を足すか |
| 認証情報 | 隠すファイルと注入する秘密 |

プロセス ID、IPC、UTS、ユーザーの各名前空間は必ず切る。
ユーザー名前空間を作れない環境では、起動が拒否される。
cgroup の名前空間は、カーネルが対応しない場合には切らない。
これらの名前空間は次元として選べない。

認証情報の次元が扱うのは、ファイルと環境変数だけである。
UNIX ソケットを通した認証の転送（ssh-agent、gpg-agent、D-Bus の 3 つが代表）は、そのソケットのパスが隔離の中から見えれば、環境変数を消してもパスを直接指定して使える。
ソケットの経路を止めるのは `hide` であり、`env.unset` は補助にすぎない。
同梱プロファイルはこの両方を行う（[ポリシーファイルの形式と合成、同梱プロファイル](05-policy.md)）。

使わない：「サンドボックス」を bwrap の隔離の意味で。「jail」を隔離の意味で（現行の bash スクリプトを指すときだけ使う）。

## ポリシーと段
<!-- @kotowari[REQ-176:41b2abd4, REQ-177:a902d38c, REQ-178:e0a38616, REQ-179:b227cfb9] -->

**ポリシー**：kakoi が bwrap の引数列と環境、および filtered の通信許可を組み立てるのに使う指定の内容。
段の合成を終えた後のものを指す。

使わない：「設定」「config」「コンフィグ」をポリシーの意味で。「jail.conf」をポリシーの意味で（現行スクリプトのマウント表を指すときだけ使う）。

**ポリシーファイル**：ポリシーを書いた TOML ファイル一般。
プロファイルもポリシーファイルの一種である。

使わない：「設定ファイル」をポリシーファイルの意味で。

**プロファイル**：グローバルスコープにある名前付きのポリシーファイル。
`--profile NAME` で名前を指定する。
置き場所は設定ディレクトリの `profile/NAME.toml` である。

使わない：「プロファイル」を `--policy-file` で指定したファイルの意味で。

**組み込みの既定**：kakoi のバイナリに埋め込まれた、同梱プロファイル `examples/profile/default.toml` と同じ内容。
`--profile` が `default`（省略時を含む）で `profile/default.toml` が無いときにだけ、その代わりとしてグローバルスコープになる（[ポリシーファイルの形式と合成、同梱プロファイル](05-policy.md)）。
`kakoi init` がこれをファイルとして書き出す（[コマンドライン、コマンドの解決、init](03-cli.md)）。

使わない：「既定のプロファイル」を、ファイルとして置かれた `default.toml` と区別せずに。「フォールバック」。

### 段とスコープ
<!-- @kotowari[REQ-186:027ce113, REQ-187:9e060fc9, REQ-188:65e18a21] -->

**段**：ポリシーの項目に優先順位を与える 4 つの層。
下から順に次のとおりである。

| 段 | 与えるもの | 区分 |
|---|---|---|
| グローバルスコープ | `--profile` で選んだプロファイル | 書かれた段 |
| プロセススコープ | `--policy-file` で指定したポリシーファイル | 書かれた段 |
| コマンドライン | `--rw` と `--hide` | 書かれた段 |
| 生成 | kakoi が生成する項目（[マウントの解決](07-mounts.md)） | 生成された段 |

上の段は下の段に足すか、上書きする。
手順の順番を指すときは「段」ではなく「段階」を使う。

使わない：「レイヤ」「継承」「include」を段の合成の意味で。「段」を手順の順番の意味で（そちらは「段階」）。

**グローバルスコープ**：一番下の段。
`--profile` で選んだプロファイルが与える。

使わない：「グローバル設定」「ユーザー設定」をこの段の意味で。

**プロセススコープ**：下から 2 番目の段。
`--policy-file` で指定したポリシーファイルが与える。

使わない：「プロジェクト設定」「ローカル設定」をこの段の意味で。

## ファイルの置き場
<!-- @kotowari[REQ-183:0dbc3ffe, REQ-184:9a7458e6, REQ-185:288bfa39] -->

**ホームディレクトリ**：ホストの環境変数 `HOME` の実体のパス。
`HOME` が次のどれかに当たるときは、ポリシーが `~` を使うかにかかわらず、起動の途中で種類 `env` の診断で終わる。

- 無い、または空である。
- 絶対パスでない。
- 実体のパスを得られない（存在しない、途中が辿れない）。
- 実体がディレクトリでない。

単独の `--help` と `--version`、および `--print-plan` を伴わない入れ子の起動は、この検査の段階に至らない（[入れ子、並列、出力、診断と終了コード](10-process.md)）。

使わない：「ホーム」を `~` の字面や `/home/<user>` の慣習の意味で。

**設定ディレクトリ**：`$XDG_CONFIG_HOME/kakoi/`。
`XDG_CONFIG_HOME` が未設定なら `~/.config/kakoi/` である。
空文字と絶対パスでない値は、XDG Base Directory の慣習に従い未設定と同じに扱う。
たとえば `XDG_CONFIG_HOME` を相対パスにして起動すると、`~/.config/kakoi/` のプロファイルが読まれ、カレントディレクトリの下の `kakoi/profile/default.toml` は読まれない。

プロファイルは `profile/` に、秘密ファイルは `secrets/` に置く。
`secrets/` は常に隠される（[マウントの解決](07-mounts.md)）。

使わない：「プロファイルディレクトリ」を設定ディレクトリの意味で。

**正本**：利用者が編集する元のファイル。
設定ディレクトリの中身やシムの置き場が、そこから生成や同期で作り直されるか、そこへのリンクであるとき、その元を指す。
正本が他所にある場所への書き込みは、次の生成で消えるか、正本を書き換える。
設定ディレクトリの中に置かれ、他から作り直されないファイルは、それ自身が正本である。

使わない：「実体」を正本の意味で（他所から生成して置いたファイルは設定ディレクトリの中にあるが、その正本は他所にある）。

## 作業の場所
<!-- @kotowari[REQ-189:71876448, REQ-190:39ecfcb2] -->

**ワークスペース**：変数 `${workspace}` の値であり、ワークツリーを導出する起点となるディレクトリ。
`--workspace PATH` で指定し、省略時はカレントディレクトリである。
ワークスペースそのものはマウントされない。
マウントされるかどうかは、ポリシーが変数で指定するかで決まる。

使わない：「cwd」「カレントディレクトリ」をワークスペースの意味で（カレントディレクトリは bwrap の作業ディレクトリであり、ワークスペースとは別物）。「隔離の対象」（マウントされると誤読される）。

**ワークツリー**：ワークスペースから親へ向かって最初に `.git` を持つディレクトリ。
`.git` はシンボリックリンクを辿らずに見て、ディレクトリまたは通常ファイルであるものだけを数える。
見つからなければ、ワークスペース自身がワークツリーになる。

使わない：「リポジトリ」「プロジェクトルート」をワークツリーの意味で。

## マウントと秘密
<!-- @kotowari[REQ-191:0c49df34, REQ-192:9eb1c033, REQ-193:3992ab2b] -->

**指令**：マウント表の 1 行の種類。
`rw`、`rw-file`、`rw-copy`、`ro`、`hide` の 5 つがある（[マウントの解決](07-mounts.md)）。

使わない：「ディレクティブ」「ルール」「エントリ」を指令の意味で。

**走査**：`mounts.scan` の指定に従い、起点以下のファイルを名前で探して `hide` の項目を生成すること。

使わない：「スキャン」「検索」を走査の意味で。

**秘密**：`secrets` に書かれた環境変数名とファイルの組、およびファイルから読んで環境変数に入れる値（[環境変数、認証情報、Git の URL 書き換え](08-environment.md)）。

使わない：「シークレット」「クレデンシャル」「トークン」を秘密の意味で。

## 起動と失敗
<!-- @kotowari[REQ-194:2285682e, REQ-195:a4a2fccf, REQ-196:3a70e2b8] -->

**計画**：ポリシーと収集した事実から算出した、次のものの組。

- bwrap に渡す引数列（ファイル記述子の位置は記号で表す）
- 環境
- 各マウント項目の適用結果
- 解決したコマンドのパス

filtered では、起動時に確定する通信ポリシーも含む。
`--print-plan` がこれを表示する（[計画の表示](04-plan.md)）。

使わない：「ドライラン」「プレビュー」を計画の意味で。

**診断**：kakoi 自身の失敗を伝える、標準エラーへの 1 行。
形式と終了コードは[入れ子、並列、出力、診断と終了コード](10-process.md)で説明する。

使わない：「エラーメッセージ」「ログ」を診断の意味で。

**入れ子**：環境変数 `KAKOI` が `1` の状態で kakoi が起動されること。
既に隔離の中で動いているプロセスが kakoi を起動した場合がこれに当たる。

使わない：「再帰」「ネスト」を入れ子の意味で。

## 配置の安全性
<!-- @kotowari[REQ-197:5530d3f3, REQ-198:4e89abbd, REQ-199:758bfccf] -->

この 3 語は、隔離の中からの書き換えでポリシーの効き目を変えられないかを判定するときに使う（[ポリシーを保護する配置](06-policy-placement.md)）。

**解決が参照するもの**：あるパスを実体へ解決する途中で、次の 2 つに当たるもの。

- 成分を探すために中身を見るディレクトリの実体（`..` で戻る前に通ったものを含む）
- 辿るシンボリックリンクの置き場（親ディレクトリの実体とリンクの名前）

そのパス自身の実体は、中身を見ないので含まない。
解決の結果を変えるには、このどれかを書き換えるしかない。

使わない：「経路」「チェーン」「辿ったもの」を参照するものの意味で。

**根の項目**：書き込める項目のうち、自身の解決が書き込める項目の中（自身の中を含む）にあるものを一切参照しないもの。
書き込める項目とは、合成後の `rw` または `rw-file` の項目であり、その中とは項目と同一か子孫のパスを指す。
根の項目は、隔離の中からの書き換えで解決の結果を変えられないので、配置の検査の信頼の起点になる。

`rw-copy` の項目は書き込める項目に数えない。
その中への書き込みはホストに届かず（[マウントの解決](07-mounts.md)）、次の起動が読む内容も、パスの解決の結果も変えられないためである。

使わない：「錨」「アンカー」「信頼できる項目」を根の項目の意味で。

**露出する組**：書き込める項目の中を参照して解決される項目と、それが無効にする `hide`、`ro`、`rw-copy` の項目の組のうち、新しく見えるものや書けるものが生まれるもの。
組になるのは次の 2 つの場合である。

| 項目 | 相手（無効にされる側） |
|---|---|
| `rw` または `rw-file` | `hide`、`ro`、`rw-copy` |
| `ro` または `rw-copy` | `hide` |

相手には、書かれた項目のほか、祖先として効いている生成された `hide` も含む。
`hide` の項目は何も露出しないので、どの相手とも組にならない。

`rw-copy` が組になる向きは 2 つある。
相手の側では、書き込みがホストに出ない場所を `rw` や `rw-file` が上書きし、書き込みを通してしまう。
項目の側では、`ro` と同じく `hide` を無効にしてホストの内容を見せる。
`rw-copy` が `ro` に重なっても、同じ内容を見せて書き戻さないので、新しく見えるものは無い。

使わない：「衝突」「上書きの組」を露出する組の意味で。

## シムとセットアップスキル
<!-- @kotowari[REQ-180:b991b051, REQ-181:2c47f517, REQ-182:ceeff518] -->

**シム**：利用者が `PATH` に置く薄いスクリプト。
包む対象のコマンドを既定で kakoi に通し、対象に固有の差を閉じ込める。
閉じ込める差は、自前のサンドボックスを切るフラグ、引数の写し、利用者が承認した素通しの例外の 3 つである。
シムは製品の一部ではなく、kakoi は雛形を同梱する（[シム](11-shim.md)）。

使わない：「ラッパー」「ジェイル」をシムの意味で。「シム」を kakoi 自体の意味で。「分類」をシムがサブコマンドの隔離の要否を決める意味で（既定は全部隔離で、素通しは例外。却下した案を名指すときを除く）。

**モデルが動かない**：シムの許可リスト（素通し）に入れる前に、利用者が確かめる性質。
そのサブコマンドの実行中に、包む対象がモデルに問い合わせず、モデルの出力でコマンドを実行する機能も持たないことを指す。

使わない：「安全」「無害」をこの意味で。

**セットアップスキル**：同梱する SKILL.md。
エージェント CLI に読ませて、利用者の環境に固有の設定を提案させる。
提案の対象は、プロファイルへの追加、シムの設置、代替コマンドの `path-prepend`、隔離の中で壊れたコマンドの扱いの 4 つである（[セットアップスキル](12-setup-skill.md)）。

使わない：「インストーラ」。「セットアップ」を `init` の意味で。
