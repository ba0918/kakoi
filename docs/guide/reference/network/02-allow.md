# 通信許可

`filtered` で隔離環境内のアプリがどの宛先へ接続できるかを決める `[[network.allow]]` の書き方を定める。
キーの一覧、ポートの書き方、DNS 名の一致とワイルドカード、国際化ドメイン名、ホスト宛ての接続を扱う。
許可を書くとき、許可したはずの通信が通らないとき、または許可の入力エラーが出たときに読む。
モードの選び方は[ネットワークモード](01-modes.md)、IP と CIDR の書き方と特殊なアドレスは [IP の入力と分類](03-addresses.md)を参照。

## 許可のキー
<!-- @kotowari[REQ-088:6856b18a, EX-183:ba8fcbd6, EX-184:19977e38, EX-185:1db3a624, EX-186:6b1e75a0] -->

1 つの許可は、`[[network.allow]]` の 1 項目に `destination`、`protocol`、`ports` を書いて表す。
3 つとも必須で、どれかが欠けたら入力エラーになる。

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `network.allow` | テーブルの配列 | なし（許可 0 件） | 通信許可の一覧 |
| `destination` | インラインテーブル | 必須 | 宛先。下の宛先のキーのどれか 1 つを持つ |
| `protocol` | 文字列 | 必須 | `"tcp"` または `"udp"` |
| `ports` | 文字列の配列 | 必須 | 許可するポート。[ポートの書き方](#ポートの書き方)に従う |

`destination` の中には、次の宛先のキーを 1 つだけ書く。

| キー | 型 | 意味 |
|---|---|---|
| `dns` | 文字列 | DNS 名。[DNS 名の一致とワイルドカード](#dns-名の一致とワイルドカード)に従う |
| `ip` | 文字列 | 1 つの IP アドレス |
| `cidr` | 文字列 | アドレスの範囲 |
| `host-loopback` | 文字列 | `"ipv4"` または `"ipv6"`。ホストの localhost を指す。[ホストの localhost への接続](#ホストの-localhost-への接続)を参照 |

IPv6 リンクローカルアドレスへの許可で使う `host-interface` も、`destination` の中に置く。
`ip` と `cidr` の書き方、`host-interface` の規則は [IP の入力と分類](03-addresses.md)で定める。

正しい例:

```toml
[network]
mode = "filtered"

# api.example.com の TCP 443 番
[[network.allow]]
destination = { dns = "api.example.com" }
protocol = "tcp"
ports = ["443"]

# インターフェース eth0 の先にあるリンクローカル宛先
[[network.allow]]
destination = { ip = "fe80::1", host-interface = "eth0" }
protocol = "tcp"
ports = ["443"]
```

入力エラーになる例:

```toml
# 宛先のキーを 2 つ書いている
[[network.allow]]
destination = { dns = "api.example.com", ip = "192.0.2.1" }
protocol = "tcp"
ports = ["443"]

# protocol が無い
[[network.allow]]
destination = { dns = "api.example.com" }
ports = ["443"]
```

入力の形の検査は、許可を使わない `host` と `none` でも行う（[ネットワークモード](01-modes.md)）。

2 つ目の例のように `host-interface` を含む宛先は、入力の形としては正しい。
ただし `filtered` は、起動の処理で `host-interface` を含む宛先を拒否し、アプリを起動しない（[入力エラーの診断](#入力エラーの診断)）。

## 許可が通信を通す条件
<!-- @kotowari[REQ-001:4e682637, REQ-002:d7d18803, EX-001:7dd87065, EX-002:1ec39ab8, EX-003:3ff9609b] -->

新規通信は、宛先、TCP/UDP、ポートの組がいずれかの有効な許可に一致するときに通る。
どの有効な許可にも一致しなければ拒否される。

TCP 443 番だけを許可した宛先に対しては、次のようになる。

| 通信 | 結果 |
|---|---|
| TCP 443 番 | 通る |
| UDP 443 番 | 拒否 |
| TCP 22 番 | 拒否 |

隔離環境内のループバック通信は、許可を書かなくても TCP と UDP の全ポートを使える。
この例外でホスト側の localhost へ接続できるようにはならない。
ホストの localhost から隔離環境内のサービスへの接続は、明示した待受の公開の範囲でだけ通る（[公開](06-publish.md)）。

DNS 名による許可は、その名前から得た IP と指定したポートへの許可である。
許可された同じ IP とポートへの通信なら、IP を直接書いて接続しても、別の名前で接続しても区別しない。
DNS 名から得た IP にも内部アドレスの検査がかかり（[IP の入力と分類](03-addresses.md)）、得た許可には期限がある（[DNS 応答の検査と許可の寿命](04-dns.md)）。

## 段をまたぐ許可の合成
<!-- @kotowari[REQ-092:888cf6b2, EX-195:296aaab8, EX-196:f915ede9, EX-197:191165eb] -->

`network.allow` は、段の間で下の段の一覧に上の段の一覧を足して合成する。
合成後の各許可のどれかに一致する通信が通る。

| 下の段 | 上の段 | 合成後 |
|---|---|---|
| API の TCP 443 番 | ホストの IPv4 ループバックの TCP 5432 番 | 両方 |
| 通信許可あり | `network.allow = []` | 下の段の許可のまま |
| 宛先 A の TCP 443 番 | 宛先 A の TCP 443 番（同じもの） | 1 つにまとめる |

空の配列は許可を消す指定にはならない。
許可を減らすには、元の段のポリシーを編集するか、別のプロファイルを使う。
段の合成全般は[ポリシーファイル](../05-policy.md)を参照。

## ポートの書き方
<!-- @kotowari[REQ-005:a0c57879, REQ-006:1a667f1b, REQ-007:b03854b9, EX-008:e2ce701b, EX-013:4dc1a066, EX-014:1b19d717] -->

`ports` は文字列の配列で書き、省略できない。
要素は、単一の番号（`"443"`）、範囲（`"8000-8010"`）、全ポート（`"*"`）のどれかである。
番号と範囲は同じ配列に混ぜて書ける。

| 指定 | 意味 |
|---|---|
| `["443"]` | 443 番 |
| `["443", "8443", "8000-8010"]` | 443 番、8443 番、8000〜8010 番 |
| `["443-443"]` | `["443"]` と同じ |
| `["*"]` | 1〜65535 番すべて |

ポート番号は 1〜65535 で、`"*"` はこの範囲全体を表す。
範囲は両端を含む。

この記法と検査は、公開の `ports` と `host-ports` でも使う（[公開](06-publish.md)）。

### 重複と重なり
<!-- @kotowari[REQ-008:cacedade, EX-015:d1cf9c5e] -->

番号の重複と範囲の重なりはエラーにせず、指定の和集合を許可する。

| 指定 | 許可する範囲 |
|---|---|
| `["443", "443"]` | 443 番 |
| `["8000-8010", "8005-8020"]` | 8000〜8020 番 |

### ポートの入力エラー
<!-- @kotowari[REQ-005:a0c57879, REQ-006:1a667f1b, REQ-007:b03854b9, REQ-009:f5764193, EX-009:821617f3, EX-016:aad1c3f5] -->

次の指定は入力エラーになる。

| 指定 | 理由 |
|---|---|
| `ports` が無い | 省略できない |
| `[]` | 空の配列 |
| `["*", "443"]` | `"*"` に他の指定を混ぜている |
| `["65536"]` | 1〜65535 の外 |
| `["8010-8000"]` | 開始番号が終了番号より大きい |
| `["0443"]` | 先頭のゼロ |
| `[" 443 "]` | 空白 |
| `["+443"]` | プラス符号 |
| `["https"]` | サービス名 |
| `[443]` | 文字列でない数値 |

## DNS 名の一致とワイルドカード
<!-- @kotowari[REQ-003:911d17bd, REQ-004:58b85f10, EX-004:08d4e183, EX-005:54d208e7, EX-007:8a6771db, EX-020:ad5e2084] -->

ワイルドカードの無い DNS 名は、その名前だけに一致する。
先頭に `*.` を付けた名前は、深さを問わず配下の名前に一致し、親自身には一致しない。

| 指定 | `example.com` | `api.example.com` | `v1.api.example.com` |
|---|---|---|---|
| `example.com` | 一致 | 不一致 | 不一致 |
| `*.example.com` | 不一致 | 一致 | 一致 |

親自身と配下の両方を許可するには、2 つの許可をそれぞれ書く。

ワイルドカードとして使えるのは、入力の先頭にある半角の `*.` だけである。
名前の部分は、先頭の `*.` を分けてから変換する（[国際化ドメイン名](#国際化ドメイン名)）。
次の指定は入力エラーになる。

| 指定 | 理由 |
|---|---|
| `api*.example.com` | 名前の途中の星 |
| `api.*.com` | 先頭以外の `*.` |
| `＊.example.com` | 全角の星。半角に変換して受け付けることはしない |

### 名前の比べ方
<!-- @kotowari[REQ-010:96154c01, EX-017:6c7aeb57, EX-018:461b0e62, EX-019:9bd6c536] -->

DNS 名は英字の大文字と小文字を区別せずに比べ、末尾のドット 1 個は取り除いて比べる。
`API.Example.com`、`api.example.com`、`api.example.com.` は同じ指定になる。

末尾のドットの有無によらず、指定は完成した名前として扱い、ホストの検索用ドメインを補わない。
`api` と書いた許可は `api.example.com` に一致しない。

## 国際化ドメイン名
<!-- @kotowari[REQ-011:be01ca2e, REQ-012:39912430, REQ-013:ceef1add, EX-021:5a16821a, EX-022:41aa9a0e] -->

日本語のような ASCII 以外の文字を含む DNS 名は、そのまま `dns` に書ける。
kakoi は既存のライブラリで UTS #46 の非移行処理（nontransitional processing）を行い、ASCII の名前へ変換する。
たとえば `ＥＸＡＭＰＬＥ.com` は `example.com` になる。
非移行処理なので、`ß` を `ss` に置き換えることはない。

変換後の ASCII の名前は、許可の判定と名前解決の両方で同じものを使う。
変換した名前にも、IP とポートの制限と内部アドレスの検査がかかる（[IP の入力と分類](03-addresses.md)）。
実際に使う変換後の名前は、[計画の表示](../04-plan.md)で確かめられる。

変換または検証に失敗した名前は入力エラーになる。

## ホストの localhost への接続
<!-- @kotowari[REQ-089:c0aadeaa, REQ-090:956eb7e2, EX-187:ba3d850d, EX-189:7da88119, EX-190:e9cac4a6, EX-192:fbf3ee32] -->

隔離環境内の `localhost` は隔離環境自身を指す。
ホストの localhost で動くサービスにつなぐには、`destination` に `host-loopback` を書いて許可し、アプリからは専用の名前で接続する。

| `host-loopback` の値 | 指す先 | アプリが使う名前 |
|---|---|---|
| `"ipv4"` | ホストの `127.0.0.1` | `host-v4.kakoi.internal` |
| `"ipv6"` | ホストの `::1` | `host-v6.kakoi.internal` |

両方を許可するには 2 件書く。
`host-loopback` は `dns`、`ip`、`cidr` と同じ `destination` に書けず、書くと入力エラーになる。

```toml
[network]
mode = "filtered"

# ホストの 127.0.0.1 の TCP 5432 番
[[network.allow]]
destination = { host-loopback = "ipv4" }
protocol = "tcp"
ports = ["5432"]

# ホストの ::1 の UDP 9000 番
[[network.allow]]
destination = { host-loopback = "ipv6" }
protocol = "udp"
ports = ["9000"]
```

この例でアプリが `host-v4.kakoi.internal` の TCP 5432 番へ接続すると、ホストの `127.0.0.1` の TCP 5432 番へ中継される。
`host-v6.kakoi.internal` の UDP 9000 番へ送ると、ホストの `::1` の UDP 9000 番へ中継される。
`localhost:5432` と書いた接続は、隔離環境内へ向かう。

専用の名前を知っていても、許可した TCP/UDP とポートの外には接続できない。
上の例で `host-v4.kakoi.internal` の TCP 5433 番へ接続しても拒否される。

### 専用の名前を dns に書いた場合
<!-- @kotowari[REQ-091:8d8bf2a6, EX-193:d7d44db0, EX-194:24fd428a] -->

`host-v4.kakoi.internal` や `host-v6.kakoi.internal` を `dns` にそのまま書くと、`host-loopback` を使うよう案内する起動前エラーになる。

```toml
# 起動前エラー。host-loopback を使う
[[network.allow]]
destination = { dns = "host-v4.kakoi.internal" }
protocol = "tcp"
ports = ["5432"]
```

`dns` のワイルドカードからは、ホストのループバックへの許可は生まれない。
`*.kakoi.internal` の TCP 5432 番を許可していても、`host-loopback` の許可が無ければ、`host-v4.kakoi.internal` の TCP 5432 番への接続は許可されない。

## ホストのその他の IP への接続
<!-- @kotowari[REQ-139:6f52ba4e, REQ-425:90eb2091, EX-310:09795a64, EX-311:328f7824, EX-816:2ae17eec, EX-817:d65ec552] -->

ホストの LAN 側の IP のような、ループバック以外のホストの IP にあるサービスへは、一般の宛先と同じく `ip` または `cidr`、TCP/UDP、ポートを明示して許可する。
ホストの IP だからという理由で自動で許可することはない。

`filtered` がホスト自身のアドレスとして扱うのは、起動時にホストが持っていたアドレスである。
ホストのアドレスは起動時に一度だけ読み、その後は読み直さない。

| アドレス | `dns` の許可の名前がそのアドレスに解決された場合 |
|---|---|
| 起動時にホストが持っていたアドレス | ホストのアドレスとして扱い、`dns` の許可だけでは通さない。`ip` か `cidr` の明示が要る |
| 起動後にホストが得たアドレス（VPN の接続で得たものが典型） | ホストのアドレスとして扱わず、他の宛先と同じく `dns` の許可で通りうる |

ホストの localhost への接続には、引き続き `host-loopback` を使う。
ホストの非ループバック IP への到達経路は実証が済んでいない（[未決事項](../../appendix/open-issues.md)）。

## 入力エラーの診断
<!-- @kotowari[REQ-088:6856b18a, REQ-426:13163061, REQ-427:3cb13e97, EX-820:ad4ee418] -->

この章の入力エラーは、どれも起動前に見つかり、アプリは実行されない。
診断の種類は誤りを見つけた場所で決まり、ポリシーの読み込みと段の合成で見つかる誤りは `policy`、`filtered` の起動の処理で見つかる誤りは `bwrap` で、どちらも終了コード 125 である。
`host-interface` を含む宛先の拒否は後者に当たる。
規則の全体は[ネットワークモード](01-modes.md)のエラーの節にある。
