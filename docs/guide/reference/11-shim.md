# シム

この章は、コマンドの手前に置いて `kakoi` を経由させる**シム**の契約を決める。
シムは利用者が `PATH` に置く小さなスクリプトで、kakoi 本体の一部ではなく、雛形として同梱する（用語は[用語](02-terms.md)を参照）。
シムを自分のコマンド用に写すとき、隔離の中でコマンドが壊れたときの直し先を探すとき、雛形を変更して確かめるときに読む。
雛形の写しを埋めてもらう手順は[セットアップスキル](12-setup-skill.md)が持つ。

## 雛形の構成（本体とツール節）
<!-- @kotowari[REQ-366:e29a1866, EX-672:41e7e93b] -->

シムの雛形は、包む対象に依らない汎用の本体と、包む対象ごとに書き換える先頭のツール節から成る。
雛形は `examples/shim/codex` に置き、README から指す。
[セットアップスキル](12-setup-skill.md)も同じ内容の写しを自身のディレクトリに持ち、2 つの写しが一致することを検証で確かめる。
スキルだけを入れた利用者の手元にはソースツリーが無いため、スキルの側にも写しが要る。

同梱の雛形には codex の値が入っているが、codex は例にすぎない。
この章の規則は包む対象を限定せず、どのコマンドを包むシムにも同じく適用する。

ツール節は次の 5 項目から成る。
「同梱雛形での名前」は `examples/shim/codex` での変数名である。

| 項目 | 同梱雛形での名前 | 意味 |
|---|---|---|
| 実体の名前 | `REAL_COMMAND` | `PATH` から探す実体のコマンド名 |
| 差し込むフラグ | `BYPASS_FLAG` | 対象が自前のサンドボックスを切るために受け付けるフラグ。無ければ空 |
| 引数の写し | `WORKSPACE_OPTIONS`、`RW_OPTIONS` | 対象のオプションを `kakoi` の `--workspace` と `--rw` に写す対応 |
| 素通しの許可リスト | `ALLOW_LIST` | `kakoi` を通さずに実体を起動するサブコマンド |
| フラグを付けない一覧 | `NO_FLAG_LIST` | `kakoi` は通すが、差し込むフラグを付けないサブコマンド |

差し込むフラグが空でも、本体は同じ動きをし、何も差し込まずに起動する。

## 起動がどの経路に進むか
<!-- @kotowari[REQ-367:c1d25fbb, REQ-368:f678342f, EX-674:2df86473, EX-676:e13dccd7] -->

シムは、`--help` や `--version` を含むすべての起動を既定で `kakoi` に通す。
隔離の要否をサブコマンドから決めることはしない。
対象の版が上がって知らないサブコマンドが増えても、それは隔離に入る。

起動は次の 3 つの経路のどれかに進む。

| 条件 | 経路 | `kakoi` | 差し込むフラグ |
|---|---|---|---|
| `KAKOI_SHIM_OFF=1`、または引数の先頭の語が素通しの許可リストにある | 素通し | 通さない | 付けない |
| 引数の先頭の語がフラグを付けない一覧にある | 隔離（フラグなし） | 通す | 付けない |
| 上のどれでもない | 隔離（既定） | 通す | 付ける |

素通しの経路では、シムは実体を exec し、引数は変えない。

一覧との照合は、引数列の先頭の語だけと行う。
先頭がオプションなら、どちらの一覧とも一致せず、既定の隔離に入る。
雛形は値を取るオプションの一覧を持たないので、オプションの後ろにある語をサブコマンドと読み違える恐れがある。
照合を先頭の語に限ることで、その読み違いの向きを隔離の側に固定している。
引数全体からサブコマンドの名前を探して素通しにすることはしない。

素通しの許可リストとフラグを付けない一覧は、どちらも出荷時は空である。
利用者の手元の写しで、コマンドが壊れたときにだけ増やす（何を足すかは[壊れたときの直し先](#壊れたときの直し先)）。

フラグを付けない一覧に一致しても、境界は `kakoi` のもので緩まない。
対象の自前のサンドボックスが隔離の中で動くか、そのサブコマンドが隔離の中で動くかは保証しない。

入れ子（隔離の中からさらにシムを呼ぶ形）でも、シムは `kakoi` を呼ぶ。
入れ子の検出と警告は `kakoi` が行い、雛形は入れ子を見ない（[入れ子、並列、出力、診断と終了コード](10-process.md)）。

## シムが読む環境変数
<!-- @kotowari[REQ-367:c1d25fbb, REQ-370:ad04bcce] -->

| 変数 | 値 | 効果 |
|---|---|---|
| `KAKOI_SHIM_OFF` | `1` | すべての起動が素通しになる。`kakoi` も差し込むフラグも付けずに実体を exec する |
| `PATH` | 探索するディレクトリの並び | 実体を探す範囲。シム自身は候補から除く（[実体の探し方](#実体の探し方)） |

`KAKOI_SHIM_OFF=1` で素通しにしても、安全の度合いは変わらない。
kakoi はホストを信頼する側として扱っており、ホストの利用者は元から隔離を外して実体を起動できるためである。

## 素通しの許可リストに入れる条件
<!-- @kotowari[REQ-367:c1d25fbb, EX-675:8603bcad] -->

素通しの許可リストには、利用者が承認したサブコマンドだけを書く。
承認の前に、利用者はそのサブコマンドで**モデルが動かない**ことを確かめる。
モデルが動かないとは、そのサブコマンドの実行中に、包む対象がモデルに問い合わせず、モデルの出力でコマンドを実行する機能も持たないことである。

確かめ方は、対象の文書を読むことと、実際に起動して観測することの 2 つである。
codex であれば、起動時に表示されるヘッダーと `exec` の表示で分かる。

素通しの結果には利用者が責任を持つ。
シムの本体は、モデルが動くかどうかからサブコマンドを自動で振り分けない。

## 壊れたときの直し先
<!-- @kotowari[REQ-369:a2f42068, EX-678:45d80f37, EX-679:31e272a2] -->

隔離の中でコマンドが壊れたとき、何をどこに足すかは壊れ方で決まる。
雛形はこの対応を次の表の形でヘッダーのコメントに持つ。
実行時にヒントを表示することはしない。

| 壊れ方 | 足す先 |
|---|---|
| 対象がフラグを拒む、またはフラグを受け取るが効かない | フラグを付けない一覧 |
| 隔離の中でホストに届かず、かつモデルが動かない | 素通しの許可リスト（利用者が確かめて承認してから） |
| モデルが動くのに隔離の中で壊れる | どちらの一覧にも入れない。プロファイルで直す |

壊れたことだけを根拠に、サブコマンドを素通しの許可リストへ足してはいけない。
モデルが動くコマンドを素通しにすると、隔離の外でモデルの出力が実行されうる。

ヘッダーは、許可リストに最初に入りそうな例として認証のサブコマンド（codex なら `login`）を示す。
これは `--help` の読み方の例で、実測していない。
ツール節の値としては出荷しない。

## 実体の探し方
<!-- @kotowari[REQ-370:ad04bcce, EX-680:a1f84f91, EX-681:c8a92e36] -->

シムは、`PATH` から自分自身を除いて実体を探し、見つけた候補のパスをそのまま `kakoi` の `COMMAND` として渡す。
名前だけを渡すと、隔離の中で `PATH` を引き直して再びシムに戻ってしまうためである。

候補がシンボリックリンクでも、シムは最後まで解決しない。
版管理ツールのシムは起動された名前でどのツールかを決めるので、解決したパスを渡すと別のコマンドを起動してしまう。
リンクを実体のパスへ解決するのは、候補が自分自身かどうかを比べるときだけである。

```text
PATH=/home/u/bin:/home/u/.local/share/mise/shims:/usr/bin

/home/u/bin/codex                     シム自身（比較の結果、除く）
/home/u/.local/share/mise/shims/codex 版管理ツールのシム → このパスのまま COMMAND にする
```

シムが利用者の起動経路で実際に選ばれるかの確かめ方は、[セットアップスキル](12-setup-skill.md)が持つ。

## 共有ディレクトリ /tmp/kakoi の作成
<!-- @kotowari[REQ-371:a710eaf7, EX-682:1387f2e5] -->

`kakoi` に通す経路でだけ、シムは `/tmp/kakoi` が無ければ作る。
素通しの経路では作らない。

`/tmp/kakoi` という名前がシンボリックリンクなら、シムは作らずに止まる。
同じホストの別の利用者が先にリンクを置き、リンク先に作らせる形を防ぐためである。
`/tmp` は書き込める項目ではないので、[ポリシーを保護する配置](06-policy-placement.md)の検査はこのリンクに届かない。

## フラグと引数の写し
<!-- @kotowari[REQ-372:4b0d1377, EX-684:27dace50, EX-685:8796e0af, EX-767:be494d6b, EX-768:a1158288] -->

差し込むフラグは、引数列の先頭（グローバルオプションの位置）に置く。
サブコマンドによって位置を変えない。
フラグを付けない一覧に一致した起動でも、`kakoi` は通す。

引数の写しは、ツール節の対応に従って対象のオプションの値を `kakoi` の `--workspace` と `--rw` へ写す。
値は次の 3 つの書き方で読む。

| 書き方 | 例（`-C`、`--cd` を `--workspace` に対応させた場合） |
|---|---|
| 次の語 | `-C /work/app` |
| `=` で付けた形 | `--cd=/work/app` |
| 1 文字のオプションに続けた形 | `-C/work/app` |

写すのは次の範囲に限る。

- `--` より後ろは走査しない。対応するオプションが `--` の後ろにあっても、その値で許可を足さない。
- 位置引数は写さない。
- 1 つのオプションに空白区切りで複数の値を渡す形では、先頭の値だけを写す。

雛形は、写し先が存在するかを検査しない。
存在しない写し先の扱いは `kakoi` の側で決まる（[マウントの解決](07-mounts.md)）。

写しは対象に渡す引数を変えない。
対象は元の引数をそのまま受け取るので、写しの取りこぼしは、対象がその場所に書けない側に倒れる。
写せない形の案内は[セットアップスキル](12-setup-skill.md)が行う。

### 同じ名前の語による広がり

写しの誤りは、取りこぼしの向きだけではない。
雛形は、包む対象の他のオプションが値を取るかを知らない。
そのため、写す対象のオプションと同じ名前の語を、他のオプションの値の位置でも位置引数の位置でも、どこにあってもそのオプションとして読み、続く語を値として写す。
この読み方で、`kakoi` に渡る `--workspace` や `--rw` が利用者の意図より広がりうる。

```text
codex -m --cd /etc exec
```

`--cd` を `--workspace` に対応させたツール節では、利用者が `-m` の値のつもりで置いた `--cd` もオプションとして読むので、`kakoi` に `--workspace /etc` が渡る。

この性質は受け入れている。
写しの誤りがどれも隔離が緩む向きに働かないと説明することは、この契約に反する。
公開文書は、この性質を既知の隙間の 1 件として載せる（[公開文書に載せる事項](../maintainer/public-docs.md)）。

## 雛形の確かめ方
<!-- @kotowari[REQ-373:3c604af3, EX-686:2d4d9f1d, EX-687:aa45e501] -->

雛形は自動テストの対象にせず、人が確かめる（自動テストの範囲は[検証の契約](../maintainer/verification.md)）。
本物の対象は起動せず、代役で分岐と引数を観測する。

1. `PATH` の先頭にディレクトリを 2 つ置く。
2. 前のディレクトリに、雛形の写しを包む対象の名前で置く。
3. 後のディレクトリに、包む対象の代役と `kakoi` の代役を置く。どちらも受け取った引数を表示して終わるだけのものにする。
4. シムを起動し、代役の表示を見る。

素通しの経路でも起動するのは代役なので、本物の対象は動かない。

保守側は、同梱の雛形について次を確かめる。

| 確かめること | 観測されるべき結果 |
|---|---|
| 先頭がサブコマンド、オプション、`--help` のそれぞれで起動する | どの場合も `kakoi` の代役が起動する |
| 対応するオプションを付けて起動する | `--workspace` と `--rw` に写した値が `kakoi` の代役の引数に出る |
| 一覧に一時的に名前を入れた写しで起動する | 先頭の語がその名前のときだけ素通しまたはフラグなしになり、先頭がオプションなら既定の経路になる |
| 差し込むフラグを空にしたツール節で起動する | 起動する |
| `KAKOI_SHIM_OFF=1` で起動する | `kakoi` の代役が起動しない |
| 同梱値のフラグを先頭に置いて実対象を起動する | 実対象にフラグの効果がある（codex では起動ヘッダーが `sandbox: read-only` 以外になる） |

代役での確認は分岐と引数しか示さない。
代役が期待どおりに動いても、同梱のフラグが実対象に効くことまで確かめたことにはならないので、最後の行は実対象で確かめる。

利用者は、自分の写しの素通しの許可リストにある各項目について、モデルが動かないことを確かめる。

これらの手順と、それぞれを誰が確かめるかは `docs/shim.md` にも載せる。

## 公開文書に載せるシムの説明
<!-- @kotowari[REQ-407:3334a806, REQ-408:a3d962b7, EX-769:63ae8242, EX-770:92c92484, EX-771:80962647, EX-772:d5e9aa5e] -->

シムの詳細の文書 `docs/shim.md` には、次の 5 つを載せる。

1. 雛形を写し、ツール節を埋める手順。
2. 同梱のツール節の値が codex の例であること。
3. [壊れたときの直し先](#壊れたときの直し先)の、壊れ方に応じた表。
4. 素通しの許可リストに最初に入りそうな例。
5. 保守側と利用者のそれぞれが確かめる条件（[雛形の確かめ方](#雛形の確かめ方)）。

壊れ方に応じた表を雛形のヘッダーにだけ置き、`docs/shim.md` に載せないことは、この契約に反する。
codex 以外のコマンドを包みたい利用者が `docs/shim.md` を読んで、ツール節の埋め方と、同梱の値が codex の例であることが分かること。

README のシムの節には、次の 3 つを載せる。

- 雛形を写す最短の手順。
- `KAKOI_SHIM_OFF=1` があること。
- `docs/shim.md` への導線。

README のシムの節から `docs/shim.md` へリンクしていても、節そのものに `KAKOI_SHIM_OFF=1` を載せないことはこの契約に反する。
