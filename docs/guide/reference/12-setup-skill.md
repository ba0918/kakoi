# セットアップスキル

この章は、同梱の**セットアップスキル** `kakoi-setup` が何をし、何をしないかを決める。
セットアップスキルはエージェント CLI に読ませる Agent Skill で、利用者の環境に固有の設定（プロファイルへの追加、シムの設置、代替コマンド、隔離の中で壊れたコマンドの扱い）を提案させる（用語は[用語](02-terms.md)を参照）。
スキルを使って環境を整える利用者と、スキルの指示を変更する保守者が読む。

スキルは次の順に進む。

1. プロファイルとシムに別の正本があるかを尋ね、プロファイルが無ければ `init` の実行を尋ねる。
2. 導入済みの対象を調べ、プロファイルの項目とシムの写しを提案する。
3. シムの雛形で写せない引数を説明する。
4. 差分を示し、利用者の承認を得てから書く。
5. シムが各起動経路で選ばれることを確かめる。
6. 変更前後の計画で、提案が反映されたことを確かめる。

## スキルの置き場と配布
<!-- @kotowari[REQ-374:a16e67cd, EX-688:311b79fd, EX-689:d006497c] -->

スキルは `skills/kakoi-setup/SKILL.md` に置き、Agent Skills の共通仕様に従う。

| フロントマターのキー | 値 |
|---|---|
| `name` | ディレクトリ名と同じ `kakoi-setup` |
| `description` | 持つ（空にしない） |

形式への適合は、skills-ref パッケージの `agentskills validate` で確かめる。
独自のインストール手段は作らない。
README にはインストールの形として `gh skill install` を書く。

```sh
gh skill install ba0918/kakoi kakoi-setup
```

## 隔離の外で動くことと承認の境界
<!-- @kotowari[REQ-378:e75628a0, EX-696:2def9bb4, EX-697:883ff7ae] -->

スキルは隔離の外で動く。
設定ディレクトリは書き込める項目の中に置けないので、隔離の中のエージェントは自分のプロファイルを編集できないためである（[ポリシーを保護する配置](06-policy-placement.md)）。

隔離の外では、エージェントの書き込みを境界が止めない。
そのためスキルは、プロファイルとシムを書く前に、書き先と位置を差分で示し、利用者の承認を得る。
承認を得てから書き、書いてから差分を見せる順序はとらない。

次の場合も、差分の提示と承認の要求を省かない。

- 利用者が変更内容を先に指定した場合。
- エージェント CLI の側に書き込みの承認がある場合。

## 書き先の範囲と別の正本
<!-- @kotowari[REQ-379:d2394fbe, EX-698:fe0868a1, EX-699:4f9f16b3] -->

スキルが書いてよい場所は次の 2 つに限る。

- 設定ディレクトリのうち `secrets/` 以外。
- 利用者が承認したシムの置き場。

仕様と公開文書は編集しない。

書き先のファイルが別のファイルから生成や同期で作られるか、他所へのリンクであるとき、その元のファイルを**正本**と呼ぶ。
利用者が別の正本があると答えた場所には、承認を得ても書かない。
代わりに、利用者が正本へ反映するものを提案する。

| 書き先 | 提案するもの | 利用者が行うこと |
|---|---|---|
| プロファイル | 正本へ足す行 | 正本への反映 |
| シム | 置く内容と、実行可能にすること | 正本への反映と実行可能ビットの設定 |

## 正本とプロファイルの有無の確認
<!-- @kotowari[REQ-375:6d918496, EX-690:425efe19, EX-691:a4b995db] -->

スキルは、プロファイルとシムのそれぞれについて、最初の変更提案より前に、別の正本があるかを利用者に尋ねる。
答えはファイルの印や内容から推測せず、利用者の答えだけを根拠にする。

| 対象 | 尋ねる時点 |
|---|---|
| プロファイル | 手順の最初 |
| シム | 利用者が置き場を承認した時点 |

プロファイルがまだ無い場合は、先に `kakoi init` で組み込みの既定を書き出すかを尋ね、承認された場合だけ実行する（`init` は[コマンドライン](03-cli.md)を参照）。
実行しない場合は、プロファイルへの変更を提案せず、その旨を利用者に伝える。
組み込みの既定を想定してプロファイルへの提案を先に出すことはしない。

## 対象に合わせた提案
<!-- @kotowari[REQ-376:18438f33, EX-692:c6b13980, EX-693:964fd0c8] -->

スキルは導入済みの対象コマンドを調べ、次を提案する。

| 見つけたもの | 提案 |
|---|---|
| 対象が状態を書き込む置き場 | `rw` の項目 |
| 対象が読む設定や指示のファイル | `ro` の項目 |
| 包む対象 | シムの写し（ツール節を埋めたもの） |

シムの写しは、スキルが同梱する雛形の写しから作り、先頭のツール節だけを埋める。
雛形を記憶から書き起こさない。
ツール節より下の本体は、同梱の写しも利用者の写しも編集しない（雛形の構成は[シム](11-shim.md)）。

ツール節の値は、対象の `--help` の出力だけを根拠に提案し、実測していないことを明記する。
値が対象に実際に効くかは利用者が実測する。
記憶したフラグを実測済みとして加えることはしない。

## 雛形で写せない引数の説明
<!-- @kotowari[REQ-377:ae77c356, EX-694:1a8105fa, EX-695:c925b125] -->

対象の `--help` に次の形があれば、スキルはどのオプションがなぜ写らないかを示し、回避策を案内する。
黙って取りこぼさない。

| 対象が受け付ける形 | 雛形での結果 | 案内する回避策 |
|---|---|---|
| 作業ディレクトリを位置引数で渡す（`tool [project]`） | 写らず、ワークスペースはカレントディレクトリのまま | そのディレクトリで起動する |
| 1 つのオプションに空白区切りで複数の値を渡す（`--add-dir a b`） | 先頭の値だけが写る | `--rw` への対応なら、対象が許す限りオプションを繰り返す。`--workspace` への対応は最後の 1 つしか残らないので、そのディレクトリで起動する |
| 区切り文字で複数の値を 1 語にする（`--add-dir a,b`） | 全体が 1 つの存在しないパスとして写る | `--rw` なら飛ばされ、`--workspace` なら `path` の診断で止まることを説明する |

対象自身には元の引数がそのまま渡るので、写らなかった場所は隔離の中で書けない側に倒れる。
位置引数の場所を写せないまま、カレントディレクトリに許可を置いて対応したことにはしない。
`path` の診断の終了コードは[入れ子、並列、出力、診断と終了コード](10-process.md)を参照。

## 設定ディレクトリを読めない場合
<!-- @kotowari[REQ-380:afeac5a3, EX-700:afab8838, EX-701:0ea01451] -->

設定ディレクトリを読めない場合、スキルは `--print-plan=full` の計画から合成後のポリシーと出所を読み、コメントは見えていないことを利用者に伝える（計画は[計画の表示](04-plan.md)）。
現在のファイルの内容を、組み込みの既定や記憶で補わない。

差分を作れないので、プロファイルに書き込める場合でも書かず、足す行の提案にとどめる。

## シムが選ばれることの確認
<!-- @kotowari[REQ-382:7047c90c, EX-704:d0c2b03c, EX-705:957e55c3] -->

シムの写しは実行可能にする。
差分はファイルのモードを運ばないので、スキルはシムの差分を示すときに、実行可能にもすることを伝える。
設置した後に、写しのモードを確かめる。

経路の確認も設置した後に行い、まだ設置していない写しを有効と報告しない。
利用者に起動経路を挙げてもらい、少なくとも次の 2 つで確かめる。

| 経路 | 確かめる者 |
|---|---|
| 利用者の対話シェル | 利用者 |
| スキルを実行中のエージェント CLI のコマンド実行 | スキル |
| それ以外の経路 | スキルから実行できなければ利用者 |

各経路で `command -v NAME` の結果を実体のパスへ解決し、承認した写しの実体と一致することを確かめる。
対象コマンドそのものは起動しない。
対話シェルでは、その名前を関数や alias が横取りしていないことも別に確かめる。
`command -v` が関数や alias をどう扱うかの説明には未決の問題があり、付録で追跡している（[未決事項](../appendix/open-issues.md)）。

## PATH の不一致と隔離内の PATH
<!-- @kotowari[REQ-383:600c6c0d, EX-706:4853fcfa, EX-707:7d64360e] -->

エージェント CLI の側だけが写しを見つけない場合、スキルは次を案内する。

- 利用者が変更した `PATH` が、エージェント CLI のプロセスにまだ反映されていない可能性がある。CLI を再起動してから確かめ直す。
- 版管理ツールの shims のディレクトリが写しより前にあると、写しは素通りされる。対話シェルと非対話のシェルで `PATH` の順が違う場合がある。

環境固有の代替コマンドを `path-prepend` に足す提案は、隔離の中の `PATH` への提案である。
ホスト側でシムを見つける探索順とは別のもので、`path-prepend` を足してもホストでシムが見つからない問題は直らない（`path-prepend` は[環境変数、認証情報、Git の URL 書き換え](08-environment.md)）。

## 計画での反映の確認
<!-- @kotowari[REQ-384:a3eef16e, EX-708:821d2084, EX-709:ed2425f6] -->

スキルは変更の前後で計画を取り、並べて比べる。
前後とも `--print-plan=full` を使い、提案した項目が合成後のポリシーに現れることを確かめる。
現れなければ、その旨を利用者に伝える。

別の正本がある場合は、利用者が反映したと伝えてから変更後の計画を取る。
提案を出しただけで反映済みとはしない。

```sh
kakoi --print-plan=full -- true
```

隔離の中で壊れたコマンドの相談では、スキルは[シム](11-shim.md)の直し先の表に沿って、一覧へ足すかプロファイルで直すかを差分で提案する。
どちらにするかの判断は利用者に委ねる。

## 秘密に触れないこと
<!-- @kotowari[REQ-381:e12741f8, EX-702:42153b96, EX-703:03f1ac3b] -->

スキルは `secrets/` の中を一覧せず、読まず、書かない。
置き場とモードの案内にとどめる。

守る対象は、秘密の値と、どんな名前のファイルがあるかの 2 つである。
既にプロファイルや計画に現れている秘密の環境変数名とパスは、この対象に含まない。

秘密が置かれているかは、ポリシーの秘密の項目と起動の結果から判断する。

| 起動の結果 | 分かること |
|---|---|
| 秘密の不在を知らせる警告が出る | 置かれていない |
| `secret` の診断が出る | 置かれているが値を使えない |
| 警告も診断も出ない | 置かれている |
| そもそも秘密の項目が無い | 判断できない。利用者に尋ねる |

秘密の項目は[環境変数、認証情報、Git の URL 書き換え](08-environment.md)を参照。

## スキルの人による確認
<!-- @kotowari[REQ-385:1cda341a, EX-710:4a07aa16, EX-711:1d4453a2] -->

スキルは自動テストの対象にせず、人が確かめる（自動テストの範囲は[検証の契約](../maintainer/verification.md)）。
SKILL.md に指示が書かれていることに加え、実際にスキルを動かす試行で次を観測する。
指示があるだけでは、スキルが守ったことにはしない。

- 利用者が内容を指定しない変更でも、先に指定した変更でも、書く前に差分と承認の要求が出る。
- 各書き先への最初の提案より前に、別の正本があるかを尋ねる。
- プロファイルが無ければ `init` の実行を尋ね、未作成のまま項目を提案しない。
- 別の正本がある場所には書かず、行または内容を提案する。
- 写せない引数の形を持つ `--help` を与えると、該当するオプション、理由、回避策を説明する。
- シムの設置後に、各経路での探索結果を確かめる。
- 設定ディレクトリを読めない場合に、コメントは見えていないと伝える。
