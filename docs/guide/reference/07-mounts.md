# マウントの解決

この章は、ポリシーの `[mounts]` に書いた項目が隔離の中でどう見えるか、どこへ書き込みが残るか、何が診断で止まるかを決める。
マウントの項目を書くとき、計画の表示で項目の結果を読むとき、パスの診断の理由を調べるときに読む。
同じパスを複数の段が指したときの合成は [ポリシーファイルの形式と合成](05-policy.md) に、隔離の中から差し替えられる配置の拒否は [ポリシーを保護する配置](06-policy-placement.md) にある。

## マウントの指定の一覧
<!-- @kotowari[TBL-153:e9601286, REQ-167:79a9d4fb] -->

`[mounts]` に書けるのは、次の 7 つである。
上の 5 つが**指令**（マウント表の 1 行の種類）で、パスを 1 つずつ並べる。
下の 2 つは指令ではなく、`hide` の項目を自動で生成する指定である。

| 指定 | 対象 | 隔離の中での見え方 |
|---|---|---|
| `rw` | ディレクトリ | 読み書きできる |
| `rw-file` | ディレクトリ以外（通常ファイル、ソケット、FIFO） | その場での書き込みができる。一時ファイルを作ってからの置き換え（rename）は失敗する |
| `rw-copy` | ディレクトリまたは通常ファイル | ホストの内容の複製で始まり、読み書きできる。書いたものはホストに届かず、終了時に消える |
| `ro` | ディレクトリまたはファイル | 読み取り専用 |
| `hide` | ディレクトリまたはファイル | ディレクトリは空のディレクトリで、書けるが内容は終了時に消える。ファイルは空の読み取り専用ファイル |
| `scan` | `root` 以下で名前が一致するエントリ | 一致したものを `hide` にする（[走査](#走査)） |
| `hide-mounts` | `under` 以下のマウント | ファイルシステム種別が一致したマウントを `hide` にする（[マウント種別による隠蔽](#マウント種別による隠蔽)） |

```toml
[mounts]
rw      = ["${workspace}", "${worktree}", "${git_common_dir}", "/tmp/kakoi", "~/.cache"]
rw-file = ["~/.claude.json"]
rw-copy = ["~/.gitconfig"]
ro      = ["~/.codex/AGENTS.md"]
hide    = ["/tmp", "/run/user", "~/.ssh", "~/.aws", "/run/WSL"]
```

パスの書き方（絶対パス、`~`、変数）は [ポリシーファイルの形式と合成](05-policy.md) で定める。
この章で指令の対象が「ディレクトリ」「通常ファイル」というときは、シンボリックリンクを解決した実体の種類を指す。

指令の種類が対象に合わないときは、種類 `path` の診断で終わる（終了コード 125。診断の形は [入れ子、並列、出力、診断と終了コード](10-process.md)）。
組み合わせごとの診断は各指令の節に書く。

## 書かれていない範囲の見え方
<!-- @kotowari[REQ-167:79a9d4fb] -->

隔離の中のファイルシステム全体は、ポリシーに書かれていない範囲を読み取り専用で見せる。
`/dev` と `/proc` は、ホストのものではなく隔離用のものを用意する。

読み取り専用で見えている範囲にあるホストの UNIX ソケットには、隔離の中から接続できる。
接続を止めるには、そのソケットかそれを含むディレクトリを `hide` にする。

```toml
[mounts]
hide = ["/run/user"]
```

## rw
<!-- @kotowari[REQ-167:79a9d4fb, EX-336:e4d4ae77, EX-337:a01c674f] -->

`rw` はホストのディレクトリを、隔離の中から読み書きできる形で見せる。
隔離の中で書いた内容はそのままホストに残る。

| 項目 | 内容 |
|---|---|
| 対象 | ディレクトリ |
| 見え方 | 読み書きできる。書いた内容はホストに届く |
| エラー | 実体がディレクトリ以外なら種類 `path` の診断で終わり、説明で `rw-file` を案内する |

```toml
[mounts]
rw = ["${worktree}", "/tmp/kakoi"]
```

`rw = ["~/.claude.json"]` のように通常ファイルを書くと `path` の診断で止まる。
ファイルを書き込めるようにするなら `rw-file` を使う。

## rw-file
<!-- @kotowari[REQ-167:79a9d4fb] -->

`rw-file` はディレクトリ以外の 1 つのファイルを、その場で書き込める形で見せる。

| 項目 | 内容 |
|---|---|
| 対象 | ディレクトリ以外（通常ファイル、ソケット、FIFO） |
| 見え方 | その場での書き込みができ、ホストに届く。一時ファイルを作ってから rename で置き換える書き方は失敗する |
| エラー | 実体がディレクトリなら種類 `path` の診断で終わる |

```toml
[mounts]
rw-file = ["~/.claude.json"]
```

rename での置き換えが失敗するのは、そのファイル自体が 1 つのマウント点になっていて、別のファイルで置き換えられないためである。

## rw-copy
<!-- @kotowari[REQ-167:79a9d4fb, TBL-154:becfbf03] -->

`rw-copy` は、ホストの内容の複製を隔離の中にだけ用意して、実体の上に重ねる。
隔離の中からは読み書きできるが、書いた内容はホストに届かず、終了時に消える。
ホストの実体は読むだけで、書き換えない。

| 項目 | 内容 |
|---|---|
| 対象 | ディレクトリまたは通常ファイル |
| 見え方 | ホストの内容で始まり、読み書きできる。終了時に内側の変更は消える |
| エラー | 実体がディレクトリでも通常ファイルでもない（ソケット、FIFO、デバイスファイル）なら種類 `path` の診断で終わり、説明で `rw-file` を案内する。複製の上限を超えたとき、複製元が読めないときも `path` の診断で終わる（[複製の上限と読めないとき](#複製の上限と読めないとき)） |

```toml
[mounts]
rw = ["~/.config"]
rw-copy = ["~/.config/gh"]
```

この例では、`~/.config/gh` の中は隔離の中で書けるがホストには出ず、`~/.config` のそれ以外はホストと共有される。

`rw-copy` は、`ro` と `hide` のどちらでも表せない要求のためにある。
隔離の中の道具に自分の設定ファイルを書き換えさせたいが、その結果をホストに残したくない、という形である。
ホストへ書き戻さない 3 つの指令の違いは次のとおり。

| 指令 | 初期状態 | 書き込み | 終了後 |
|---|---|---|---|
| `ro` | ホストの内容 | 不可 | ホストは不変 |
| `hide` | 空 | ディレクトリは可、ファイルは不可 | ホストは不変 |
| `rw-copy` | ホストの内容 | 可 | ホストは不変。内側の変更は消える |

ソケット、FIFO、デバイスファイルを拒否するのは、それらが複製する内容を持たないためである。
この種類の判定は、`rw` と `rw-file` の種類の判定と違い、複製を読み込むために開いたファイル記述子の上で行う。
名前で種類を見てから開くまでの間に、実体を差し替えられるためである。
そのため、この診断はマウントを検査する段階の最後に出る（検査の順序は [入れ子、並列、出力、診断と終了コード](10-process.md)）。

### 複製の作り方
<!-- @kotowari[REQ-167:79a9d4fb] -->

実体がディレクトリのときは、その実体に tmpfs を重ね、起動時にホストの実体の下にある木を流し込む。
流し込むのは次の 3 種類である。

| ホストのエントリ | 複製に作るもの |
|---|---|
| 通常ファイル | 同じ内容とモードの通常ファイル |
| ディレクトリ | 同じモードのディレクトリ。空のディレクトリも作る |
| シンボリックリンク | 辿らず、同じ先の文字列を持つリンク |

ディレクトリは、その下のエントリより先に作る。
同じディレクトリの中は、エントリ名のバイト順に見る。
このため、同じ木からは同じ並びの bwrap の引数が得られる（同じ入力から同じ計画が得られることは [kakoi とは](01-overview.md) の約束である）。

実体が通常ファイルのときは、その内容の複製を作り、実体の上に読み書きできる形で重ねる。

モードは複製元のものを引き継ぐ。
実行ビットを含み、set-user-ID、set-group-ID、sticky も写すが、tmpfs は `nosuid` なのでこれらは効かない。
所有者、時刻、ハードリンクの共有は引き継がない。

複製の中身は隔離のマウント名前空間の中にしか無く、名前空間と一緒に消える。
ホストのファイルシステムに複製の実体は残らない（[実行時の境界](../maintainer/runtime.md)）。

tmpfs とそれを埋める引数は、[適用順](#適用順) の中でその項目の位置にまとめて置かれる。
そのため、`rw-copy` の中に着地する狭い項目は、複製が出来上がった後に乗る。

### 複製の中での改名と削除
<!-- @kotowari[REQ-168:f73cc849, EX-338:9bfeef6c] -->

改名と削除ができるかは、複製の形で異なる。

| 複製元 | 改名、削除、一時ファイルからの置き換え |
|---|---|
| ディレクトリ | できる。中のエントリは tmpfs の中の普通のファイルである。変更は隔離の中だけに残る |
| 通常ファイル | できない。その場での書き込みだけができる。実体の上に重ねた 1 つのマウント点なので、`rw-file` と同じく rename での置き換えと削除は失敗する（2026-09-10 に bwrap 0.9.0 で実測） |

置き換えで保存する道具に設定ファイルを書かせるなら、そのファイルではなく親ディレクトリを `rw-copy` にする。

シンボリックリンクを辿らずに作り直すのは、辿ると複製が木の外へ広がり、循環もありうるためである。
隔離の中ではリンクは他のパスと同じに解決され、複製の外を指すリンクは、ポリシーがその先に与えたもの（既定では読み取り専用）に届く。
これは隔離の中のどこからでもできることで、`rw-copy` が新しく与える経路ではない。

### 複製の上限と読めないとき
<!-- @kotowari[REQ-168:f73cc849, EX-339:245dc25c] -->

1 つの `rw-copy` の項目が持てる量には上限がある。

| 上限 | 値 |
|---|---|
| エントリの数 | 4096 個まで |
| 通常ファイルの内容の合計 | 64 MiB まで |

どちらかを超えたら、種類 `path` の診断で終わる。
診断の説明は、その項目のパス、超えた上限、`ro` を使う案内を含む。
内容はファイル記述子と隔離の tmpfs に二重に載るので、大きすぎる複製元を指した指定は読み込まずに止める。

複製元が読めないときも、種類 `path` の診断で終わる。
読めないとは、次の 3 つのどれかである。

- ディレクトリのエントリを列挙できない
- 通常ファイルを開けないか、読めない
- シンボリックリンクの先を読めない

診断の説明は、その項目のパス、読めなかったエントリのパス、理由を含む。
`rw-copy` はホストの内容で始まることを約束するので、それより少ない内容で黙って始めない。

複製元の木の中に、通常ファイルでもディレクトリでもシンボリックリンクでもないエントリ（ソケット、FIFO、デバイスファイル）があるときは、診断にしない。
そのエントリを複製に作らず、計画に理由付きで表示して起動を続ける（[計画の表示](04-plan.md)）。
これらは読めない失敗ではなく、複製に意味の無い種別である（ソケットはホストのそれ自身であって、複製はそれではない）。
作らないことで隔離の中から見えなくなるだけなので、新しく露出するものは無い。
黙って飛ばさず、計画に出すことだけを求めている。

複製元の実体が存在しない項目は、空の複製で始めず、飛ばす（[パスの解決と存在しない項目](#パスの解決と存在しない項目)）。

## ro
<!-- @kotowari[REQ-167:79a9d4fb, TBL-154:becfbf03] -->

`ro` はホストの内容を読み取り専用で見せる。

| 項目 | 内容 |
|---|---|
| 対象 | ディレクトリまたはファイル |
| 見え方 | ホストの内容で始まり、書き込めない。ホストは不変 |
| エラー | 種類の不一致による診断は無い |

```toml
[mounts]
rw = ["~/.codex"]
ro = ["~/.codex/AGENTS.md"]
```

この例では、`~/.codex` の中は書けるが、`AGENTS.md` だけは読み取り専用になる（[適用順](#適用順)）。

## hide
<!-- @kotowari[REQ-167:79a9d4fb, TBL-154:becfbf03] -->

`hide` はホストの内容を隔離の中から見えなくする。

| 項目 | 内容 |
|---|---|
| 対象 | ディレクトリまたはファイル |
| 見え方 | ディレクトリは空のディレクトリで、書けるが内容は終了時に消える。ファイルは空の読み取り専用ファイル。ホストは不変 |
| エラー | 種類の不一致による診断は無い |

```toml
[mounts]
hide = ["/tmp", "/run/user", "~/.ssh", "~/.aws"]
rw   = ["/tmp/kakoi"]
```

この例では、`/tmp` は空に見え、その中の `/tmp/kakoi` だけがホストと共有される。
`hide` で隠したディレクトリの中を、より狭い項目で再び見せることができる（[適用順](#適用順)）。

`hide` の中をカレントディレクトリにして起動すると診断で止まる（[作業場所の検査](#作業場所の検査)）。

## 走査
<!-- @kotowari[REQ-170:5a7ef2e4] -->

**走査**（`mounts.scan`）は、`root` 以下を名前で探し、一致したエントリを `hide` の項目として生成する。
`.env` のように、どこに置かれるか前もって分からない秘密を隠すために使う。

| キー | 意味 |
|---|---|
| `root` | 探索の起点のパス |
| `names` | 隠すエントリの名前 |
| `exclude` | `names` に一致しても対象外にする名前 |
| `prune` | 中に入らないディレクトリの名前 |

必須のキーと省略時の値は [ポリシーファイルの形式と合成](05-policy.md) で定める。
`names`、`exclude`、`prune` はシェルのワイルドカード（`*`、`?`）を使える。
ワイルドカードの意味も同じ章で定める。

```toml
[[mounts.scan]]
root    = "${worktree}"
names   = [".env", ".env.*"]
exclude = ["*.example", "*.sample", "*.dist", "*.template"]
prune   = [".git", "node_modules"]
```

### 隠すものと隠さないもの
<!-- @kotowari[REQ-170:5a7ef2e4, EX-343:f068d7a9] -->

`names` に一致したエントリのうち、次のものは隠さない。

- ディレクトリ
- 解決先がディレクトリのシンボリックリンク
- `exclude` に一致する名前のエントリ
- 読み込んだポリシーファイル

探索は、`prune` に一致する名前のディレクトリの中に入らない。
シンボリックリンクのディレクトリの中にも入らない。

一致したエントリがシンボリックリンクなら、リンクそのものではなく解決先を隠す（[パスの解決と存在しない項目](#パスの解決と存在しない項目)）。

走査で隠したファイルが git に追跡されていると、隔離の中の git には、そのファイルが空になった変更として見える。

隠す先が `rw-copy` の項目の中であっても隠す。
隠すのは複製の中身であってホストのファイルではないが、隠さなければ複製に載った `.env` の中身が隔離の中で読めてしまうためである。
[適用順](#適用順) により、`hide` は複製が出来上がった後に乗る。

### リンクの先が ro の項目の中にあるとき
<!-- @kotowari[REQ-170:5a7ef2e4, REQ-171:3ff48649] -->

一致したシンボリックリンクの解決先が、`ro` の項目の実体と同一か、その中（子孫）にあるときは、そのリンクの解決先を隠さない。
ここでの `ro` の項目は、書かれた段（グローバルスコープ、プロセススコープ、コマンドライン）の項目に段の合成の置き換えを適用した後に残っているものである。
その後の扱いは、その `ro` の項目の解決が書き込める項目の中を参照するかどうかで分かれる。

| `ro` の項目の解決 | 結果 |
|---|---|
| 書き込める項目の中を参照しない（隔離の中から差し替えられない） | 隠さずに、計画に理由付きで表示して起動を続ける |
| 書き込める項目の中を参照する（差し替えられうる） | 種類 `path` の診断で終わる |

この判定に使う書き込める項目は、走査の `root` の検査と同じく、書かれた段だけに合成の置き換えを適用した集合である（[ポリシーを保護する配置](06-policy-placement.md)）。
該当するリンクが複数あれば、診断はリンクのパスのバイト順で最初のものを名指す（走査の探索順には依らない）。
診断の説明は、そのリンクのパス、`ro` の項目のパス、理由を含む。

この規則は 2 つの経路を、診断で見える形で塞ぐ。
1 つは、隔離の中で `.env` という名前のリンクを張って、読み取り専用にした自分の設定や指示を次の起動で空にする経路である（2026-09-06 に実測）。
もう 1 つは、`ro` のリンクを向け直して、走査が隠すべきファイルの隠しを外す経路である。
解決先がディレクトリのリンクは、元から走査の対象外である。

## マウント種別による隠蔽
<!-- @kotowari[REQ-170:5a7ef2e4, REQ-437:f6034c46] -->

`mounts.hide-mounts` は、`under` 以下にあるマウントのうち、ファイルシステム種別が `fstype` のいずれかであるものを、そのマウント先ごとに `hide` にする。
同梱プロファイルは、WSL2 の `/mnt` 以下にある 9p と drvfs のマウントをこれで隠す（[ポリシーファイルの形式と合成](05-policy.md)）。

| キー | 意味 |
|---|---|
| `under` | 探す範囲の起点のパス |
| `fstype` | 隠すファイルシステム種別 |

```toml
[[mounts.hide-mounts]]
under  = "/mnt"
fstype = ["9p", "drvfs"]
```

マウント先が、ワークスペース、ワークツリー、`${git_common_dir}` のいずれかの実体と同一なら、`hide` を生成しない。
利用者が選んだ作業場所そのものを隠さないためである。
マウント先の中にある作業場所は、狭い項目として後に乗るので見える（[適用順](#適用順)）。

マウントの一覧は、`under` が値を持つ `hide-mounts` が 1 つでもあるときだけ読む。
`under` が値を持たない変数を含む項目は飛ばし（[ポリシーファイルの形式と合成](05-policy.md)）、隠すものが無いので一覧も読まない。
一覧が読めなければ、種類 `path` の診断で終わる。
隠すべきマウントを隠さずに起動しないためである。
一覧が読めない状況は、別の隔離環境の中から起動したときのように `/proc` が制限された環境で起きうる。

一覧のマウント先はバイト列として扱う。
UTF-8 として読めない名前のマウントも一覧から落とさないので、そうした名前のマウントも種別が一致すれば隠す。

## パスの解決と存在しない項目
<!-- @kotowari[REQ-169:511b9b69, EX-340:42438518, EX-341:f227b87d] -->

すべての指令は、シンボリックリンクを解決した実体のパスにマウントする。
書いたパスがリンクなら、リンクの先の実体が対象になる。

実体が存在しない項目は飛ばす。
飛ばした項目は、計画に「飛ばした」と理由付きで表示する（[計画の表示](04-plan.md)）。
起動のたびの警告は出さない。
この規則は `rw-copy` にも例外なく効き、複製元が無いときに空の複製で始めることはしない。

存在しないパスにマウントしないのは、bwrap がマウント先を作ろうとし、書ける領域では 0 バイトの実ファイルがホストに残るためである（2026-09-03 に実測）。
存在しないパスに何かを用意すれば、この理由でホストに実体が残る。

この規則の帰結として、起動時に存在せず、起動後に現れたファイルは隠れない。
たとえば起動時に無かった `hide` の対象は、作られずに飛ばされ、隔離の中で後から作られたファイルはそのまま見える。
これは既知の隙間として README に書く（[公開文書に載せる事項](../maintainer/public-docs.md)）。

## 自動で隠す項目
<!-- @kotowari[REQ-170:5a7ef2e4, REQ-171:3ff48649, EX-342:8ae8092b] -->

ポリシーに書かれた項目に加えて、次の 4 つが `hide` の項目を生成し、生成の段に置く。
生成はこの順に行う。

| 順 | 生成元 | 生成する `hide` |
|---|---|---|
| 1 | 走査（`mounts.scan`） | 名前が一致したエントリ（[走査](#走査)） |
| 2 | `mounts.hide-mounts` | 種別が一致したマウントのマウント先（[マウント種別による隠蔽](#マウント種別による隠蔽)） |
| 3 | 秘密ファイル | `secrets` に書かれたファイルのうち存在するもの（[環境変数、認証情報、Git の URL 書き換え](08-environment.md)） |
| 4 | 設定ディレクトリの `secrets/` | 存在すればそのディレクトリ。参照されていない秘密ファイルを隔離の中から読めなくするため |

たとえば、設定ディレクトリの `secrets/` に `secrets` から参照していないファイルがあっても、`secrets/` 全体が `hide` になるので隔離の中からは読めない。

### 生成した項目の優先順位
<!-- @kotowari[REQ-171:3ff48649, EX-344:9313f03e] -->

生成した項目にも、書かれた項目と同じ同一性の判定（実体のパスで同じ項目かを決める規則。[ポリシーファイルの形式と合成](05-policy.md)）を適用する。
生成した項目は、同じ実体を指す書かれた項目を置き換える。
たとえば、同じ実体に書かれた `ro` と生成した `hide` があれば、`hide` が残る。

生成した項目同士が同じパスを指したときは、同じ指令なら 1 つにまとめる。
生成される指令は `hide` だけなので、違う指令の衝突は起きない。

### 生成の前に見る検査と後に見る検査
<!-- @kotowari[REQ-171:3ff48649, EX-345:6ca9cf4c] -->

マウントの項目に対する検査の多くは、生成の段を適用した後の項目の集合に対して行う。
対象は、配置の保護の検査（[ポリシーを保護する配置](06-policy-placement.md)）、指令の種類の検査、[作業場所の検査](#作業場所の検査) である。

例外は次の 2 つで、どちらも書かれた段だけに合成の置き換えを適用した集合（生成の前の集合）で見る。

- 走査の `root` と `hide-mounts` の `under` の根の項目の検査。生成の前に行う
- 走査で一致したリンクの先の `ro` が差し替えられうるかの判定（[リンクの先が ro の項目の中にあるとき](#リンクの先が-ro-の項目の中にあるとき)）。走査の最中に行う

たとえば、生成した `hide` がある `rw` を置き換える予定でも、その `rw` の中にある走査の起点の検査は、置き換える前の `rw` を使って判定する。

## 適用順
<!-- @kotowari[REQ-172:6a63629a, TBL-155:523aa4d6, EX-346:479b264c, EX-347:e39f1e0a] -->

同一性の判定を終えた項目は、実体のパスで、祖先が先、子孫が後の順にマウントする。
互いに祖先でも子孫でもないパス同士は、実体のパスのバイト順に並べる。
この規則により、狭いパスの指令が広いパスの指令に勝ち、同じ入力からは同じ順序が得られる。

`rw-copy` の項目は、tmpfs とそれを埋める引数をその項目の位置にまとめて置く。
複製の中に着地する狭い項目は複製の後に乗り、狭い項目が勝つ規則は変わらない。

| 場面 | 結果 |
|---|---|
| `/mnt/c` を `hide`、その中のワークツリーを `rw` | ワークツリーは読み書きできる |
| `~/.codex` を `rw`、`~/.codex/AGENTS.md` を `ro` | `AGENTS.md` は読み取り専用 |
| ワークツリーを `rw`、走査で見つけた `.env` を `hide` | `.env` は空 |
| `/tmp` を `hide`、`/tmp/kakoi` を `rw` | `/tmp` は空で、`/tmp/kakoi` だけがホストと共有される |
| `~/.cache` を `rw`、`~/.cache/x/.env` を走査で `hide` | `.env` は空 |
| `~/.config` を `rw`、`~/.config/gh` を `rw-copy` | `gh` の中は書けるがホストに出ず、`~/.config` の他はホストと共有される |

たとえば `/tmp` が `hide` で `/tmp/kakoi` が `rw` なら、`/tmp` の後に `/tmp/kakoi` を置く。

## 作業場所の検査
<!-- @kotowari[REQ-173:7e2ed9bc] -->

合成と飛ばしを終えた項目に対して、作業場所に関わる次の 4 つを検査する。
1 つ目だけが警告で、残りは診断で起動を止める。

| 条件 | 結果 |
|---|---|
| ワークスペース、ワークツリー、それらの祖先のどれかを指す `rw` が 1 つも無い | `kakoi: warning:` で始まる 1 行を標準エラーに出し、起動を続ける |
| ワークツリーまたはワークスペースの実体が `/`、ホームディレクトリ、ホームディレクトリの祖先のいずれか | 種類 `path` の診断、終了コード 125 |
| カレントディレクトリの実体を含む項目のうち、適用順で最後に適用されるものが `hide` | 種類 `path` の診断、終了コード 125 |
| カレントディレクトリそのものが取得できない（消されている、辿れない） | 種類 `path` の診断、終了コード 125 |

警告は診断ではない（[用語](02-terms.md)）。

### 成果が残らない警告
<!-- @kotowari[REQ-173:7e2ed9bc, EX-348:0f328486] -->

`rw-copy` は、1 つ目の条件の `rw` に数えない。
作業場所を覆う項目が `rw-copy` だけの起動では、隔離の中で書いた成果が終了時に消える。
警告が要るのはまさにその場面なので、警告を出して起動を続ける。

### 広すぎる作業場所の拒否
<!-- @kotowari[REQ-173:7e2ed9bc] -->

git の管理外にあるホームディレクトリで `--workspace` を省略して起動すると、ワークスペースもワークツリーもホームディレクトリになり、この規則に当たる。

### カレントディレクトリが見えること
<!-- @kotowari[REQ-173:7e2ed9bc, EX-349:0ade17e3] -->

カレントディレクトリが `hide` の中にあると、bwrap がそこへ移れないため、起動前に診断で止める。
`hide` の中に `rw` で再び見せたディレクトリは、最後に適用される項目が `rw` なので、この規則に当たらない。
`rw-copy` の複製の中のディレクトリも、複製がそのディレクトリを作るので、この規則に当たらない。

カレントディレクトリが取得できないときは、bwrap の作業ディレクトリ（`--chdir`）に渡す値が無いため、診断で止める（[実行時の境界](../maintainer/runtime.md)）。

### 次回の起動でワークツリーが変わる隙間
<!-- @kotowari[REQ-173:7e2ed9bc] -->

隔離の中からワークツリーの `.git` を消すと、次回の起動でワークツリーの導出が祖先のリポジトリに変わりうる。
祖先がホームディレクトリかその祖先なら上の広さの拒否で止まるが、それより下の祖先は止まらない。
これは既知の隙間として README に書く（[公開文書に載せる事項](../maintainer/public-docs.md)）。
