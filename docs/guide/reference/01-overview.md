# kakoi の目的と対応範囲

この章は、kakoi が何をするツールで、どの環境で動き、0.3 で何を作らないかを決める。
kakoi を使い始める前と、ある機能が無い理由を確かめたいときに読む。
ここに出る用語の定義は[用語](02-terms.md)にある。

## kakoi が守る約束
<!-- @kotowari[REQ-350:79ab78ed, REQ-351:7d58187a, EX-640:e06df598, EX-641:c827c8a5, EX-643:ba8ef1c1] -->

kakoi は、指定したコマンドを**ポリシー**（隔離の中身を決める指定）とワークスペースに従う隔離環境で起動する、Rust 製の CLI である。
隔離には bubblewrap（bwrap）のマウント名前空間を使う。

入力はポリシーファイル、ワークスペース、実行するコマンド（COMMAND と ARGS）の 3 つである。
kakoi は起動について次の 4 つを約束する。

| 約束 | 内容 |
|---|---|
| 引数を保つ | ARGS を追加も変更もしない。コマンドから見える名前（argv[0]）は COMMAND に与えた文字列のままにし、実行ファイルを探して得たパスに置き換えない |
| 実行結果を返す | 終了結果は包んだコマンドの終了結果である。ただし、ネットワークモード filtered での外部からの終了要求と安全上の故障は、[filtered の終了の契約](network/07-lifecycle.md)が優先する |
| 同じ条件から同じ計画を作る | ポリシー、ワークスペース、カレントディレクトリ、環境、ファイルシステムの事実が同じなら、同じ起動計画を算出する |
| 許可を起動時に固定する | ポリシーは起動時に確定し、隔離の中のアプリから変更も拡張もできない。filtered の DNS 由来の許可と公開の更新は、確定したポリシーの範囲の中で行う |

次の起動では、argv[0] は `sh` のままになる。

```sh
kakoi -- sh -c 'echo "$0"'
```

argv[0] を `/usr/bin/sh` に変えることや、同じ入力でマウントの順番が起動ごとに変わることは、この約束に反する。

計画の中身と表示のしかたは[計画の表示](04-plan.md)、終了コードは[入れ子、並列、出力、診断と終了コード](10-process.md)で説明する。

## 対応環境
<!-- @kotowari[REQ-352:8bd96a8f, EX-644:79f14d18, EX-645:e6779831] -->

kakoi が動く環境は次のとおりである。

| 条件 | 対応範囲 |
|---|---|
| OS と CPU | Linux x86_64。WSL2 を含む |
| bubblewrap | 0.9.0 以上で、setuid でないもの |
| 利用者 | root 以外 |
| x86_64 以外の CPU | 対応しない。x86_64 以外を対象にしたビルドはコンパイル時に失敗する |

x86_64 の上でも、32 ビットと x32 のバイナリは隔離の中で実行できない。
aarch64 でコンパイルが通ったとしても、それを理由に対応環境へ含めることはしない。

ネットワークモード filtered に要る追加の依存は、ライブラリの実証条件（[ライブラリの責務と実証条件](../maintainer/library.md)）を満たす過程で確定する。
host と none のモードには、追加の依存を必須としない。

## 0.3 で作らないもの
<!-- @kotowari[REQ-353:623c6acb, EX-646:b9c89ac2, EX-647:edf70e26] -->

0.3 は次の機能を提供しない。
`--help` の一覧とポリシーのキーには、これらを有効にするオプションやキーが存在しない（文書に無いキーで隠れて有効になることも無い）。

| 作らないもの | 補足 |
|---|---|
| cgroup による CPU やメモリの制限 | bwrap では作れない |
| 段の合成での削除の演算子 | 上の段は下の段に足すか上書きするだけである |
| `default.toml` を常に読む合成 | 書かれた段を 4 つにする形は採らない |
| カレントディレクトリからのポリシーファイルの自動探索 | |
| bwrap の `--new-session` | 端末の扱いは[端末の保護](09-terminal.md)を参照 |
| 入れ子での二重の隔離 | 入れ子は[入れ子、並列、出力、診断と終了コード](10-process.md)を参照 |
| 環境変数以外による入れ子の検出 | |
| `.git/hooks` と `.git/config` の保護 | |
| ポリシーファイルの読み取り専用の重ね掛け | [ポリシーを保護する配置](06-policy-placement.md)の拒否で置き換えた |
| `git init --separate-git-dir` のメインワークツリーの相互リンク | ワークツリーの 3 つ目の相互リンクの形。既知の隙間として README に載せる |
| `kakoi init` の上書き（`--force`） | |

ネットワークモード filtered の初版では、アプリのマルチキャストとブロードキャスト、DNS over HTTPS を扱わない。
この扱いは承認済みのネットワークの契約と実証条件のとおりで、後から対応するときの変更の規模は[ライブラリの責務と実証条件](../maintainer/library.md)で確かめる。

次の 2 つも作らないが、契約は担当の章にある。

- セットアップスキルの独自のインストール手段。各 CLI の手段に任せ、README は `gh skill install` を案内する（[セットアップスキル](12-setup-skill.md)）。
- シムの雛形による、位置引数の写しと、空白区切りで並べた複数の値のうち先頭より後ろの写し。写らない形はセットアップスキルが回避策を案内する（[シム](11-shim.md)）。
