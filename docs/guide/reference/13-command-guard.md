# コマンドのガードレール

この章は、隔離の中で起動されるプログラムの使い方（たとえば git の push）を止めるガードレールの規則、照合、見張り役の振る舞いを説明する。
ガードレールは悪意があれば迂回できる事故防止の柵で、境界ではない。
確実に止めるには権限の狭いトークンや filtered の通信の許可を使い、プログラムそのものを使わせないには `hide` で隠す（[公開文書に載せる事項](../maintainer/public-docs.md#ガードレールの案内)）。

## 規則の形
<!-- @kotowari[REQ-438:fa13561a, EX-846:abe17015, EX-847:7b76062e, EX-871:ee344f9d] -->

規則はポリシーの `[[commands.guard]]` に書く。
各規則は次のキーを持つ。

| キー | 必須 | 意味 |
|---|---|---|
| `program` | 必須 | PATH で探す名前。空でなく、`/` を含まず、`kakoi` でない |
| `reason` | 必須 | 禁止したときに示す理由。空でない文字列 |
| `options-with-value` | 任意 | 値を取るグローバルオプションの名前の一覧 |
| `for` | 任意 | 語の並びの一覧。`deny-flags`、`deny-option-values`、`deny-env` を当てる起動を絞る |
| `deny` | 任意 | 先頭一致で禁じる語の並びの一覧 |
| `deny-flags` | 任意 | 位置を問わず禁じるフラグの一覧 |
| `deny-option-values` | 任意 | オプションの名前ごとの、禁じる値の一覧 |
| `deny-env` | 任意 | 禁じる環境変数の名前の型の一覧 |
| `guard-absolute-path` | 任意 | 真なら絶対パスでの起動も見張る。既定は偽 |
| `examples.deny`、`examples.allow` | 任意 | 禁止になるべき例と、ならないべき例 |

`deny`、`deny-flags`、`deny-option-values`、`deny-env` のどれも持たない規則、空の一覧や空の語の並びを持つ規則、条件に合わない `program` の規則、知らないキーを持つ規則は、形の誤りとして種類 `policy` の診断で終わる。

## 語の照合と先頭一致
<!-- @kotowari[REQ-439:e63748f0, REQ-440:c97d8b14, EX-848:485d34ab, EX-849:32688d99, EX-850:4be2d635, EX-851:f567dea7, EX-852:1666c83e, EX-853:a4ed55fe, EX-872:35f4aa5f] -->

`deny` と `for` の語、`deny-option-values` の値は、語全体と照合する。
`/` で始まり `/` で終わる 2 文字以上の文字列は、囲まれた部分を Rust の regex クレートの構文の正規表現として語全体に当てる。
それ以外は語との完全一致である。
したがって `"push"` は `pushx` に当たらず、`"/pu.h/"` は `push` に当たって `pushx` に当たらない。
オプションの名前は常に完全一致で、UTF-8 として読めない語はどの照合にも当たらない。

`deny` と `for` の各項目は語の並びで、位置ごとに 1 つの語か、代替の語の一覧を書く（`["remote", ["add", "set-url"]]`）。
照合の前に、プログラム名の直後から `-` で始まる語を読み飛ばす。

- `options-with-value` に書いた名前の語は、次の語も値として読み飛ばす。
- `=` を含む語は、その 1 語だけを読み飛ばす。
- それ以外の `-` で始まる語は、値を取らないものとして読み飛ばす。
- `--` の語が来たら、それを読み飛ばして読み飛ばしを終える。

残った語の並びの先頭が項目の語の並びにすべて当たれば禁止で、項目より後ろの語は問わない。
`git --no-pager -C push push origin` は `-C` を宣言していれば `push` から照合され、宣言していなければ `-C` の次の語が残って当たらない。
`git commit -m push` の `push` は先頭でないので当たらない。
語の並びの途中のオプションは読み飛ばさないので、`git remote -v add origin x` は `["remote", ["add", "set-url"]]` に当たらない。
`git -- push` は当たり、`git -- -x push` は当たらない。

## フラグ、オプションの値、環境変数
<!-- @kotowari[REQ-441:461230a3, REQ-442:beeb71d7, EX-854:a130a7fb, EX-855:26c3d40f, EX-856:d2d68199, EX-857:4aa84d00, EX-858:6ee90404, EX-873:d3a414e8] -->

`deny-flags` の各フラグは、プログラム名より後で最初の `--` より前の語に照合する。
語が `=` を含むときは最初の `=` より前の部分を照合するので、`--force=yes` は `--force` に当たる。
`-` に続けて 1 文字のフラグは、`-` で始まり `--` で始まらない語に含まれる文字にも当てるので、`-fq` は `-f` に当たる。
`git log -- --force` の `--force` は `--` より後なので当たらない。

`deny-option-values` は、最初の `--` より前で、オプションの名前の語の次の語か、`名前=値` の語の最初の `=` より後ろを、その名前の一覧と照合する。
`-c` と `--config-env` に `"/alias[.].*/"` を書けば、`git -c alias.p=push p` と `git --config-env=alias.p=ENV p` は禁止になり、`git -c color.ui=false log` はならない。

`deny-env` の各項目は環境変数の名前の型で、ワイルドカードの意味は `env.unset` と同じである（[環境変数と認証情報](08-environment.md)）。
見張り役が起動されたときの環境に、どれかの型に当たる名前の変数があれば禁止とする。

規則が `for` を持つときは、読み飛ばしの後の先頭の語の並びが `for` のどれかの項目に当たる起動にだけ、`deny-flags`、`deny-option-values`、`deny-env` を当てる。
`for = [["push"]]` と `deny-flags = ["-f"]` の規則は、`git push -f` を禁止し、`git checkout -f` を禁止しない。

## 照合の順と合成
<!-- @kotowari[REQ-443:c94c9294, EX-861:8a2962ee, EX-874:4bbd8bbe] -->

`commands.guard` の規則は段をまたいで連結し、上の段で下の段の規則を消すことはできない（[段の合成](05-policy.md)）。
下の段が `push` を、上の段が `fetch` を禁じれば、どちらも禁止になる。
見張り役は、その起動に当てる規則ごとに `deny-env`、`deny`、`deny-flags`、`deny-option-values` の順で照合し、最初に当たったもので禁止とする。
どの規則にも当たらなければ禁止にしない。

## 例の検証
<!-- @kotowari[REQ-444:582d3f7f, EX-859:41178139, EX-860:90ad932c, EX-875:97c5a75a, EX-876:64b1a504] -->

`examples.deny` と `examples.allow` の例は、シェルと同じ引用の規則で語に分ける文字列である。
先頭から続く `NAME=value` の語はその例の環境として読み、残りの語をコマンドとする。
例の検証の環境はその語だけで、ホストの環境は使わない。

ポリシーを読み込んで合成するとき、各例をその規則だけで照合し、`examples.deny` の例は禁止になり、`examples.allow` の例は禁止にならないことを確かめる。
コマンドの先頭の語が規則の `program` と異なるとき、期待と異なるとき、正規表現が壊れているとき、規則が形の誤りのときは、種類 `policy` の診断で終わる。
説明には規則の `program` と、期待と異なった例を含む。
`--print-plan` も同じ診断で終わる。

たとえば `options-with-value` を書かずに `examples.deny = ["git -C dir push"]` と書くと、`-C` の次の `dir` が残って禁止にならないので、起動は止まる。

## 見張り役の置き方
<!-- @kotowari[REQ-446:d9d65b91, EX-862:6b1814ed, EX-863:bf7e0275, EX-864:f248b34e, EX-865:e01ded06, EX-877:4f223fe2, EX-878:28926e5a] -->

規則のあるプログラムごとに、kakoi は隔離へ渡す PATH（`path-prepend` を足した後で、見張り役の場所を除く）でそのプログラムの本物を探し、kakoi 専用の tmpfs の中の見張り役の場所に同じ名前の見張り役を置き、その場所を PATH の最も先頭に足す（[環境変数と認証情報](08-environment.md)）。

本物は、隔離の中でシェルがその名前で起動するものである。
PATH の項目の順に同じ名前を見て、その名前の場所もリンクを解決した実体も `hide` で隠されず、リンクを解決した先が実行できる通常ファイルである最初のものを本物とする。
隠されるかは、自動で生成された `hide` を含め、それを含む項目のうちマウント順で最後に効くものが `hide` であるかで決める。
ディレクトリ、行き先の無いリンク、実行できない通常ファイル、場所か実体が隠される名前は飛ばして先を探す。
隔離の中では隠した実体も実行できないので、シェルもそれらを飛ばして後ろのものを起動する。
最初の名前で探すのを止めたりプログラムごと飛ばしたりすると、後ろの本物が見張られずに起動されてしまう。
たとえば PATH の前の項目に `git` という名前のディレクトリがあり、後ろの項目に実行できる `git` があれば、後ろの `git` の前に見張り役が立つ。

隔離の中で `sh -c 'git push'` のように PATH で探して起動すると、見張り役を通る。
`path-prepend` の中にある本物も同じく見張る。
kakoi に直接渡したコマンド（`kakoi -- git push`）も、隔離の中で起動される以上、見張り役を通る。
見張り役を通るかは、上と同じ探し方で決める。

既定では本物の場所には重ねないので、`/usr/bin/git push` のような絶対パスの起動は見張り役を通らない。
規則が `guard-absolute-path` を真にしているときは、本物のリンクを解決した実体のパスにも見張り役を重ね、本物をその tmpfs の中に置き直す。
置き直すとプログラムから見た自分の場所が変わるので、自分の場所から資源を探すプログラムは壊れうる。

見張り役は kakoi 自身の実行ファイルである。
見張り役、規則、置き直した本物は、見張り役の場所を通しては隔離の中から書き換えられない。
ただし kakoi 自身の実行ファイルが隔離の中から書ける項目の下にあるときは、その項目を通して見張り役の中身が変わる。
これは見張れないものとして案内する（[公開文書に載せる事項](../maintainer/public-docs.md#ガードレールの案内)）。
見張り役を置くのに kakoi 自身の実行ファイルの場所が分からないときは、規則が黙って効かないまま起動しないよう、種類 `bwrap` の診断を出して 125 で終わる。
これらは利用者のマウントより後に重ね、host、none、filtered のすべてで同じにする。
置き場所のパスの具体値は実装が決め、`--print-plan` に出る。

## 見張り役を置かないプログラム
<!-- @kotowari[REQ-449:696b534c, EX-868:5db8c83d, EX-869:ac97b01d, EX-883:7ed5734e] -->

規則のあるプログラムでも、次のときは見張り役を置かず、理由を付けて飛ばす。
起動は続き、規則の形と例の検証は行う。

- 本物が隔離へ渡す PATH に見つからない。
- 本物が kakoi 自身の実行ファイルである。
- 隔離へ渡す環境に PATH が無い（`env.mode = "clear"` で PATH を渡さないとき）。

ディレクトリ、行き先の無いリンク、実行できない通常ファイル、場所か実体が隠される名前は、そのプログラムを飛ばすのではなく、その名前を飛ばして先を探す（[見張り役の置き方](#見張り役の置き方)）。
そういう名前しか無いときは、本物が見つからないとして飛ばす。
本物を探すことと隠されるかの判定は、マウントの解決の後に行う。
すべて飛ばしたときは、PATH に見張り役の場所を足さない。

## 見張り役としての起動
<!-- @kotowari[REQ-453:bdd1a68d, EX-879:08621bc3, EX-880:4d49efdd] -->

kakoi は、起動された実行ファイルの場所が、自分が置いた見張り役の場所とプログラムの対応に載っていれば見張り役として動く。
この判定は入れ子の判定と引数の解析より前に行うので、隔離の中（`KAKOI=1`）で `git --version` を実行しても、入れ子の警告は出ず、本物の git の版が返る。
同じ本物を複数のプログラムの名前が指すときは、それらすべての規則を当てる。
対応に載っていない場所から起動された kakoi は、別の名前で置いた写しでも、見張り役として動かない。

## 禁止と通過
<!-- @kotowari[REQ-447:7ed09e28, REQ-448:58d5eb4f, EX-866:e145c03d, EX-881:466bf7dc, EX-867:a1341526, EX-882:8eba721a] -->

受け取った引数と環境が規則で禁止になるとき、見張り役は本物を起動せず、標準エラーに次の 1 行を出して終了コード 126 で終わる。
標準出力には何も出さない。

```text
kakoi: guard: <プログラム名> <当たった語>: <reason>
```

プログラム名は、当たった規則の `program` である。
同じ本物を複数の名前が指すとき（[見張り役としての起動](#見張り役としての起動)）、どの規則が当たったかと理由の出所がそのまま分かる。
当たった語は引数の側の語で、先頭一致なら当たった語の並び、フラグならそのフラグ、オプションの値ならオプションと値、環境変数ならその名前である。
制御文字は見える表記に逃がす（[プロセスと終了コード](10-process.md)）。
`reason` が `push は人が行う` の規則に `git push origin main` を渡すと `kakoi: guard: git push: push は人が行う`、`deny-flags = ["--force"]` に `git push --force` を渡すと `kakoi: guard: git --force: <reason>` になる。
禁止したことは隔離の外へ通知しない。

どの規則でも禁止にならないとき、見張り役は本物を、受け取った argv[0] を含む同じ引数、同じ環境、同じ作業場所で、自分を exec で置き換えて起動する。
その後の終了コード、標準出力、標準エラーは本物のものである。
本物の exec に失敗したとき（たとえば本物が存在しないインタプリタを `#!` で指すスクリプトのとき）は、種類 `command not executable` の診断を出して 126 で終わる。
見張り役は bwrap がコマンドを起動した後で動くので bwrap はこの失敗を報告できず、入れ子と同じ種類と終了コードに揃える（[プロセスと終了コード](10-process.md#bwrap-を-exec-できないとき)）。

## 計画表示
<!-- @kotowari[REQ-450:bf86d6e1, EX-870:9496db7d] -->

`--print-plan` の要約と全量は、見張り役を置いたプログラムごとに見張り役の場所と置き直した本物の場所（置き直したときだけ）を、飛ばしたプログラムごとに理由を示す。
全量はさらに合成した規則とそれぞれの出所を示す。
JSON は `guards`（置いたプログラムごとに `program`、見張り役の場所、置き直した本物の場所、当てる規則の出所）と `skipped_guards`（`program` と理由）をキーの追加として載せ、`format_version` は 1 のままである（[計画の表示](04-plan.md)）。
計画の command のパスは、見張り役を通るときは見張り役のパスである。
実際に exec されるものを示すためである。

## 同梱プロファイルの見本
<!-- @kotowari[REQ-451:aa81f6e1] -->

同梱プロファイルには有効な規則を入れない。
上の段から消せないので、利用者が外せなくなるためである。
代わりに git の見本をコメントとして入れる。
見本は push の禁止、git のグローバルオプションの宣言、`-c` と `--config-env` で別名を作る値の禁止、理由、当たるべき例と当たってはならない例を持つ。
`GIT_CONFIG_*` の環境変数は禁じない。
`git.instead-of` を使うと kakoi 自身が `GIT_CONFIG_*` を環境に入れるので、禁じると git のすべての起動が止まるためである。
